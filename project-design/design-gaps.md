## 二、必须补画：功能已有，设计稿完全没画

### 2.1 我的预约（订单列表）—— 优先级最高

**为什么必须**：第 4 屏的「确认预约」和第 5 屏的「我的订单 / 待支付 / 已预约 / 已完成 / 全部订单」都指向它，但没有这一页，下单后就没有落点。

**必须包含**：

- 顶部状态筛选：全部 / 待确认 / 已确认 / 已完成（**已取消、未到店**也要有归宿）
- 订单卡片：状态胶囊、预约单号、**日期大字 + 时间段**（主色）、美甲师、项目名、`已付定金 · 待付 ¥196`、总金额（主色）
- 操作按钮：**取消预约**（待确认/已确认时）、**去评价**（已完成时）、**继续支付**（未付款时）
- 空态：无预约时的引导（配一个「去挑款式」按钮）

### 2.2 订单详情

**为什么必须**：列表点进去要看明细；退款/取消理由也要有地方看。

**必须包含**：单号、状态、美甲师、门店、日期时间、**项目明细逐项价格**、优惠/折扣、已付/待付、支付记录、取消/退款记录、底部操作条。

### 2.3 预约·选美甲师

**如果按第 4 屏合并进预约页，则不需要单独画**（见 §五）。
若要独立页：美甲师头像 + 昵称 + 擅长标签 + 可约时段数 + 「选 TA」。

### 2.4 确认预约

**第 4 屏底部虽然有「确认预约」按钮，但没有画点击之后的确认页。**
需要确认是「点了直接提交」还是「再进一页确认」。若再进一页，需补画：

- 预约摘要卡（美甲师 / 日期时间 / 预计时长）
- **款式明细逐项价格 + 项目原价合计**
- 会员折扣、积分抵扣的展示位置（后端算价后才出最终金额）
- 备注输入
- 底部「提交预约」

### 2.5 支付（微信收银台）

**为什么必须**：定金 / 尾款 / 到店补差都要付钱，这是唯一没有设计稿的**钱链路**页面。

**必须包含**：待付金额（大字）、订单摘要、支付方式（微信支付）、支付说明、底部「微信支付 ¥xxx」。
以及：**支付成功 / 支付失败 / 支付超时**三个结果态。

### 2.6 评价

**为什么必须**：第 5 屏有订单状态，完成后要能评价；`POST /app/reviews` 后端已是真实现。

**必须包含**：星级（**细线五角星，不要 emoji**）、快捷标签（手艺细腻 / 沟通耐心 / 环境干净 / 款式还原度高）、文字输入、图片上传（3~9 张）、匿名开关、底部提交。

### 2.7 主题设置

**为什么必须**：这是你之前明确要的功能（主题可修改），现有实现是自绘的，没有设计稿。

**必须包含**：当前主题卡、**效果预览卡**（用真实组件演示：标题/价格/按钮/标签）、预设主题网格（色点表达差异，卡片保持白底）、自定义色板、恢复默认。

### 2.8 美甲师工作台（4 屏）

后端已就绪、前端页面已存在，但**全是自绘**：

| 页面               | 必须包含                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| 工作台首页         | 今日日程（时间轴：几点/哪位客人/什么项目/状态）、今日业绩卡（单量、实收、提成）、待处理操作（点到店 / 点完成） |
| 我的预约（美甲师） | 按日期 + 状态筛选、客人姓名与**脱敏手机号**（带拨号按钮）                                                      |
| 业绩明细           | 期间切换、完成单量、实收分摊、**提成总额 + 逐单明细**（`已计提 / 已结算 / 已冲销` 三态）、平均评分             |
| 我的评价           | 评价列表（星级、内容、图片、店家回复）、平均分概览                                                             |

### 2.9 门店信息

**为什么必须**：第 1 屏导航栏右侧的「门店」图标点了要有落点。

**必须包含**：门店名、门店照片、营业时间、地址（**一键导航**）、联系电话、客服微信。

## 三、需要补画：状态与流程（最容易被漏，但上线前一定会遇到）

设计稿只给了**有数据**的漂亮状态，以下都没画：

| #   | 状态                             | 必须包含                                                                                             |
| --- | -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 3.1 | **空态**                         | 无款式 / 无预约 / 无次卡 / 无评价 / 搜索无结果，各一个（配插画或细线图标 + 一句引导 + 一个行动按钮） |

## 四、设计稿画了、但**后端暂时没有**的数据/功能

这些我会**按设计稿照样渲染**（布局与视觉 1:1），但点击只能走「功能开发中」。你需要决定：**补后端，还是让设计保留位**。

| 设计稿位置                                                              | 缺什么                                                                                           |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 第 5 屏：**优惠券 168**                                                 | 没有优惠券模型（`biz_coupon` 不存在）                                                            |
| 第 5 屏：**收藏款式 2**                                                 | 没有收藏模型（顾客↔款式 无关联表）                                                               |
| 第 5 屏：**我的地址**                                                   | 没有顾客地址表                                                                                   |
| 第 5 屏：**意见反馈**                                                   | 没有反馈表                                                                                       |
| 第 5 屏：**待支付 / 已预约 / 已完成 / 全部订单**                        | 有对应数据，但要确认状态口径（「已预约」= confirmed？「待支付」= unpaid？）                      |
| 第 6 屏：**会员权益 4 项**（专属折扣 / 生日礼遇 / 优先预约 / 积分兑换） | 专属折扣有（等级折扣率）；**生日礼遇、优先预约、积分兑换**没有配置项                             |
| 第 6 屏：**会员专享活动「新客专享·首次到店立减¥30 + 立即领取」**        | 没有活动/优惠券发放模型                                                                          |

| 第 3 屏：**颜色选择**（5 个色块 + 更多）                                | **没有颜色/款式维度**：`biz_service_item` 只有名称/分类/时长/价格/图，需要新增颜色维度或子款式表 |
| 第 3 屏：**收藏 / 客服**                                                | 同「收藏」缺失；客服可做成拨电话/打开客服会话                                                    |
| 第 2 屏：**搜索框 + 筛选漏斗**                                          | 搜索可做（后端列表已支持 keyword？需确认）；**筛选维度**（价格区间/时长/风格）没有字段支撑       |
| 第 1 屏：**门店图标 / 消息图标**                                        | 门店信息可做静态配置；**消息中心**没有模型（站内消息 `sys_notice` 是发给员工的，不是顾客）       |

## 五、结构冲突：设计稿把两页并成了一页（需你确认）

**第 4 屏「预约美甲」同时包含**：

1. 已选款式摘要
2. **选择时间**（日期条 + 时段网格）
3. **选择美甲师**（4 个头像）
4. 备注输入
5. 底部「合计 ¥168」+「确认预约」

也就是说：设计稿把「选时间」和「选美甲师」**合并在一屏**，并且**没有独立的确认页**。

我现在的实现是三页：`slots`（选时间）→ `staffs`（选美甲师）→ `confirm`（确认）。

**按「完全照设计稿实现」，我的做法是**：

- 把三页合并成设计稿的一页（`slots` 改造为「预约美甲」）
- `staffs` 与 `confirm` 两个页面**不再使用**（保留文件但不在路由里出现，或直接删除）

**请确认一句**：合并后，点「确认预约」是**直接提交订单**，还是**再弹一个确认弹层**（弹层也需要设计稿）？

## 六、给设计的出图顺序建议

按「不画就做不下去」排序：

1. **我的预约** + **订单详情**（下单后没落点）
2. **确认预约 / 支付 / 支付结果**（钱链路）
3. **预约美甲合并页**（第 4 屏的重画：含选美甲师与底部操作条）
4. **评价**（完成后要能评）
5. **空态 / 加载 / 错误 / 授权引导 / 取消规则说明**（一组一起画）
6. **美甲师工作台 4 屏**
7. **主题设置**
8. **门店信息**

> 另外建议：第 1 屏的导航栏右侧两个图标在真机上会被微信胶囊按钮挤占位置，
> 设计稿可以按「胶囊左侧」的可用宽度来画（我已按这个规则实现）。
