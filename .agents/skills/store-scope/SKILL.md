# 多店（连锁直营）

> 完整叙述（阶段 0 ~ 1.12 的每一批做了什么、为什么）见 `dev-docs/data/multi-store.md`。
> 本技能只留**动手时要用的那几页**。

## 前提（先确认，别推翻）

- 连锁**直营**：统一结算、**会员资产全店通兑**（余额 / 积分 / 次卡 / 券全店通用，一个池子）。
- 已落地阶段 0 ~ 1.12。
- **明确不做**（已评估，不是漏掉）：① 支付多商户号 —— 只有「加盟 / 独立结算」才需要，
  直营统一结算下做它是负资产；② 门店维度的其它视图 —— 工作台是**个人视角**、dashboard 是**系统维度**，
  都不该接门店上下文。
- 若真要「**按店独立资产**」→ 那是拆资产池 + 改唯一键 + 跨店识别同一个顾客的**另一套改动**
  （文档「阶段 2」），不是把 1.12 再加一点。

## 门店上下文：三级来源（永远按这个顺序）

```
显式 ?storeId=  →  actor.storeId（顶栏切换器，请求头 x-store-id）  →  默认门店
```

| 函数                                                  | 用途                                                                      |
| ----------------------------------------------------- | ------------------------------------------------------------------------- |
| `resolveStoreScope(db, actor, requestedStoreId?)`     | 范围 + 当前门店 + 切换器选中 → `{ scope, activeStoreId, currentStoreId }` |
| `requireCurrentStoreId(db, actor, requestedStoreId?)` | **写入用**，拿不到就 403                                                  |
| `storeConditions(column, context, requestedStoreId?)` | **列表 where 片段**（传整个 `StoreContext`，不是 `scope`）                |
| `listVisibleStores(db, actor)`                        | 我可见的门店（`GET /stores/mine`）                                        |

- 头里的门店**不可见 → 静默忽略**（回落到"没选"，常见于授权刚被收回）；
  显式 `?storeId=` 不可见 → **403**。区别在于后者是用户的显式请求。
- **不要塞进 JWT**：切门店 / 改授权要**立刻生效**，服务端每次都按 `sys_user_store` 复核，头本身不是权限。
- 店长**不传任何参数也只统计本店** —— 这是数据权限，不是筛选。

## 表上的门店列

| 表类型                                            | 形态                               | 理由                                                                         |
| ------------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| **单据类**（预约 / 收款 / 退款 / 应收）           | `NOT NULL` + FK                    | 建单时必然知道落哪家店                                                       |
| **流水 / 日志类**（`biz_member_transaction` 等）  | **可空** + FK `ON DELETE SET NULL` | 定时任务 / 系统自动 / 历史数据**没有门店可归**，强行 NOT NULL 就是编个假门店 |
| **排班**（`biz_staff_weekly_shift` / `override`） | **可空**                           | `NULL` = 通用层（对所有可服务门店生效），填了 = 该店专属层                   |

- 给非空表加 `NOT NULL` 列 → **三步走**（加可空 → 回填 → `MODIFY ... NOT NULL`）。
  直接 `ADD ... NOT NULL` 会让 MySQL 补隐式 `0`，随后加外键**必失败**。
- `store_id` **不要**注册进 `defineRelations`（同时声明双向关系会抛
  `Cannot read properties of undefined (reading 'through')`），联查一律 `leftJoin`。
- 美甲师 ↔ 门店是**多对多**（`biz_staff_store`，空集合 = 全部门店），不要给 `biz_staff` 加 `store_id`。

## 写入落店：只在一个地方决定

- **单据**：建单入口用 `requireCurrentStoreId`。
- **会员流水**：`writeLedger` 是**唯一写入口** —— 有 `bookingId` 就**顺预约带出**，
  独立收付款（充值 / 冲正 / 调整 / 购卡 / 退卡）由入口解析，都没有则留空。
  **不要在调用点各自传 `storeId`**：十几个调用点漏一个就是一条没有门店的资金流水，而那种最难发现。
- **门店解析放事务外**（用 `this.database.db`），事务里只写业务 —— 锁窗口更短，单测队列也不容易错位。

## 报表口径边界（最容易算错的地方）

| 口径                     | 指标                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| **按店（发生额）**       | 营收 / 退款 / 单量 / 客单价 / 项目排行 / 美甲师业绩 / 应收账龄 / 次卡核销 + **储值充退 / 积分发放抵扣** |
| **恒全店（存量与主体）** | **期末结存 / 新增会员 / 次卡发售**                                                                      |

- **判据一句话**：这个数字回答「**某家店发生了什么**」→ 按店；「**这家公司现在有多少**」→ 全店。
- 前端「全店」标签**必须跟着口径走**（口径不标注比数字算错更坑）。
- 按店时「**宁少不多**」：无门店的历史流水**不算进任何门店** —— 把别店的钱算进来比少算更难发现。

## 前端

- 顶栏切换器 → pinia `storeScope.activeStoreId`（持久化 localStorage）→ 拦截器统一发 `x-store-id`。
  改在拦截器一处，77 个调用点一行没动。
- 可见门店 **> 1** 才渲染切换器；切「全部门店」**不发**这个头（口径回到升级前）。
- `useTable` 监听 `activeStoreId` 自动重载（35 个列表页零改动）；**新列表页别自己拼 `?storeId=`**。
- 已接门店的：列表页（`useTable`）、收银台队列、报表页、排班页、会员流水。
  新增**非列表**视图先判一次：它回答"某家店发生了什么"还是"某个人 / 整个系统怎么样"。

## 坑

- **`LewDropdown` 的勾选标记写在 `option` 上**，不是组件上：lew-ui 用
  `options.some(o => o.checkable)` 决定要不要渲染勾选列，dropdown 自己的 `checkable` prop 不参与。
  只写 `checked: true` 会「菜单能开、但看不出选中哪项」—— 每个 option 都要带 `checkable: true`。
- **单测队列要给门店解析留一格**：`requireCurrentStoreId` 会先插一次 `defaultStoreId()` 查询，
  漏了会报「系统里还没有门店」，看着像业务错了，其实是 mock 队列短了一格。
- **两个 `bun test` 并行跑集成测试会互相踩**：共用同一个测试库，症状是莫名 404 / 记录消失，串行即绿。
