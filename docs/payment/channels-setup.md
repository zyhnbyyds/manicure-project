# 支付通道接入（微信 / 支付宝扫码收款）

## 这个模块解决什么问题

门店收钱有两种完全不同的做法：

| 做法 | 顾客怎么付 | 系统怎么知道钱到了 |
| --- | --- | --- |
| **线下收款码**（店家自己的码） | 顾客扫台面上贴的码 | **不会自动知道**，靠店员看到顾客手机上的付款成功页后手动记账 |
| **在线扫码**（微信 Native / 支付宝当面付） | 顾客扫**系统临时生成的**码 | 微信 / 支付宝**主动通知系统**，系统自动把这笔记到那张单子上 |

本页讲的是第二种：**把「在线扫码」这条通道开通**。开通之后有两个直接好处：

1. 账自动对——顾客付完，收银台几秒内自己就变成「支付成功」，不用店员盯着顾客手机；
2. 能对账——系统每天自动去微信 / 支付宝拉账单，逐笔核对，钱少了或者系统漏记了都能发现。

> 💡 大白话：线下收款码是「店员相信自己的眼睛」，在线扫码是「微信 / 支付宝替我们作证」。前者只能记账，后者能对账。

**重要前提**：开通通道不是后台点几下就能完成的，需要在**服务器上填写配置项并重启服务**，配置项由微信支付 / 支付宝发放。所以这件事需要**老板（准备资料、去渠道申请）+ 技术对接人（改配置）**一起做。

> ⚠️ **小程序内的在线支付目前没有开通。** 顾客在小程序里点「微信支付」会看到「这个功能马上就来啦～」，余额 / 次卡 / 积分也标着「暂未开放」。本页开通的是**收银台**上的在线扫码收款，不是小程序内付款。**不要对顾客承诺「可以在小程序里付款」。**

## 谁来用（适用角色）

| 角色 | 在这件事里做什么 |
| --- | --- |
| 老板 / 店长 | 准备材料、注册商户号、签约产品、拿到渠道给的密钥材料；做小额验证；每天看一次对账 |
| 技术对接人（或服务商） | 在服务器环境配置文件里填写配置项、重启服务、确认回调地址公网可达 |
| 前台 / 收银员 | 只使用，不需要关心配置；通道没配好时会看到「通道未启用」提示，改用现金 / 线下收款码即可 |
| 财务 | 用「支付流水」与「支付对账」核对渠道到账 |

权限怎么控：**「支付对账」这个页面本身没有单独的页面权限点**，能不能在这里看到它，取决于角色有没有被授予这个菜单；而页面里的「触发对账」和「标记处理」按钮由权限点 **`biz:payment:reconcile`** 控制（这个权限点登记在「支付流水」页的按钮上，两处共用同一个点）。**建议只把它和退款审批一起给店长**，前台不需要看对账数据。

## 操作路径

后台**没有**支付通道的配置页面——这是刻意的设计：密钥属于敏感信息，不能从浏览器里改。

| 要做什么 | 去哪里 |
| --- | --- |
| 填写配置项、重启服务 | **服务器上的环境配置文件**（技术对接人操作），不是后台页面 |
| 使用在线扫码收款 | 后台 → 左侧菜单「美甲预约」→「收银台」`/biz/cashier` |
| 看每笔收款的渠道状态 | 后台 → 左侧菜单「美甲预约」→「支付流水」`/biz/payments` |
| 每天核对渠道账单 | 后台 → 左侧菜单「美甲预约」→「支付对账」`/biz/payment-diffs` |
| 退款（原路退回） | 后台 → 左侧菜单「美甲预约」→「退款审批」`/biz/refunds` |

## 分步操作

下面是一条完整的开通时间线。**建议按顺序做，不要跳步。**

| 阶段 | 谁做 | 大概耗时 | 做完的标志 |
| --- | --- | --- | --- |
| 0. 决定开通哪个渠道 | 老板 | 10 分钟 | 定下「微信 / 支付宝 / 两个都要」 |
| 1. 准备材料 | 老板 | 半天 | 证件、照片、域名、HTTPS 齐了 |
| 2. 申请商户号 / 应用，拿到密钥材料 | 老板 | 1~3 个工作日（渠道审核） | 拿到 6 项（微信）或 4 项（支付宝）材料 |
| 3. 填配置、重启服务 | 技术对接人 | 30 分钟 | 收银台选该渠道不再报「通道未启用」 |
| 4. 小额验证（正向 + 退款） | 店长 + 技术对接人 | 30 分钟 | 支付流水里能看到「成功」+ 渠道交易号 + 退款记录 |
| 5. 上线前检查 | 店长 | 15 分钟 | 检查清单全部打勾 |
| 6.（可选）日常对账 | 店长 | 每天 5 分钟 | 「支付对账」没有待处理差异 |

---

### 阶段 0：先决定开通哪种

| 渠道 | 顾客体验 | 需要通道配置 | 建议 |
| --- | --- | --- | --- |
| 微信 Native 扫码 | 用微信扫码付款 | ✅ 需要 | 国内门店首选，客户覆盖率最高 |
| 支付宝扫码（当面付） | 用支付宝扫码付款 | ✅ 需要 | 建议一起开通，成本主要是走流程 |
| 现金 | 直接给现金 | ❌ 不需要 | 永远保留，通道出问题时靠它兜底 |
| 微信线下收款码 / 支付宝线下收款码 | 扫店家自己的码 | ❌ 不需要 | 已经能用，只是**不会自动记账、也不能对账** |
| 储值余额 / 次卡核销 / 挂账 | 用会员权益或赊账 | ❌ 不需要 | 已经能用 |

**两个在线通道互相独立**：只配微信不配支付宝，微信扫码照常用；反之亦然。

### 阶段 1：材料准备（一次备齐，避免反复提交）

| 材料 | 说明 | 微信支付 | 支付宝当面付 |
| --- | --- | --- | --- |
| 营业执照 | 与门店招牌一致；个体户 / 公司都行 | 需要 | 需要 |
| 法人（经营者）身份证 | 正反面照片 | 需要 | 需要 |
| 结算银行账户 | 对公账户；个体户可按规定用经营者账户 | 需要 | 需要 |
| 门店门头照 + 内部经营照 | 能看清招牌与店内环境 | 通常需要 | 通常需要 |
| 客服电话 | 能接通的手机号 | 需要 | 需要 |
| **一个已认证的公众号或小程序 AppID** | 微信扫码下单要用它绑定 | **需要** | 不需要 |
| **公网可访问的域名 + HTTPS 证书** | 渠道要往这个地址回调通知；必须是 `https://`，不能是 IP、不能是内网地址 | 需要 | 需要 |

> 💡 大白话：回调地址就是「微信 / 支付宝给我们的系统打电话的号码」。这个号码必须外面能打通（公网）、必须是加密的（HTTPS），否则钱收了系统也不知道。

### 阶段 2：申请商户号 / 应用，拿到密钥材料

#### 2.1 微信支付（Native 扫码）

按微信支付官方流程办理，入口与文件说明见官方文档 [证书密钥概览](https://pay.wechatpay.cn/doc/v3/merchant/4024350132)。要点：

1. **申请微信支付商户号**：在微信支付商户平台提交上面的材料，通过审核并完成签约，拿到**商户号**。
2. **申请商户 API 证书**：商户平台 → **账户中心 → API 安全 → 商户 API 证书 → 管理证书 → 申请新证书**。
   - 用微信提供的证书工具在本地电脑生成；
   - 会得到 `apiclient_cert.pem`（证书）、`apiclient_key.pem`（**私钥**）、`apiclient_cert.p12`；
   - 从证书里能看到**证书序列号**；
   - ⚠️ 官方明确说明：**证书一旦丢失无法找回，只能重新申请**；有效期 5 年，过期前必须更换（不能续期）。
3. **设置 APIv3 密钥**：商户平台 → **账户中心 → API 安全 → APIv3 密钥 → 设置**。
   - 是**32 位字母数字组合**；
   - 官方明确说明：**一旦丢失只能重设，不能找回**，设置时务必先记下来并存到安全的地方。
4. **绑定 AppID**：在商户平台把公众号 / 小程序的 AppID 与商户号绑定（Native 下单要传 `appid`）。
5. **（可选）平台证书**：微信平台证书由微信生成，用来验证微信的应答与回调签名。系统会**自动联网下载并缓存**，通常不需要人工准备；有效期 5 年，微信支持新旧双证书平滑更换。
   - 官方现在也提供「**微信支付公钥**」（`pub_key.pem`，无过期时间）作为平台证书的替代方案，两者同一商户号选其一。系统当前按**平台证书**方案工作。

#### 2.2 支付宝当面付

1. 用**企业支付宝账号**登录支付宝开放平台，创建应用（网页 / 移动应用均可），拿到 **APPID**。
2. 签约 **当面付** 产品（在开放平台或商家中心完成签约，审核通过后可用）。
3. 生成 **RSA2 密钥对**：用支付宝官方工具生成应用私钥与公钥；
   - 把**应用公钥**上传到开放平台；
   - 上传后从开放平台**查看并保存「支付宝公钥」**（注意：这**不是**你自己生成的应用公钥，两者不能混）。
4. 记录 **APPID / 应用私钥 / 支付宝公钥** 三项材料，加上回调地址，一共 4 项配置。

> ⚠️ 「应用公钥」和「支付宝公钥」是两个不同的东西。填错最典型的症状是：下单能成功，但回调永远验签失败，系统里永远看不到「支付成功」。系统会把这种失败记在「支付流水」的渠道轨迹里（事件显示为「回调验签失败」）。

### 阶段 3：填写配置项（六个 / 四个，缺一项都不算开通）

配置文件是服务器根目录的环境配置文件（项目里有一份 `.env.example` 模板，里面列了所有配置项的名字，值留空）。**改完必须重启服务才生效**（配置是服务启动时读取的）。

#### 3.1 微信支付 Native 扫码：6 个必填项

| 配置项（变量名） | 含义 | 去哪里拿 | 缺失 / 填错会怎样 |
| --- | --- | --- | --- |
| `WXPAY_APPID` | 商户号绑定的公众号 / 小程序 AppID | 微信公众平台 / 小程序后台；须已在商户平台绑定 | 未填 → 通道算「未启用」；填错 → 下单被微信拒绝，报「微信支付下单失败：…」 |
| `WXPAY_MCHID` | 微信支付商户号 | 微信支付商户平台「账户中心 → 商户信息」 | 未填 / 填错 → 通道未启用或下单失败 |
| `WXPAY_SERIAL_NO` | **商户 API 证书的序列号**（用来告诉微信「用哪张证书验我的签名」） | 申请商户 API 证书后可见（证书详情 / 证书工具里） | 未填 / 填错 → 请求签名对不上，微信返回签名类错误 |
| `WXPAY_PRIVATE_KEY` | **商户 API 证书私钥**（`apiclient_key.pem` 的内容） | 申请证书时本地生成，务必自己留好（微信不保存、丢了找不回） | 未填 → 通道未启用；填错 → 所有请求签名失败 |
| `WXPAY_API_V3_KEY` | **APIv3 密钥**，用于解密回调内容（以及解密平台证书） | 商户平台「账户中心 → API 安全 → APIv3 密钥」 | 未填 → 通道未启用；**不是 32 位** → 系统直接报「微信支付 APIv3 密钥必须为 32 位」 |
| `WXPAY_NOTIFY_URL` | 回调地址，微信把「顾客付款成功」通知发到这里 | 自己的域名 + 系统固定路径（见下） | 未填 → 通道未启用；填了但外面打不通 → 钱收了系统不知道，只能靠主动查单兜底 |

回调地址的正确写法（把域名换成门店自己的域名）：

```
https://你的域名/api/v1/biz/payments/notify/wxpay
```

#### 3.2 微信支付：1 个可选项（不影响开通）

| 配置项（变量名） | 含义 | 去哪里拿 | 缺失会怎样 |
| --- | --- | --- | --- |
| `WXPAY_PLATFORM_PUBLIC_KEY` | **微信平台证书公钥**的本地副本，只为「内网 / 无法联网下载证书」的环境准备 | 官方平台证书工具，或调用微信的证书下载接口 | **配不配都不影响通道是否启用**。不配时系统自己联网下载平台证书（缓存 12 小时）。网络正常就留空 |

> 💡 大白话：这一项是给「机房不能访问外网」这种情况留的后门。正常门店留空即可，**它不是第六个必需项**。

#### 3.3 支付宝当面付：4 个必填项

| 配置项（变量名） | 含义 | 去哪里拿 | 缺失 / 填错会怎样 |
| --- | --- | --- | --- |
| `ALIPAY_APP_ID` | 开放平台应用的 APPID | 支付宝开放平台 → 应用详情 | 未填 → 通道算「未启用」；填错 → 下单被支付宝拒绝 |
| `ALIPAY_PRIVATE_KEY` | **应用私钥**（RSA2） | 自己用官方工具生成并保存 | 未填 → 通道未启用；填错 → 下单请求验签失败 |
| `ALIPAY_PUBLIC_KEY` | **支付宝公钥**（不是应用公钥！） | 上传应用公钥后，在开放平台应用里查看「支付宝公钥」 | 未填 → 通道未启用；填成应用公钥 → 回调验签失败，系统永远收不到「支付成功」 |
| `ALIPAY_NOTIFY_URL` | 回调地址 | 自己的域名 + 系统固定路径（见下） | 未填 → 通道未启用；外面打不通 → 同上，靠主动查单兜底 |

回调地址的正确写法：

```
https://你的域名/api/v1/biz/payments/notify/alipay
```

#### 3.4 私钥怎么填（微信和支付宝都一样）

系统对私钥的写法是**宽容**的，两种都可以：

- **整段 PEM**：把 `-----BEGIN PRIVATE KEY-----` 到 `-----END PRIVATE KEY-----` 整段（含换行）粘进去；
- **压成一行**：把换行写成字面上的 `\n`。系统会自动还原成标准格式。

如果只粘贴了中间那串字符（没有 `BEGIN` 行），系统也会自动补上头尾。**但请务必原样复制，漏字符会导致签名失败。**

> ⚠️ **密钥是钱柜钥匙。** 不要把私钥、APIv3 密钥发到微信群、不要截图、不要提交到代码仓库。谁拿到商户私钥 + 序列号，理论上就能以门店名义向微信发起退款等操作。人员离职或怀疑泄露，立刻到商户平台**重设 APIv3 密钥 / 重新申请 API 证书**，然后同步更新配置。

> ⚠️ **「配置齐全」是六个都要有值。** 系统判定一条通道是否启用的规则很简单：**必填项只要有一个是空的，这条通道就算「未启用」**。所以「配了五个忘了一个」和「完全没配」在使用上是一样的。可选那一项（平台证书公钥）不参与判定。

### 阶段 4：小额验证（配置完必须做，别等顾客来试）

#### 4.1 先确认「通道已启用」

重启服务后，不用真的付钱也能看出配没配好：

1. 打开收银台，随便选一张单据（如果只是想试，可以先做一张小程序 / 后台的小额预约，或按正常流程选一张待收款的单）；
2. 右栏加一行，渠道选「微信 Native 扫码」，金额填很小的一笔；
3. 点「去收款」→「确认收款」：
   - **如果弹出「扫码收款」窗并显示二维码内容** → 配置已生效；
   - **如果提示「微信支付通道未启用」/「支付宝通道未启用」** → 说明还有必填项没填、填了没重启、或 APIv3 密钥不是 32 位。改好再试。
4. 试完记得把这次测试收款处理掉（见 4.3）。

> 💡 大白话：「通道未启用」这个提示是系统在保护你——它在**没有向渠道下单之前**就拒绝了，所以不会留下任何待支付单，也不会扣一分钱。

#### 4.2 正向验证（真实小额）

1. 用最小的金额走一笔真实的在线扫码收款（金额多少由渠道与门店约定，越小越好）；
2. 让顾客（或用自己手机）扫码付款；
3. 收银台弹窗**每 3 秒自动查询一次**，付款成功后应提示「支付成功，单据金额已刷新」；
4. 到「支付流水」找到这张支付单，点「详情」，核对下面这几项：

| 要看什么 | 应该是什么 |
| --- | --- |
| 状态 | **成功** |
| 渠道交易号 | **有一串渠道给的交易号**（不是空） |
| 支付时间 | 有值 |
| 回调时间 | **有值**（说明渠道确实通知到系统了，而不是靠主动查单补的） |
| 渠道轨迹 | 至少有「创建支付单」和「渠道回调」两条 |

5. 如果「回调时间」是空的、只有「主动查单」，说明**回调地址不通**（被防火墙挡了、域名 / 证书有问题）。这不会丢钱（后台每 2 分钟自动查单兜底），但**对账会变麻烦**，请技术对接人排查。

#### 4.3 退款验证（原路退回）

1. 到「退款审批」点「发起退款申请」；
2. 填预约 ID，点「**试算判责**」→ 系统回填建议退款金额（会显示命中规则、规则阈值、距开始小时数、可退比例、建议退款额、判责扣减、可退上限）；
3. 「去向」选**原路退回**（在线支付的退款，**只有在线支付才能选原路退回**）；
4. 填退款原因（必填，且不能太短），提交 → 生成**待审批**退款单；
5. 用店长账号点「审批」→「通过」→ 确认窗提示「通过后将立即执行退款（原路退回调渠道 / 现金或退余额直接落地），且只能执行一次」；
6. 通过后：顾客会收到退款，支付单状态变成「部分退款」或「已全额退款」，渠道轨迹里会多一条「退款」。

#### 4.4 关于沙箱（重要）

- 系统里微信 / 支付宝的网关地址是**写死的正式地址**（微信 `api.mch.weixin.qq.com`、支付宝 `openapi.alipay.com`），没有「切沙箱」的开关。
- 所以**开通验证只能用正式商户号 + 真实小额交易**来做，没有免费的练习环境。
- 也正因为如此，请把验证放在**正式营业前**，不要拖到顾客排队结账时才发现配置有问题。

#### 4.5 验证检查清单

- [ ] 收银台选该渠道不再提示「通道未启用」
- [ ] 能弹出一个待顾客扫码的在线支付单
- [ ] 小额正向支付能自动变成「成功」（不用手动刷新队列）
- [ ] 「支付流水」里该笔有**渠道交易号**和**回调时间**
- [ ] 渠道轨迹里有「创建支付单」与「渠道回调」
- [ ] 能成功发起一笔**原路退回**的退款并审批通过
- [ ] 退款后支付单状态变成「部分退款 / 已全额退款」
- [ ] 「支付对账」里能看到前一天的账单比对结果（差异为 0，或差异都能解释）

---

### 阶段 5：上线前检查

1. **回调地址**：公网 HTTPS、证书有效、防火墙 / 网关放行；不要用 IP、不要用内网地址、不要带端口之外的怪路径。
2. **域名一致**：配置里的回调地址域名要和实际对外域名一致（换域名 / 加 CDN 时要同步改）。
3. **两台收款设备**：至少准备一台能上网的收银设备打开后台收银台；再准备线下收款码与现金作为备用。
4. **权限**：确认「收银台-创建收款」「收银台-关闭支付单」「退款审批-申请」给了前台；「退款审批-审批」「支付对账」只给店长。
5. **对账习惯**：每天开店前看一次「支付对账」，把待处理差异清零（详见 [对账](./reconcile.md)）。
6. **应急方案**：通道故障时改用**现金 / 线下收款码**，并在备注里写清原因；已生成的在线支付单用「改现金收款」关掉，**不要放着不管**。
7. **密钥保管**：私钥与 APIv3 密钥只存在服务器配置文件与门店的密码管理里，不进聊天记录、不进截图、不进代码仓库。

### 阶段 6：二维码 5 分钟失效怎么处理

在线支付单的有效期由门店配置项控制，**默认 5 分钟**。失效后的表现与正确处理：

| 情况 | 界面表现 | 正确做法 |
| --- | --- | --- |
| 二维码还没到期 | 「剩余有效时间 04:32」这样倒计时，每 3 秒查一次状态 | 让顾客在这段时间内扫完付款 |
| 已到期 | 「二维码已过期」+ 出现「重新获取」「改现金收款」两个按钮 | 二选一，见下 |
| 系统已自动关单 | 收银台提示「该支付单已关闭，请重新获取二维码或改现金收款」 | 同上 |

两个出口的区别：

- **「重新获取」**：先**关掉**这张超时的支付单，再按刚才完全相同的收款内容**新建**一张支付单、生成新的二维码。
  - 为什么必须新建？因为同一张预约重新收款时，系统的商户订单号必须全局唯一，**旧单必须先关掉**。这是规矩，不是重复扣钱。
- **「改现金收款」**：关掉这张在线支付单，把本次收款**改成现金**，金额会带出来让你确认后重新提交。
  - 应收台账里的「改现金收款」刻意**不自动重提**，只把在线单关干净并提示「请按现金方式重新销账」——因为金额构成可能已经被店员改过，系统不替店员做决定。

> ⚠️ **二维码过期 ≠ 这笔钱丢了。** 本地关单只是「我们自己判断超时了」，**顾客完全可能在最后一刻付款成功**。所以系统在关单 / 失败之后，**还会继续向渠道查询 24 小时**；一旦查到钱确实收到了，这笔单会被「救回来」重新落成成功并正常入账（收银台的渠道轨迹里能看出来）。也正因如此：**在确认这笔线上支付确实失败之前，不要改收现金。**

> ⚠️ **关闭扫码弹窗前先确认状态。** 收银台和应收台账在关闭弹窗时都会主动向渠道查一次；但如果网络查不通，请到「支付流水」手动点「查单」。这是避免「微信收了、现金又收一遍」的关键动作。

## 字段说明

### 通道配置项（服务器环境配置文件）

必填项与取值来源见上文 3.1 / 3.3 的两张表。这里只汇总「填错最常见的样子」：

| 字段 | 必填 | 填错会怎样 |
| --- | --- | --- |
| 微信：AppID / 商户号 / 证书序列号 | 是 | 通道算未启用，或下单被微信拒绝（报「微信支付下单失败：…」，后面会带 `Request-Id`，报给微信客服时提供它最快） |
| 微信：商户证书私钥 | 是 | 通道未启用，或所有请求签名失败 |
| 微信：APIv3 密钥 | 是 | 不是 32 位会直接报「微信支付 APIv3 密钥必须为 32 位」；位数对但值错 → 回调解密失败，回调被拒（渠道会重投，但一直失败） |
| 微信：回调地址 | 是 | 没填 → 通道未启用；填了不通 → 回调收不到，只能靠主动查单 |
| 微信：平台证书公钥（可选） | 否 | 乱填非法内容时系统会记一条日志并**回退到联网下载**，不会因此启用失败 |
| 支付宝：APPID / 应用私钥 | 是 | 通道未启用，或下单请求验签失败 |
| 支付宝：支付宝公钥 | 是 | 填成应用公钥 → **回调验签永远失败**，系统收不到支付成功 |
| 支付宝：回调地址 | 是 | 同微信 |

### 界面上会看到的字段（收银台 / 支付流水）

| 字段 | 说明 |
| --- | --- |
| 扫码收款（弹窗标题） | 显示渠道名与应收金额。渠道名会如实写成「微信 Native 扫码」或「支付宝扫码」 |
| 二维码内容 | 渠道返回的**支付链接文本**（微信 `weixin://` 开头、支付宝 `https://qr.alipay.com/` 开头），不是图片 |
| 剩余有效时间 | 二维码倒计时（默认 5 分钟） |
| 重新获取 / 改现金收款 | 到期后的两个出口（见阶段 6） |
| 支付流水 → 状态 | 待支付 / 成功 / 失败 / 已关闭 / 已全额退款 / 部分退款 |
| 支付流水 → 渠道交易号 | 渠道那边的单号，和渠道客服核对时用它 |
| 支付流水 → 渠道轨迹 | 事件列表：创建支付单 / 渠道回调 / 主动查单 / 关单 / 退款 / 回调验签失败 |

> 💡 大白话：「渠道轨迹」就是这笔钱的**行车记录仪**。钱到没到、是渠道主动通知的还是我们自己去问的、有没有验签失败过，全在这几条记录里。查不出问题时，把轨迹截图给技术对接人，一眼就能定位。

## 使用注意事项

> ⚠️ **配置齐全才算启用，缺一项就是「未启用」，但绝不影响其它收款方式。** 现金、微信 / 支付宝线下收款码、储值余额、次卡核销、挂账**都不需要通道配置**，通道没开通时照常使用。所以开通可以慢慢做，门店不会因为没配好就收不了钱。

> ⚠️ **未配置时选择在线渠道会报错，但不会产生任何脏数据。** 系统在**写任何本地数据之前**就先检查通道是否启用，所以不会留下待支付单、不会扣钱、也不会影响那张预约。看到「通道未启用」，直接改成现金或线下收款码继续收款。

> ⚠️ **未配置的通道在每日对账里会被自动跳过。** 系统会记一条日志并跳过该渠道（不报警、不算失败），账单为空时也会跳过，避免误报「系统缺单」。所以「对账页面一片空白」不等于「没问题」，要看清是不是这条通道根本没开。

> ⚠️ **改完配置必须重启服务。** 配置是服务启动时读入的，改文件不重启等于没改。这是最容易被漏掉的一步，也是「明明填了却还提示未启用」的第一大原因。

> ⚠️ **回调地址必须是公网 HTTPS。** 微信和支付宝只会往这个地址发成功通知。打不通的后果不是丢钱，而是：系统状态靠每 2 分钟一次的主动查单兜底，延迟变大；长期不通会让对账出现大量「系统状态不一致」的噪声。

> ⚠️ **回调里的金额和系统金额不一致时，系统会拒绝这笔通知并留证。** 这是保护机制——**绝不会按渠道传来的金额改账**。如果反复出现，立刻找技术对接人，别让前台手工改金额。

> ⚠️ **二维码默认 5 分钟失效。** 失效后请用「重新获取」或「改现金收款」，不要拿旧二维码反复让顾客扫。重新获取会先关旧单再新建，这是正常流程。

> ⚠️ **关单之后仍然可能收到钱。** 系统会在关单 / 失败后继续查 24 小时，查到钱就自动救回并落账。所以**关单后不要立刻当成没收钱**，先把这笔处理干净再决定下一步收款方式。

> ⚠️ **密钥交给谁 = 把钱柜钥匙交给谁。** 商户私钥 + 序列号 + APIv3 密钥泄露，等于别人可以冒充门店和微信打交道。务必只放在服务器配置与门店自己的密码管理里，怀疑泄露立刻在商户平台作废重设。

> ⚠️ **小程序内支付没开通，小程序充值也没开通。** 小程序里充值页面用的是提示语「充值通道正在接入，可先到店充值」，不是真的能充值。**顾客充值只能到店由前台操作。**

## 常见问题

**Q：不配置通道，门店还能正常营业吗？**
A：能。现金、微信 / 支付宝**线下**收款码、储值余额、次卡核销、挂账都不需要配置，收银、退款、会员、预约全都正常。在线扫码只是「更省事、能自动对账」的加分项。

**Q：只配微信、不配支付宝可以吗？**
A：可以。两条通道互相独立，配置齐全的那条能用，没配的那条在收银台选到会提示「通道未启用」。

**Q：我明明填了配置，为什么还提示「微信支付通道未启用」？**
A：按顺序查四件事：① 六个必填项是不是**都有值**（少一个就等于没配）；② 改完配置**重启服务**了吗；③ `WXPAY_API_V3_KEY` 是不是**正好 32 位**（不是 32 位会报专门的提示）；④ 有没有把值写在注释行里或前后带空格。

**Q：收银台弹窗里显示的不是二维码图片，是一串字符。**
A：这是当前版本的已知情况：界面**没有内置二维码渲染**，渠道返回的是支付链接文本。点「复制二维码内容」把链接转成二维码给顾客扫，或直接用现金 / 线下收款码。

**Q：顾客付了钱，但系统一直显示「待支付」。**
A：先等几秒（弹窗每 3 秒自动查一次）。仍然不变时：到「支付流水」找到这笔，点「查单」主动向渠道确认。若查单也确认已付款，系统会自动补记成功。**在确认之前不要重复收款。**

**Q：对账页面上看不到微信 / 支付宝的差异，是不是说明没问题？**
A：不一定。通道没配置时对账任务会**跳过**该渠道；渠道账单为空时也会跳过。所以先确认通道确实配好了，再看差异。

**Q：能不能先用沙箱环境试，不花真钱？**
A：系统里渠道的网关地址是固定的正式地址，没有沙箱开关。开通验证只能用正式商户号走**小额真实交易**。

**Q：微信提示商户证书快过期了怎么办？**
A：商户 API 证书有效期 5 年且**不能续期**，需要在商户平台**申请新证书**，然后把新的私钥与新的序列号一起更新到配置里并重启服务，最后做一次小额验证。**换证书时序列号和私钥必须成对更换**，只换一个会导致所有请求签名失败。平台证书由系统自动下载，不必手工干预。

**Q：我没配支付通道，那「支付对账」这个菜单还需要看吗？**
A：不需要。没有在线通道就没有渠道账单可比。等开通了再看，并在**每天开店前**花几分钟清掉待处理差异。
