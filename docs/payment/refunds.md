# 退款

## 这个模块解决什么问题

顾客要退钱，门店必须回答四个问题：

1. **该不该退、退多少？** —— 服务开始前：无理由全退；服务开始后：由店长判断。
2. **谁说了算？** —— 服务开始前，前台就能退；服务开始后，只有店长能退。
3. **钱怎么回去？**（原路退回、给现金、还是退到会员卡余额？）
4. **会不会退重了？**（同一个人点了两次会不会退两笔？）

系统的做法是：**按「当前时间有没有过预约开始时间」把退款分成两种，各自有各自的规矩，然后一步退到位。**

| 什么时候退                 | 谁决定       | 退多少                                     |
| -------------------------- | ------------ | ------------------------------------------ |
| **服务开始前**（还没到点） | 前台就可以退 | **无理由全额退**，系统锁定金额             |
| **服务开始后**（含已做完） | **只有店长** | **店长手动填**，上限是这笔收款还能退的余额 |

> 💡 大白话：客人还没到店就说要退 —— 不多问，全退。人已经来了、甚至在做了 —— 退不退、退多少，店长拍板。
> 系统只看**当前时间有没有过预约开始时间**，不看预约单是什么状态。

## 谁来用（适用角色）

| 角色          | 能做什么                                               | 对应权限      |
| ------------- | ------------------------------------------------------ | ------------- |
| 前台 / 收银员 | 退款试算；**服务开始前**直接发起并完成退款；查看退款单 | 退款审批-申请 |
| 店长          | 上面全部 + **服务开始后**发起退款、重试失败的退款      | 退款审批-审批 |

**权限设计的关键**：服务开始前不需要审批 —— 无理由可争，要的是快；服务开始后必须店长权限 —— 这时才需要有人对「退多少」负责。

> ⚠️ 系统是按权限点控制的，不是按人名控制的。建议给前台只配「退款审批-申请」，把「审批」这一项收在店长手里。

## 操作路径

后台管理端 → 左侧菜单「美甲预约」→「退款审批」，或直接访问 `/biz/refunds`

列表默认列出全部状态的单子，顶部可以按**退款阶段**（服务开始前 / 服务中）和状态筛选。

## 分步操作

### 一、看清一张退款单的关键字段

打开列表，每行都能看到这些字段（列名就是界面上的原名）：

| 列名              | 意思                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| 退款单号          | 这张退款单的编号，沟通时用它                                         |
| 预约号            | 因为哪张预约退的钱                                                   |
| 会员              | 退给谁                                                               |
| 支付单号          | **退的是哪一笔收款**（一张单子收过好几次钱时，这一列决定退的是哪笔） |
| 申请金额(元)      | 这次退款的金额                                                       |
| 实退金额(元)      | 实际退出去的钱（正常与申请金额一致）                                 |
| 阶段              | **服务开始前**（绿） / **服务中**（橙）—— 决定这笔退款按哪套规矩办   |
| 去向              | 原路退回 / 现金退 / 退入余额                                         |
| 责任              | 店家 / 顾客 / 不可抗力                                               |
| 原因              | 退款原因                                                             |
| 状态              | 已退款成功 / 退款失败 /（历史的）待审批 / 已通过 / 已驳回            |
| 申请人 / 申请时间 | 谁在什么时候提交的                                                   |

### 二、发起退款（服务开始前：前台可直接退）

1. 页面右上角点「**发起退款**」。
2. 表单里填：
   - **预约**（必填）：支持按单号 / 姓名 / 手机号搜索后再选；
   - **判定时间**（选填）：不填按「现在」判定服务阶段，补录以前的退款才需要填；
   - **退款金额(元)**：先试算再回填。**服务开始前这一栏是锁定的，改不了**；
   - **去向**：原路退回 / 现金退 / 退入余额；
   - **责任**：服务开始前固定「店家」，这一项不显示；
   - **退款原因**（必填）。
3. 点「**判定阶段 / 试算**」—— 这一步决定这笔退款按哪套规矩办：
   - 试算结果会显示五行：**退款阶段**、距开始、可退上限、建议退款额、按规则参考；
   - 服务开始前提示「服务开始前，可无理由全额退 X 元」，金额**自动回填并锁定**；
   - 服务开始后提示「服务已开始，是否退款、退多少由店长决定，请手动填写金额」，金额留空等店长填；
   - 该预约没有在线支付单时，去向会自动改成「现金退」并说明原因。
4. 点提交 → 二次确认窗会写明：
   - 服务开始前：「服务开始前无理由全额退 X 元，按『原路退回』**立即执行**（无需审批）。确定吗？」
   - 服务开始后：「将按『现金退』立即退款 X 元（店长手动判定）。确定吗？」
5. 确认后系统**当场执行退款**，提示「退款已执行」，列表自动刷新。

> ⚠️ **提交 = 立即退钱。** 服务开始前不需要任何人审批，点下去钱就出去了（原路退回是打给微信 / 支付宝，现金退 / 退入余额是当场记账）。

### 三、服务中退款（只有店长能做）

1. 同样点「发起退款」，选好预约、点「判定阶段 / 试算」。
2. 如果试算结果里「退款阶段」显示**服务中**：
   - 「退款金额」由**店长手动填写**（不会自动带出建议值）；
   - 「责任」这一项才会出现（默认「店家」）；
   - 前台账号走到提交会被拒：**「预约已开始，退款需店长处理」**。
3. 金额规则：**必须大于 0，且不能超过「可退上限」**（= 这张支付单收了多少 − 已经退了多少）。
4. 提交后同样当场执行 —— 服务中只是「多了一道店长的判断」，不是「多了一道等待」。

> 💡 大白话：服务中退款没有「申请单」和「审批」两步。店长填多少钱，系统就退多少钱，填的那一刻就执行。

### 四、退款金额谁说了算

| 情况       | 金额怎么来                                     |
| ---------- | ---------------------------------------------- |
| 服务开始前 | 系统锁定为**全额**（这笔收款还剩多少就退多少） |
| 服务开始后 | **店长手动填**，上限是可退上限                 |

「按规则参考」那一行是旧判责规则算出来的数字，**只是给店长看的参考**，不会自动带出、也不会自动扣款：

| 规则名称        | 提前时间                  | 参考可退比例 | 举例（假设实收 200 元） |
| --------------- | ------------------------- | ------------ | ----------------------- |
| 24 小时以上全退 | 提前 ≥ 24 小时取消        | 100%         | 200 元                  |
| 2-24 小时退一半 | 提前 2~24 小时取消        | 50%          | 100 元                  |
| 2 小时内不退    | 提前 < 2 小时取消，或爽约 | 0%           | 0 元                    |

- 服务已经做完、顾客事后投诉要求补偿 —— 退多少完全由店长决定，参考值只能帮你想个数字；
- 想全退就全退，想退一半就填一半，**只要不超过可退上限**。

### 五、三种去向怎么选

| 去向     | 界面文案 | 什么时候用                                                  | 谁能用                                                                 |
| -------- | -------- | ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| 原路退回 | 原路退回 | 顾客是用微信 / 支付宝**在线扫码**付的钱，钱退回到原付款账户 | **只有在线支付可以**。现金、线下收款码、储值、次卡、挂账付的单子不能选 |
| 现金退   | 现金退   | 顾客当初付的是现金 / 扫的是店家自己的码，当场退现金给顾客   | 任何支付单都可以                                                       |
| 退入余额 | 退入余额 | 顾客是会员，与其退现金不如退到会员卡里继续消费              | 需要会员身份；退的是**实付本金**，赠送金额不退                         |

系统里的提示语：

- 选「原路退回」时提示：**「在线支付强制原路退回；线下收款（现金 / 收款码）不支持原路退回。」**
- 选「退入余额」时提示：**「退入储值余额需会员身份，将同事务回补余额并写会员流水。」**

> 💡 大白话：原路退回的意思是「从哪张卡出去就从哪张卡回来」。微信付的就退回微信，这是渠道的规矩，不是门店能选的。

### 六、退款成功后系统自动做了什么

退款执行成功之后，系统会在**同一个动作里**完成下面这些事，不需要人工再做：

1. 记录退款成功、写下渠道退款单号（原路退回时）；
2. 更新那张**支付单**的「已退金额」，状态变成「部分退款」或「已全额退款」；
3. **重算预约单上的金额**：已退款、待收尾款都会跟着变（如果退款后尾款重新大于 0，这张单会回到收银台的「待收尾款」队列）；
4. **回减会员的累计消费与积分**（按退款金额等比例回减）；
5. **冲销对应的提成**（美甲师的提成记录会被冲掉相应部分）；
6. 如果去向是「退入余额」，把钱加回会员余额并写一条会员流水。

### 七、渠道退款失败怎么办

原路退回是给微信 / 支付宝发请求，可能失败（网络、参数、账户异常）。失败时：

- 退款单状态变成 **退款失败**，列表里会出现「**重试执行**」按钮；
- 确认渠道侧恢复正常后点「重试执行」→ 二次确认后系统重新发起；
- 也可以改用「现金退」重新提交一张新的退款申请，当面把钱给顾客。

> 💡 失败单的钱在渠道里**没动**，单据上的商户退款单号不变，渠道侧天然去重 —— 重试不会退两次。

## 字段说明

| 字段         | 必填       | 说明                                                 | 填错会怎样                                                                                                  |
| ------------ | ---------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 预约         | 是         | 要退哪张预约。系统据此找到支付单、判定服务阶段       | 填错会退到别人的单子上；找不到会提示「预约不存在」                                                          |
| 判定时间     | 否         | 判定服务阶段用的时点；不填按当前时间                 | 补录历史退款时不填，会按「现在」判定，可能把「服务开始前」算成「服务中」                                    |
| 退款金额(元) | 服务中必填 | 服务开始前由系统锁定为全额；服务中由店长手动填       | 服务中不填会被拦（「服务中退款必须手动填写退款金额」）；超过可退上限会提示「退款金额不能超过可退上限 X 元」 |
| 去向         | 是         | 原路退回 / 现金退 / 退入余额                         | 现金支付选「原路退回」会被拒，提示「该支付单不是在线支付，原路退回不可用，请选择现金退或退入储值余额」      |
| 责任         | 服务中必填 | 店家 / 顾客 / 不可抗力（服务开始前固定店家，不显示） | 服务中忘了选会被拦；它只影响单据留痕，不影响退款金额                                                        |
| 退款原因     | 是         | 必填说明                                             | 空着或太短会被拦（「退款原因必填」「退款原因过于简单」）；**没有理由的退款事后没人说得清**                  |
| 驳回原因     | 驳回时必填 | 为什么不批（只对历史的待审批单有效）                 | 不填会提示「驳回原因必填」                                                                                  |

## 使用注意事项

> ⚠️ **退款单必须挂在「某一笔支付单」上。** 一张预约用混合支付收过好几次钱（例如余额 120 + 现金 80），退款时**要按笔分别处理**，不能合成一笔退。试算结果里的「可退上限」是按当前这一笔算的。

> ⚠️ **原路退回只对在线支付开放。** 顾客当初扫的是店家自己的码（属于线下收款码记账），或者付的现金 / 储值 / 次卡 / 挂账，都**不能选原路退回**，只能现金退或退入余额。硬选会被系统拒绝。

> ⚠️ **提交 = 立即执行，且只能执行一次。** 服务开始前没有审批环节，点「确认退款」钱就出去了。系统用条件更新保证同一张单不会被退两次，但**点错了也没法撤回** —— 只能再走一笔相反方向的调整，所以点之前务必核对金额与去向。

> ⚠️ **服务中退款只有店长能做。** 前台在服务开始后发起会被拒（「预约已开始，退款需店长处理」）。这是有意设计的：钱已经发生的部分要有人负责。

> ⚠️ **历史的待审批单仍可审批 / 驳回。** 老数据里可能有停在「待审批」的单子，点「审批」能执行、点「驳回」能作废；已驳回的单子再点通过会提示「退款单已被驳回，不能执行」，要重新退就**重新发起一张**。

> ⚠️ **退款金额不能超过「可退上限」。** 上限 = 这张支付单的收款金额 − 已经退过的金额。已经全额退过的支付单不能再退，系统会提示「该支付单已无可退金额」；如果整个预约的钱都退完了，会提示「该预约没有可退款的支付单」。

> ⚠️ **服务中改金额也要写清楚原因。** 金额由店长决定，但**必须留下书面理由** —— 这是事后复盘（以及老板查账）时唯一的依据。

> ⚠️ **退了钱，业绩与积分会一起回退。** 退款成功后系统会自动回减顾客的累计消费与积分、并冲销对应提成。如果只想着「把钱退了」，会发现会员的累计消费和积分也变少了 —— 这是设计如此，不是 bug。

> ⚠️ **储值充值的钱不完全走这条流程。** 顾客「充值」进来的钱要退回时，后台走的是「会员管理 → 冲正退款」（现金冲正 / 储值冲正，只写反向流水，**不生成退款单**）。而**在线支付的收款**退款才是本页的流程。两者不要混：不确定时先问店长，或看 [会员储值充值](../member/recharge-cards.md)。

## 常见问题

**Q：顾客还没到店就取消了，应该退他多少钱？**
A：**全退**。服务还没开始，系统会锁定为这笔收款剩余的全额，金额不用你算。

**Q：顾客已经做完了，事后投诉要求退 50 元，怎么操作？**
A：这是**服务中**的退款，要店长操作：点「发起退款」→ 选预约 → 试算 → 在「退款金额」里手动填 50 → 提交即时执行。前台账号提交会被拒。

**Q：我是前台，顾客现在就要现金退，我能直接退吗？**
A：**看时间。** 预约还没开始 —— 能，选「现金退」提交即时记账。预约已经开始了 —— 只能叫店长来操作。

**Q：为什么我提交后提示「预约已开始，退款需店长处理」？**
A：当前时间已经过了这张预约的开始时间，属于**服务中退款**，需要「退款审批-审批」权限（店长）。请找店长处理。

**Q：退入余额比现金退方便，能都选退入余额吗？**
A：可以，但必须顾客同意。退入余额退的是**实付本金**，赠送部分不退；而且余额只能在本店消费。已经离店不再来的顾客，选现金退更合适。

**Q：顾客付了定金 60 元，现在要退，能退多少？**
A：看时间。服务还没开始就是全退 60 元；已经开始了，由店长定（最多 60 元）。

**Q：退款单里怎么会有一个「待审批」状态？**
A：那是升级前的老数据（当时是「申请 → 审批」两步）。现在新发的退款单会直接变成「已退款成功」或「退款失败」。老单子点「审批」能执行、点「驳回」能作废。

**Q：退款到一半失败，钱到底出去了没有？**
A：**没出去。** 渠道退款失败时系统会把占用的额度释放掉，单据停「退款失败」，钱仍在渠道（或顾客原账户）。点「重试执行」重新发一次即可，不会退两次。

**Q：退款后，这张预约在收银台又出现了，是正常的吗？**
A：正常。退款会重新计算「待收尾款」，如果退款导致已收金额低于应付金额，这张单就会回到「待收尾款」队列。例如应付 200、已收 200，退了 100 之后待收尾款就是 100。

**Q：能先退款再让顾客补办手续？**
A：退款单上必须填原因并留下提交人。请不要把退款当「走个流程」，每一笔都要有真实理由。
