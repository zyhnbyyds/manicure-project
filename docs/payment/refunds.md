# 退款

## 这个模块解决什么问题

顾客要退钱，门店必须回答四个问题：

1. **退多少？**（是全额退，还是按规则扣一部分？）
2. **谁说了算？**（前台能不能直接退？）
3. **钱怎么回去？**（原路退回、给现金、还是退到会员卡余额？）
4. **会不会退重了？**（同一个人点了两次会不会退两笔？）

本模块把这三件事分开管：**判责试算给建议 → 前台申请 → 店长审批 → 系统执行**。这样做的好处是：退多少有依据（不是拍脑袋），退钱有人复核（不是一个人说了算），退几次有记录（不会退重）。

> 💡 大白话：退款不是一个「点一下就退钱」的按钮，而是一张**需要审批的单子**。前台填单子，店长批单子，系统才真正把钱退出去。

## 谁来用（适用角色）

| 角色          | 能做什么                            | 对应权限      |
| ------------- | ----------------------------------- | ------------- |
| 前台 / 收银员 | 判责试算、发起退款申请、查看退款单  | 退款审批-申请 |
| 店长          | 上面全部 + **审批通过并执行**、驳回 | 退款审批-审批 |

**权限设计的关键**：申请和审批是两个独立权限点。「退款审批-审批」建议**只给店长**，前台只给「申请」。这样即使前台判断错了金额，也还有人复核。

> ⚠️ 系统是按权限点控制的，不是按人名控制的。如果某个账号同时被授予了申请和审批两个权限，它在系统里就能自己申请自己批。请店长在配角色时把「审批」这一项收好。

## 操作路径

后台管理端 → 左侧菜单「美甲预约」→「退款审批」，或直接访问 `/biz/refunds`

页面标题是「退款审批」，副标题是「判责试算 + 申请 / 审批分离（审批默认只看待审批单）」。

列表**默认只筛出「待审批」**的单子——这是为了让店长一进页面就看到需要自己处理的活儿。

## 分步操作

### 一、看清一张退款单的六个关键数字

打开列表，每行都能看到这些字段（列名就是界面上的原名）：

| 列名              | 意思                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| 退款单号          | 这张退款单的编号，沟通时用它                                         |
| 预约号            | 因为哪张预约退的钱                                                   |
| 会员              | 退给谁                                                               |
| 支付单号          | **退的是哪一笔收款**（一张单子收过好几次钱时，这一列决定退的是哪笔） |
| 申请金额(元)      | 申请的退款金额（判责基数）                                           |
| 实退金额(元)      | 实际退出去的钱                                                       |
| 判责扣减(元)      | 因为责任在顾客而扣下的钱（申请金额 − 实退金额）                      |
| 去向              | 原路退回 / 现金退 / 退入余额                                         |
| 责任              | 店家 / 顾客 / 不可抗力                                               |
| 原因              | 申请时填的退款原因                                                   |
| 状态              | 待审批 / 已通过 / 已退款 / 已驳回 / 退款失败                         |
| 申请人 / 申请时间 | 谁在什么时候提的                                                     |

### 二、发起退款申请（前台）

1. 点右上角「**发起退款申请**」。
2. 表单里填：
   - **预约 ID**（必填）：用于定位支付单与判责规则；
   - **取消时间**（选填）：不填就按「现在」判责。补录以前的取消要用到它，格式是日期；
   - **退款金额(元)**：先试算再回填，也可以手动改；
   - **去向**：原路退回 / 现金退 / 退入余额；
   - **责任**：店家 / 顾客 / 不可抗力；
   - **退款原因**（必填，不能太短，最少 2 个字）。
3. 点「**试算判责**」——这是最关键的一步：
   - 系统会算出「命中规则、规则阈值、距开始、可退比例、建议退款额、判责扣减、可退上限」；
   - 并把**建议退款额自动回填**到「退款金额」框里；
   - 提示语是「试算完成，已回填建议退款金额」。
4. 核对试算结果。**同意就往下走；不同意可以手动改金额，但改了金额必须在「退款原因」里写清楚为什么改**（例如「顾客提前 3 天说明家中急事，店长同意全退」）。
5. 点「提交申请」→ 二次确认窗会写明「将按『原路退回』发起 X 元退款申请，生成待审批退款单，**需店长审批后才会执行**」。
6. 确认后系统提示「已生成待审批退款单，需店长审批后执行」，列表自动切回「待审批」，方便店长直接看到。

> 💡 大白话：**申请不等于退钱。** 前台提交完只是「把单子递上去了」，钱一分都还没动。必须店长点「通过」才会真的退。

### 三、审批（只给店长）

1. 在列表里找到状态是「待审批」的单子，点「审批」图标（不是待审批的单子点进去只能看详情，底部只有「关闭」）。
2. 弹窗标题是「退款审批」，里面列出退款单号、预约号、会员、申请金额、实退金额、判责扣减、去向、责任、申请人、申请时间、**命中规则**、退款原因。
3. 底部两个按钮：
   - **「通过」**：会弹二次确认「通过后将立即执行退款（原路退回调渠道 / 现金或退余额直接落地），**且只能执行一次**。确定通过吗？」→ 点「确认通过」后系统立刻执行，提示「已通过并执行退款」；
   - **「驳回」**：必须填写驳回原因（必填，会记录在退款单上），二次确认后提示「已驳回」。驳回后这张单子**不再执行退款**。
4. 通过之后的执行结果：
   - 去向是「原路退回」→ 系统把这笔退给微信 / 支付宝，钱回到顾客原来的付款账户；
   - 去向是「现金退」→ 系统直接记账，钱由店里当面给顾客；
   - 去向是「退入余额」→ 系统直接把这笔加回到顾客的会员余额里。

> ⚠️ **「通过」是不可撤销的动作。** 通过后系统立刻打款或记账。点之前请把金额、去向、责任这三项再看一遍。

### 四、判责规则：退多少是谁定的

系统里预置了三档判责规则（规则名称就是后台看到的名字）：

| 规则名称        | 提前时间                  | 可退比例 | 举例（假设实收 200 元） |
| --------------- | ------------------------- | -------- | ----------------------- |
| 24 小时以上全退 | 提前 ≥ 24 小时取消        | 100%     | 200 元全退              |
| 2-24 小时退一半 | 提前 2~24 小时取消        | 50%      | 退 100 元，扣 100 元    |
| 2 小时内不退    | 提前 < 2 小时取消，或爽约 | 0%       | 不退                    |

**规则怎么被选中**：系统按「规则要求的提前小时数 ≤ 实际提前小时数」的条件，取**其中最大的那一条**。

- 举例：顾客提前 30 小时取消 → 满足「≥24 小时」也满足「≥2 小时」，取最大的那条（24 小时档）→ **全退**；
- 举例：顾客提前 3 小时取消 → 只满足「≥2 小时」→ **退一半**；
- 举例：顾客提前 1 小时取消，或者已经过了预约开始时间（甚至爽约）→ 连「0 小时」那条也算不上更宽松 → 命中「2 小时内不退」→ **不退**。

**责任归属会覆盖规则**（这是很多人搞混的地方）：

| 责任     | 结果                                       |
| -------- | ------------------------------------------ |
| 顾客     | **按规则扣减**（上面三档就是为它准备的）   |
| 店家     | **全退**（例如美甲师临时请假、门店做错了） |
| 不可抗力 | **全退**（例如台风、突发疫情）             |

**一条都命中不了怎么办**：全退（相当于没有可用的扣减依据，宁可对顾客宽松）。

**规则只给建议**：试算结果里的「建议退款额」只是建议。最终金额由店员在申请时确认，店长在审批时把关。

### 五、三种去向怎么选

| 去向     | 界面文案 | 什么时候用                                                  | 谁能用                                                                 |
| -------- | -------- | ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| 原路退回 | 原路退回 | 顾客是用微信 / 支付宝**在线扫码**付的钱，钱退回到原付款账户 | **只有在线支付可以**。现金、线下收款码、储值、次卡、挂账付的单子不能选 |
| 现金退   | 现金退   | 顾客当初付的是现金 / 扫的是店家自己的码，当场退现金给顾客   | 任何支付单都可以                                                       |
| 退入余额 | 退入余额 | 顾客是会员，与其退现金不如退到会员卡里继续消费              | 需要会员身份；退的是**实付本金**，赠送金额不退                         |

系统里的提示语：

- 选「原路退回」时提示：**「在线支付强制原路退回。」**
- 选「退入余额」时提示：**「退入储值余额需会员身份，将同事务回补余额并写会员流水。」**

> 💡 大白话：原路退回的意思是「从哪张卡出去就从哪张卡回来」。微信付的就退回微信，这是渠道的规矩，不是门店能选的。

### 六、退款成功后系统自动做了什么

店长点「通过」之后，系统会在**同一个动作里**完成下面这些事，不需要人工再做：

1. 记录退款成功、写下渠道退款单号（原路退回时）；
2. 更新那张**支付单**的「已退金额」，状态变成「部分退款」或「已全额退款」；
3. **重算预约单上的金额**：已退款、待收尾款都会跟着变（如果退款后尾款重新大于 0，这张单会回到收银台的「待收尾款」队列）；
4. **回减会员的累计消费与积分**（按退款金额等比例回减）；
5. **冲销对应的提成**（美甲师的提成记录会被冲掉相应部分）；
6. 如果去向是「退入余额」，把钱加回会员余额并写一条会员流水。

## 字段说明

| 字段         | 必填       | 说明                                       | 填错会怎样                                                                                               |
| ------------ | ---------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 预约 ID      | 是         | 要退哪张预约。系统据此找到支付单与判责规则 | 填错会退到别人的单子上；找不到会提示「预约不存在」                                                       |
| 取消时间     | 否         | 判责用的取消时点；不填按当前时间           | 补录历史取消时不填，会按「现在」判责，可能算出「2 小时内不退」                                           |
| 退款金额(元) | 是         | 本次要退多少。默认由试算回填               | 超过可退上限会提示「退款金额不能超过可退上限 X 元」；填 0 或负数会被拦                                   |
| 去向         | 是         | 原路退回 / 现金退 / 退入余额               | 现金支付选「原路退回」会被拒，提示「该支付单不是在线支付，原路退回不可用，请选择现金退或退入储值余额」   |
| 责任         | 是         | 店家 / 顾客 / 不可抗力                     | 责任选错直接导致退款金额算错；选「顾客」才会按规则扣减                                                   |
| 退款原因     | 是         | 最少 2 个字的说明                          | 空着或太短会被拦（「退款原因必填」「退款原因过于简单」）；**改了建议金额却不写原因，事后没人知道为什么** |
| 驳回原因     | 驳回时必填 | 为什么不批                                 | 不填会提示「驳回原因必填」                                                                               |

## 使用注意事项

> ⚠️ **退款单必须挂在「某一笔支付单」上。** 一张预约用混合支付收过好几次钱（例如余额 120 + 现金 80），退款时**要按笔分别申请**，不能合成一笔退。系统在试算结果里会给出「逐笔可退明细」，请按明细一笔一笔处理。

> ⚠️ **原路退回只对在线支付开放。** 顾客当初扫的是店家自己的码（属于线下收款码记账），或者付的现金 / 储值 / 次卡 / 挂账，都**不能选原路退回**，只能现金退或退入余额。硬选会被系统拒绝。

> ⚠️ **审批通过 = 立即执行，且只能执行一次。** 重复点「通过」不会退第二笔，第二次会得到「该退款单已处理」。这是系统的保护。但反过来：**点错了也没法撤回**，只能再走一笔相反方向的调整，所以点之前务必核对。

> ⚠️ **已驳回的单子不能执行。** 被驳回后再点通过会提示「退款单已被驳回，不能执行」。要重新退，请**重新发起一张新的退款申请**。

> ⚠️ **渠道退款失败会停在「退款失败」状态，需要人工处理。** 常见原因是渠道侧参数问题或账户异常。系统会提示「渠道退款失败，可重试或改为现金退」——请**重试一次**，或改用「现金退」重新提交，不要放着不管（顾客会一直等）。

> ⚠️ **退款金额不能超过「可退上限」。** 上限 = 这张支付单的收款金额 − 已经退过的金额。已经全额退过的支付单不能再退，系统会提示「该支付单已无可退金额」；如果整张预约的钱都退完了，会提示「该预约没有可退款的支付单」。

> ⚠️ **改动系统建议的金额必须写原因。** 规则只是建议，店长有权决定全退或部分退，但**必须留下书面理由**。这是事后复盘（以及老板查账）时唯一的依据。

> ⚠️ **退了钱，业绩与积分会一起回退。** 退款成功后系统会自动回减顾客的累计消费与积分、并冲销对应提成。如果只想着「把钱退了」，会发现会员的累计消费和积分也变少了——这是设计如此，不是 bug。

> ⚠️ **储值充值的钱不完全走这条流程。** 顾客「充值」进来的钱要退回时，后台走的是「会员管理 → 冲正退款」（现金冲正 / 储值冲正，只写反向流水，**不生成退款审批单**）。而**在线支付的收款**退款才是本页的流程。两者不要混：不确定时先问店长，或看 [会员储值充值](../member/recharge-cards.md)。

## 常见问题

**Q：顾客还没到店就取消了，应该退他多少钱？**
A：先看取消时间，再用「发起退款申请 → 填预约 ID → 试算判责」让系统算。提前 24 小时以上全退；提前 2~24 小时退一半；不到 2 小时或爽约不退。责任在店家或不可抗力则全退。

**Q：我是前台，顾客现在就要现金退，我能直接退吗？**
A：前台能**发起申请**，但钱要等店长审批通过才会记账。如果顾客不愿意等，请先跟店长确认，不要自己掏钱垫付后不入系统。

**Q：为什么我点「通过」后提示「该退款单已处理」？**
A：说明这张单子已经退过了（可能是你自己点重了，或是另一位店长刚处理）。**不要当成失败再操作一遍**，先去列表里把状态改成「全部状态」查这张单的最终状态。

**Q：退入余额比现金退方便，能都选退入余额吗？**
A：可以，但必须顾客同意。退入余额退的是**实付本金**，赠送部分不退；而且余额只能在本店消费。已经离店不再来的顾客，选现金退更合适。

**Q：顾客付了定金 60 元，现在要退，能退多少？**
A：看取消时间与责任。如果提前 24 小时以上、责任在顾客，就是全退 60 元；提前 2~24 小时退 30 元。

**Q：退款后，这张预约在收银台又出现了，是正常的吗？**
A：正常。退款会重新计算「待收尾款」，如果退款导致已收金额低于应付金额，这张单就会回到「待收尾款」队列。例如应付 200、已收 200，退了 100 之后待收尾款就是 100。

**Q：能不能先退款再让顾客补办手续？**
A：退款单上必须填原因，申请人和审批人都会留痕。请不要把退款当「走个流程」，每一笔都要有真实理由。
