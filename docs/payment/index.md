# 收银台总览

## 这个模块解决什么问题

一间店每天要回答三个问题：**这张单子该收多少钱、已经收了多少、还差多少**。本模块把这三个数字固定下来，让前台、店长、报表看到的是同一套数。

> 💡 大白话：一张单子的钱只有两个「原始动作」——**收钱**（生成支付单）和**退钱**（生成退款单）。预约单上显示的「已收多少、还差多少」不是手工填的，而是系统根据这些收款记录**自动算出来的**。所以任何金额上的疑问，都去查「支付流水」，不要凭印象改数字。

一张单子从「应收」到「结清」的全过程，就是下面这几个数字的变化：

| 数字         | 界面上的叫法 | 怎么来的                                            | 在哪里看     |
| ------------ | ------------ | --------------------------------------------------- | ------------ |
| 项目原价     | 项目原价     | 各服务项目价格相加                                  | 收银台中间栏 |
| 等级优惠     | 等级优惠     | 按会员等级折扣算出来的优惠金额                      | 收银台中间栏 |
| 积分抵扣     | 积分抵扣     | 用积分抵掉的钱                                      | 收银台中间栏 |
| 手动改价     | 手动改价     | 店员改的差价（要填原因）                            | 收银台中间栏 |
| **应收金额** | 应付金额     | 原价 − 等级优惠 − 积分抵扣 + 手动改价（不会小于 0） | 收银台中间栏 |
| **已收金额** | 已收金额     | 这张单子所有成功收款之和                            | 收银台中间栏 |
| **待收尾款** | 待收尾款     | 应收 − 已收（不会小于 0）                           | 收银台中间栏 |
| **已退款**   | 已退款       | 这张单子所有成功退款之和                            | 收银台中间栏 |
| 已收渠道     | 已收渠道     | 例如「现金,储值」，混合支付时会列出多个             | 收银台中间栏 |

当**待收尾款变成 0**，单据就结清了，收银台左栏「未收 / 待收尾款」里也就不再出现它。退款后如果待收尾款重新大于 0，单据会回到「待收尾款」。

> 💡 大白话：「已收渠道」显示成「现金,储值」这样的形式，是因为一张单子允许**混合支付**（一笔现金 + 一笔储值余额），单一渠道名写不下。看到逗号就说明这一单用了多种方式收钱。

### 一张单子的五个资金状态

收银台左栏的三种分组、以及各页面里的「资金状态」列，说的都是同一件事。看这张表就不会认错：

| 界面上显示   | 什么时候出现                             | 该做什么                           |
| ------------ | ---------------------------------------- | ---------------------------------- |
| **未收**     | 一分钱都还没收到（例如还没收定金的单子） | 到店后正常收款                     |
| **待收尾款** | 收过一部分（通常是定金），还有余额没结清 | 做完项目后收剩下的钱               |
| **已结清**   | 待收尾款 = 0                             | 不用再收；收银台队列里不再出现     |
| **已退款**   | 全额退过款                               | 到「退款审批」查退款单核对         |
| **挂账**     | 走的是赊账，钱还没收到                   | 到「应收台账」等销账，不在这里催收 |

### 什么时候用哪种收款方式

| 场景                                  | 建议用                            | 为什么                                         |
| ------------------------------------- | --------------------------------- | ---------------------------------------------- |
| 顾客给现金                            | 现金                              | 只记账不经过渠道，当场就完成；可填实收用于找零 |
| 顾客扫台面上店家自己的码              | 微信线下收款码 / 支付宝线下收款码 | 只记账，需要店员看到顾客的付款成功页           |
| 顾客扫系统生成的码                    | 微信 Native 扫码 / 支付宝扫码     | **会自动确认到账、能对账**，但需要先开通通道   |
| 会员卡里有钱                          | 储值余额                          | 不足会直接失败，要拆成「余额 + 其它方式」两行  |
| 顾客买过次卡                          | 次卡核销                          | 不产生金额、不叠加折扣；必须是卡种适用项目     |
| 公司月结 / 熟客赊账                   | 挂账                              | 生成应收单，**不计当日营收**，销账时才计入     |
| 带零头的金额（例如储值抵扣后剩 3 元） | 混一行现金补零                    | 混合支付是允许的，逐笔都会留下支付单           |

## 谁来用（适用角色）

| 角色          | 能做什么                                                               |
| ------------- | ---------------------------------------------------------------------- |
| 前台 / 收银员 | 收款、录线下收款、核销次卡、开发票前查账；可**发起**退款申请但不能审批 |
| 店长          | 上面全部 + 审批退款、销账、作废应收、处理对账差异、查看支付流水        |
| 老板 / 财务   | 看「支付流水」「支付对账」「应收台账」核对资金，不需要操作收银         |

钱的权限默认只给店长：**退款审批、应收销账**这两件事，前台看得见单据但批不了。

## 操作路径

后台管理端 → 左侧菜单「美甲预约」→ 下面这几个页面（本模块）：

| 页面     | 路径                   | 用途                                   |
| -------- | ---------------------- | -------------------------------------- |
| 收银台   | `/biz/cashier`         | 收款、开台结算、混合支付               |
| 支付流水 | `/biz/payments`        | 查每一笔收款的状态与渠道轨迹           |
| 退款审批 | `/biz/refunds`         | 发起退款（提交即执行）、重试失败的退款 |
| 支付对账 | `/biz/payment-diffs`   | 与微信、支付宝账单逐笔核对             |
| 挂账主体 | `/biz/credit-accounts` | 维护可以赊账的顾客 / 公司 / 员工       |
| 应收台账 | `/biz/receivables`     | 挂账产生的一笔笔欠款，以及销账         |

## 分步操作

本页是总览，具体操作请按下面顺序阅读：

1. **日常收款** → 看 [收银台操作](./cashier.md)。从「待收款队列」选单，确认金额，选支付方式，点「去收款」。
2. **要开通微信 / 支付宝扫码收款** → 看 [支付通道接入](./channels-setup.md)。这一步需要技术对接人配合，配置齐全才生效。
3. **顾客要退款** → 看 [退款](./refunds.md)。前台发起，店长审批后才会真正退钱。
4. **每天早上核对昨天的钱** → 看 [对账](./reconcile.md)。系统每天 6:30 自动拉渠道账单比对。
5. **顾客 / 公司赊账** → 看 [挂账与应收](./credit.md)。挂账不计营收，销账才计入。

## 字段说明

| 字段                   | 必填               | 说明                                       | 填错会怎样                                                     |
| ---------------------- | ------------------ | ------------------------------------------ | -------------------------------------------------------------- |
| 支付方式               | 是                 | 收银台右栏每一行的渠道，可加多行做混合支付 | 选错渠道会导致报表里收款方式统计错误；线上渠道选错还会影响对账 |
| 应收（金额）           | 是                 | 本次收款金额（元），不能大于「待收尾款」   | 超过待收尾款会被拦下，提示「本次收款合计 ¥X 超过应收尾款 ¥Y」  |
| 实收（金额）           | 现金时出现         | 顾客实际递过来的钱，用于找零               | 只有现金允许实收大于应收；其它方式实收超过应收会被拒绝         |
| 挂账主体               | 选了「挂账」时必填 | 这笔赊账记在谁名下                         | 不选会提示「挂账必须选择挂账主体」                             |
| 积分抵扣（使用积分数） | 否                 | 用多少积分抵扣这单                         | 超过上限会被系统按上限夹取；必须整笔抵扣，不做部分抵扣         |
| 备注                   | 否                 | 记录本次收款说明                           | 不影响金额，但事后查账少了线索                                 |

## 使用注意事项

> ⚠️ **金额一律以服务端重算为准，不要相信手上算出来的数。** 收银台页面上的金额都是系统算好的；改价、改积分都会触发重算。你只需要核对，不需要自己加减。

> ⚠️ **一张单子重复收款不会「多收」。** 如果顾客已经付过，单据会从「未收」移到「待收尾款 / 已结清」，左栏就不再有它。看到同一单还在「未收」里，先点开中间栏看「已收金额」和「已收渠道」，再决定要不要收。

> ⚠️ **小程序里的在线支付目前还没有开通。** 顾客在小程序点「微信支付」会看到「这个功能马上就来啦」，**不要在电话里承诺顾客可以在小程序里付款**。到店收款请用收银台的扫码 / 现金 / 线下收款码。

> ⚠️ **线上扫码收款必须先在服务器上配好通道。** 没配置时，收银台照样能选「微信 Native 扫码」，但提交会报「微信支付通道未启用」，不会生成任何待支付单。这时请改用现金或线下收款码。

> ⚠️ **混合支付的每一笔都要能对上。** 例如应收 200 元，储值余额收 120 元 + 现金收 80 元，系统会生成两张支付单。退款时也要按支付单分别处理，不能合成一笔退。

> ⚠️ **挂账金额不计入当日营收。** 挂了账的单子当天报表上不算收入，等顾客来销账、钱真正收到时才计入。不要拿「挂账金额」当营业额报给老板。

## 常见问题

**Q：收银台左栏里只有三种分组，我的单子去哪了？**
A：左栏只显示还需要收钱的单子，分成「未收」「待收尾款」「挂账」三组。已经结清、已退款、已取消的单子不在这里，要去「预约管理」里查。

**Q：为什么我已经收到钱了，左栏还显示这张单？**
A：看中间栏的「待收尾款」。如果它不是 0，说明只是收了定金，剩下的尾款还要收；收到 0 才会离开队列。

**Q：顾客说已经微信付款了，但系统还是「待支付」。**
A：线上扫码支付的状态由微信 / 支付宝通知系统，通常几秒内到。收银台弹窗每 3 秒会自动查一次；也可以到「支付流水」里找到这笔单，点「查单」主动向渠道确认。**在状态变成成功之前不要重复收款。**

**Q：现金多收了钱（顾客给了 300 元，应收 280 元）怎么记？**
A：现金行的「实收」填 300，「应收」填 280，系统会按 280 入账，差额是找零。只有现金允许实收大于应收。

**Q：能不能把「定金 + 尾款」合成一笔收？**
A：可以。收银台支持一次提交多笔（混合支付），也可以分两次收：先收定金、到店后再收尾款。系统都会分别生成支付单，方便退款时追溯。
