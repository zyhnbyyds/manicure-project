# 对账

## 这个模块解决什么问题

收款自动到账之后，还有一个问题必须回答：**系统和微信 / 支付宝，两边的账对得上吗？**

系统每天自动做一次「对账」：

1. 每天 **早上 6:30**，系统自动去微信、支付宝拉**前一天**的渠道账单；
2. 把渠道账单上的每一笔，和自己系统里的每一笔收款**逐笔比对**；
3. 对不上的，写成一条「差异」，等人处理。

比对是按**单号**做的（系统给渠道的商户订单号，和渠道给的交易号），所以只要两边都有这一笔，就能精确对上。

> 💡 大白话：对账就是「拿微信 / 支付宝的流水单，跟自己的账本一笔一笔划勾」。划不上的地方就是差异，必须有人去看一眼、写清楚原因。

> ⚠️ **系统不会自动改账。** 发现差异时，系统只写一条差异记录，**绝不自动修改金额或状态**。因为「哪边是对的」需要人判断，机器猜错就等于把钱记错。

## 谁来用（适用角色）

| 角色 | 能做什么 |
| --- | --- |
| 店长 | 看差异、触发补跑对账、标记处理、填写处理备注 |
| 前台 / 收银员 | 不需要用这个页面；遇到顾客问「这笔钱到底到没到」，交给店长查 |
| 技术对接人 | 通道未配置 / 账单拉不到时排查渠道侧问题 |

权限说明：**「支付对账」页面本身没有单独的页面权限点**，能不能看到取决于角色有没有被授予这个菜单；页面里的「触发对账」和「标记处理」按钮由权限点 **`biz:payment:reconcile`** 控制。

**建议**：对账菜单与 `biz:payment:reconcile` 只给店长。前台不需要处理差异。

## 操作路径

后台管理端 → 左侧菜单「美甲预约」→「支付对账」，或直接访问 `/biz/payment-diffs`

页面标题是「支付对账」，副标题是「渠道账单差异与人工处理」。

## 分步操作

### 一、每天例行看一遍（店长，约 5 分钟）

1. 打开「支付对账」页。
2. 筛选「状态」选**待处理**（默认能看到全部，建议每次都按待处理筛一次）。
3. 如果列表是空的 → 昨天的账**没有差异**，今天的对账就结束了。
4. 如果有差异 → **每一条都必须处理**，一条条点「标记处理」，选「已处理」或「忽略」，并**写清楚处理备注**（备注是必填的，写不清就等于没处理）。

### 二、看懂每条差异在说什么

列表里的每一行都是一处对不上的地方，看这几个字段就够：

| 列名 | 意思 |
| --- | --- |
| 对账日 | 这条差异属于哪一天的账单 |
| 渠道 | 微信 Native / 支付宝扫码 |
| 系统单号 | 我们系统给渠道的商户订单号 |
| 渠道单号 | 渠道那边的交易号 |
| 系统金额(元) | 我们系统记的金额（系统没这笔时为 0.00） |
| 渠道金额(元) | 渠道账单上的金额（渠道没这笔时为 0.00） |
| 差异类型 | 四类之一，见下表 |
| 状态 | 待处理 / 已处理 / 已忽略 |
| 处理人 / 处理时间 / 备注 | 谁在什么时候怎么处理的 |

### 三、四类差异分别意味着什么，怎么查

| 差异类型 | 通俗说法 | 典型原因 | 怎么查 | 怎么处理 |
| --- | --- | --- | --- | --- |
| **系统缺单** | 渠道收了钱，我们系统里没有这笔 | 回调丢了、门店网络问题导致通知没进来；或是别人拿同一个商户号收的钱（例如同时用了别的收银系统） | 复制「系统单号」，到「支付流水」里按预约号 / 时间搜同金额的记录；找不到就说明系统确实没有这笔 | 在备注里写清：已核实渠道到账、系统缺哪张单、由谁补记。**补记要在业务上做**（按正常收款把这张单收一次并注明「补记」），不能手工改数字 |
| **渠道缺单** | 我们系统记了成功，渠道账单里没有 | 最常见：**跨日**（这笔的支付时间落在别的对账日）；账单当天还没出全；渠道账单延迟；测试单 / 渠道侧撤销 | 到「支付流水」打开这笔单，看**支付时间**是不是属于这个对账日；再看渠道轨迹里有没有「渠道回调」还是只有「主动查单」 | 如果只是跨日 / 延迟，备注写「跨日，归入 X 月 X 日账单」；如果渠道侧确实没有这笔，联系技术对接人核对，**不要直接改状态** |
| **金额不一致** | 两边都有这笔，但金额不一样 | 顾客实际付的金额与系统应收不一致（少付 / 多付）；同一订单被合并或拆分；改价后重新收款 | 打开「支付流水」比对该笔的「应收(元)」「实收(元)」与这里的「渠道金额(元)」 | 差的钱按业务途径纠正：少收的补一笔收款，多收的发起一笔退款；备注写清差额与依据 |
| **状态不一致** | 我们记成「成功」，渠道账单说这笔是失败 / 已关闭 | 渠道侧撤单、退款后状态变化；本地关单后又收到钱（系统会救回成成功，但账单仍显示原状态） | 打开「支付流水」看渠道轨迹，特别注意有没有「迟到的支付成功」这类痕迹，以及有没有退款记录 | 结合退款单一起看：如果已经退过款，属于正常；否则联系技术对接人核对 |

> 💡 大白话：
> - 「系统缺单」= **钱进来了，账本没记**（危险，必须查清）；
> - 「渠道缺单」= **账本记了，渠道说没这回事**（多数是跨日或延迟，虚惊一场，但要写清）；
> - 「金额不一致」= 两边都认这笔，但**数不一样**（差额要按业务补）；
> - 「状态不一致」= 两边都认这笔，但**一个说成、一个说败**（多半和退款 / 撤单有关）。

### 四、标记处理（每一条差异都要做）

1. 在待处理的差异行上点「**标记处理**」。
2. 弹窗上半部分是这条差异的只读信息（对账日、渠道、系统单号、渠道单号、系统金额、渠道金额、差异类型），**先核对再动手**。
3. 选择「处理结果」：
   - **已处理**：已经查清并做了相应处理；
   - **忽略**：确认无需处理（例如跨日归入另一天、测试单）。
4. **填写「处理备注」**（必填）：占位提示是「请写清处理方式（补单 / 手工登记 / 联系渠道）」。
   - 不填会被拦下，提示「处理备注必填，不允许静默忽略」。
5. 点「保存」→ 提示「已标记处理」或「已忽略该差异」。

> ⚠️ **「忽略」不等于「删掉」。** 忽略也要写备注，并且处理人和处理时间都会留痕。这是刻意设计的——对账差异**不允许静默消失**。

### 五、手动补跑对账（需要时）

如果发现某一天的差异没生成、或想重新核一遍某一天：

1. 点右上角「**触发对账**」。
2. 弹窗里填：
   - **对账日**（必填）：要核哪一天的账单；
   - **渠道**（选填）：不选就是全部渠道。
3. 点「开始对账」→ 确认「将对指定日期重新拉取渠道账单并比对，**已存在的差异不会重复生成**」。
4. 完成后提示「对账完成，发现 X 条差异」。

**补跑是安全的**：同一天同一笔同一类型的差异只会有一条（重复跑不会刷出一堆重复行），而且**已经处理过的差异不会被新的一轮覆盖掉处理结果**。

> ⚠️ 如果补跑后仍然一条差异都没有，先别高兴：可能是**这条通道根本没配置**（此时对账任务会跳过它并记日志），也可能是**渠道当天的账单还没有生成**（账单为空时系统也会跳过，以免误报「系统缺单」）。

## 字段说明

| 字段 | 必填 | 说明 | 填错会怎样 |
| --- | --- | --- | --- |
| 对账日（筛选） | 否 | 只看某一天的差异 | 不影响数据，只是筛不出来 |
| 渠道（筛选） | 否 | 微信 Native / 支付宝扫码 | 同上 |
| 状态（筛选） | 否 | 待处理 / 已处理 / 已忽略 | 建议每次先筛「待处理」 |
| 对账日（触发对账） | 是 | 要重新比对的营业日 | 不填会提示「不能为空 / 请选择对账日」 |
| 渠道（触发对账） | 否 | 只补跑某一条通道；留空为全部 | 选错只会多比对一次，不会产生重复差异 |
| 处理结果 | 是 | 已处理 / 忽略 | 选「忽略」却没有真实理由，等于把问题埋起来 |
| 处理备注 | **是** | 写清处理方式（补单 / 手工登记 / 联系渠道） | 不填会被拦：「处理备注必填，不允许静默忽略」 |

## 使用注意事项

> ⚠️ **差异必须人工处理，不允许静默忽略。** 系统强制要求填写处理备注，就是为了让「为什么这笔对不上」永远有迹可查。**不要为了页面干净而随便点忽略。**

> ⚠️ **对账不会自动改账。** 差异只是「记下来」。金额或状态的修正必须走业务动作（补一笔收款、发起一笔退款），**不能手工去改流水**。系统里所有资金记录都是只追加、不修改、不删除的。

> ⚠️ **通道没配置时，对账会静默跳过。** 系统会记一条日志说「XX通道未配置，跳过 X 月 X 日对账」，并在对账结果里报 0 条差异。所以**「没有差异」既可能是真的没问题，也可能是根本没比**。不确定时先确认通道是否已开通（见 [支付通道接入](./channels-setup.md)）。

> ⚠️ **渠道账单为空时也会跳过。** 例如当天还没有交易、或渠道账单尚未生成。系统刻意的选择是「宁可不报，也不误报一堆系统缺单」——否则每天早上会看到几百条假差异，真差异就被淹没了。

> ⚠️ **时间以门店所在时区切分营业日。** 一笔在凌晨 0:30 收到的钱，属于「当天」还是「前一天」取决于门店时区设置。看到「渠道缺单」时，**第一件事就是核对支付时间是不是落在别的对账日**。

> ⚠️ **同一天同一笔的差异只会有一条，但内容会刷新。** 重复跑对账时，系统会更新差异里的金额和系统单号，**但不会动你已经写好的处理状态、处理人和备注**。所以处理过的差异不会被覆盖，可以放心补跑。

> ⚠️ **退款也会体现在渠道账单里。** 渠道账单里状态会显示为已退款 / REFUND 之类的标记，系统比对时会把它归到相应的差异类型。看到某笔的「状态不一致」时，先去「退款审批」查一下这张支付单有没有退过款。

> ⚠️ **不要在早上 6:30 前催对账结果。** 自动对账跑的是**前一天**的账单，6:30 才执行。想提前看，用「触发对账」手动补跑，但渠道账单可能还没生成。

## 常见问题

**Q：这个页面一直是空的，是不是说明我不用管对账？**
A：先确认两件事：① 有没有开通在线支付通道（没开通就没有渠道账单可比）；② 有没有按「待处理」筛过。两者都确认了还是空的，那说明账确实对得上。

**Q：出现「系统缺单」是不是说明钱丢了？**
A：恰恰相反——「系统缺单」意味着**渠道那边收到了钱，我们系统没记**。钱在渠道账户里，只是账本上缺一笔。请立刻查清并在备注里写明白，然后按业务途径把这张单的收款补记上，避免影响营收统计。

**Q：出现「渠道缺单」要不要紧？**
A：多数情况是跨日（支付时间属于别的对账日）或者渠道账单延迟，属于虚惊。但**必须写备注说明**，否则下次再看还是不知道这条是怎么了。

**Q：我可以直接把这个差异删掉吗？**
A：不能，也没有这个按钮。差异只能被标记为「已处理」或「忽略」，并且都要写备注。删除差异等于销毁对账证据。

**Q：同一条差异我处理完后，第二天又出现了。**
A：先去列表把状态改成「全部状态」看这条记录的处理备注；如果是新的一天新的一条（对账日不同），那是正常的——每一天的对账是独立的。同一天同一条不会重复生成。

**Q：手动触发对账会不会把已经处理好的记录变成待处理？**
A：不会。重复比对只会刷新差异里的金额和单号，处理状态、处理人和备注都保持原样。

**Q：顾客说钱付了，我在系统里查不到，对账里也没提示，怎么办？**
A：对账只覆盖前一天。当天的异常请到「支付流水」按金额、时间、渠道搜索，或让顾客提供微信 / 支付宝的付款记录（能看到商户单号），再由店长联系技术对接人核对渠道后台。**先不要重复收款。**
