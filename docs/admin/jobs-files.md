# 定时任务与文件管理

> 💡 **定时任务**是系统自己按点干活（自动完成预约、发提醒、对账…）；**文件管理**是后台所有上传过的图片和附件的仓库。

## 这个模块解决什么问题

- 让你知道「系统半夜到底干了什么」：每个任务都有执行日志，成功失败一目了然。
- 需要时能**手工补跑一次**：例如提醒短信没发出去，补跑一次当日提醒。
- 统一管理上传的图片与附件：找得到、看得到、能下载。

## 谁来用（适用角色）

| 页面     | 页面权限点                                                                     | 建议给谁                              |
| -------- | ------------------------------------------------------------------------------ | ------------------------------------- |
| 定时任务 | `system:job:list`；新建 `create`、编辑 `update`、删除 `delete`、手动执行 `run` | 只看给店长；新建/改 Cron 只给技术同事 |
| 文件管理 | `system:file:list`；删除 `delete`；上传按钮用的是 `system:file:upload`         | 店长 / 运营                           |

> ⚠️ 这两个页面（以及所有系统管理类页面）的按钮权限点**没有预置在菜单树里**，默认只有超级管理员点得动。需要给店长用，请参照 [菜单、部门、岗位、字典与参数](./menus-depts.md) 里的办法补按钮权限点。

## 操作路径

- 定时任务：后台管理端 → 左侧菜单「定时任务」，或 `/jobs`
- 文件管理：后台管理端 → 左侧菜单「文件管理」，或 `/files`

## 分步操作

### A. 看任务有没有正常跑

1. 进「定时任务」，列表里是系统内置的任务：

| 任务名称           | 频率（Cron 六个字段：秒 分 时 日 月 周） | 它做什么                                                                   |
| ------------------ | ---------------------------------------- | -------------------------------------------------------------------------- |
| 自动完成已到店预约 | `0 */10 * * * *`（每 10 分钟）           | 已到店且服务时间已过的预约自动置为「已完成」，同时累计顾客到店统计、计提成 |
| 自动标记爽约       | `0 */10 * * * *`（每 10 分钟）           | 已确认但超过「爽约判定容忍期」仍未到店的预约自动置为「爽约」               |
| 次卡到期处理       | `0 5 0 * * *`（每天 00:05）              | 把已过有效期的次卡置为「已过期」                                           |
| 会员等级重算       | `0 30 3 * * *`（每天 03:30）             | 按累计消费重算会员等级，修正历史/手工改级                                  |
| 在线支付超时关单   | `0 * * * * *`（每分钟）                  | 超时未支付的在线收款单自动关闭                                             |
| 在线支付主动查单   | `0 */2 * * * *`（每 2 分钟）             | 对未过期的在线支付单主动查询，回调丢失时兜底补记支付                       |
| 支付渠道对账       | `0 30 6 * * *`（每天 06:30）             | 拉取前一天的渠道账单逐笔比对，生成对账差异                                 |
| 应收逾期标记       | `0 10 1 * * *`（每天 01:10）             | 到期未还的应收单标记为「逾期」（当前版本不会因此自动给店员发通知）         |
| 预约到店提醒       | `0 0 18 * * *`（每天 18:00）             | 给次日有预约的顾客发提醒（同一单当天只发一次）                             |
| 通知失败重试       | `0 */5 * * * *`（每 5 分钟）             | 把发送失败的通知重试，单条最多 3 次                                        |
| 周期预约滚动生成   | `0 15 3 * * *`（每天 03:15）             | 按规则生成将来的周期预约单                                                 |

2. 每行都能看到「状态」（启用/禁用）和「允许并发」（是/否）。
3. 点某一行的**日志图标「执行日志」**，弹窗里是该任务最近 50 条执行记录：ID、状态、消息、开始时间、结束时间、耗时(ms)。
   - 状态不是「成功」时，「消息」列会写明失败原因。
4. 想清空所有执行日志，点右上角「清空日志」→ 二次确认 →「清空」。

### B. 手工执行一次任务

1. 在任务列表里点那一行的三角图标「手动执行」。
2. 二次确认「确定立即执行任务『XXX』吗？」，点「执行」。
3. 页面提示「已触发执行」——**注意这只是「已经开始跑」，不代表跑成功了**。
4. 立刻点「执行日志」看最新一条的结果。这三点很重要，见注意事项。

### C. 新增 / 修改任务（一般交给技术同事）

1. 点右上角「新增任务」。
2. 填：

| 字段     | 说明                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------ |
| 任务名称 | 中文名，给人看的                                                                                                   |
| 处理器   | **必须是系统已经内置的动作名**（例如 `retryFailedNotices`）。填一个不存在的名字，保存会报「未知的任务处理器：xxx」 |
| Cron     | 六段式：`秒 分 时 日 月 周`                                                                                        |
| 状态     | 启用 / 禁用                                                                                                        |
| 允许并发 | 关（默认）：上一次没跑完就不再启动新的，防重入；开：允许同时跑多个                                                 |
| 备注     | 写清这个任务干什么                                                                                                 |

3. 点「保存」。系统会**立刻按新配置重新注册调度**，不需要重启服务。
4. 想临时停掉某个任务：编辑它，把「状态」关掉保存。

### D. 上传和查看文件

1. 进「文件管理」，点右上角「上传文件」，选一个文件（**单个文件最大 5MB**）。
2. 上传成功提示「上传成功」，列表刷新。
3. 列表里能看到：ID、文件名、类型（例如 `image/png`）、大小、上传时间。
4. 图片文件左侧会多一个眼睛图标「预览」，点开是图片查看器（可以左右切换、缩放、拖拽）。
5. 点「下载」图标把文件存到本地。
6. 点红色垃圾桶「删除」，二次确认后删除。

## 字段说明

### 定时任务

| 字段     | 必填 | 说明                                         | 填错会怎样                                   |
| -------- | ---- | -------------------------------------------- | -------------------------------------------- |
| 任务名称 | 是   | 中文名                                       | —                                            |
| 处理器   | 是   | 系统内置的动作名，必须是下面这张白名单里的值 | 填错保存报「未知的任务处理器」，任务存不进库 |
| Cron     | 是   | 六段式表达式（秒 分 时 日 月 周）            | 语法不对会提示「Cron 表达式无效」            |
| 状态     | 是   | 启用 / 禁用                                  | 禁用即停跑，日志仍在                         |
| 允许并发 | 是   | 是否允许多个实例同时跑                       | 打开后，任务跑得慢又频繁触发会互相打架       |
| 备注     | 否   | 说明                                         | —                                            |

**可用的处理器白名单**（除前两个外，其余都有内置任务）：

| 处理器                        | 干什么                                     |
| ----------------------------- | ------------------------------------------ |
| `autoCompleteExpiredBookings` | 自动完成已到店预约                         |
| `autoNoShowBookings`          | 自动标记爽约                               |
| `expireMemberCards`           | 次卡到期处理                               |
| `recountMemberLevels`         | 会员等级重算                               |
| `closeExpiredPayments`        | 在线支付超时关单                           |
| `queryPendingPayments`        | 在线支付主动查单                           |
| `reconcilePayments`           | 支付渠道对账                               |
| `markOverdueReceivables`      | 应收逾期标记                               |
| `sendBookingReminders`        | 预约到店提醒                               |
| `retryFailedNotices`          | 通知失败重试                               |
| `generateRecurringBookings`   | 周期预约滚动生成                           |
| `cleanExpiredRefreshTokens`   | 清理过期的登录凭证（进阶，默认没有建任务） |
| `noop`                        | 空动作，只用于测试（进阶）                 |

### 执行日志

| 列                  | 说明                                                       |
| ------------------- | ---------------------------------------------------------- |
| ID                  | 日志编号                                                   |
| 状态                | 成功 / 失败（失败会在「消息」里写原因）                    |
| 消息                | 失败原因或摘要                                             |
| 开始时间 / 结束时间 | 本次执行的时间窗                                           |
| 耗时(ms)            | 跑了多少毫秒；突然从几百变成几万，说明数据量涨了或出了问题 |

### 文件管理

| 字段 / 列 | 说明                               | 限制                                 |
| --------- | ---------------------------------- | ------------------------------------ |
| 文件名    | 上传时的原始文件名（中文正常显示） | 最长 255 字符，特殊符号会被替换      |
| 类型      | 文件的内容类型，例如 `image/jpeg`  | 按**扩展名**校验，不在白名单直接拒绝 |
| 大小      | 文件体积                           | **单个文件最大 5MB**                 |
| 上传时间  | 上传成功的时间                     | —                                    |
| 预览      | 图片才有的按钮                     | 非图片不显示                         |
| 下载      | 把文件下载到本地                   | 下载链接是公开的，不需要登录         |
| 删除      | 删除记录 + 删除服务器上的文件      | **不可恢复**                         |

**允许上传的扩展名**：
`.jpg` `.jpeg` `.png` `.gif` `.webp` `.svg` `.pdf` `.doc` `.docx` `.xls` `.xlsx` `.ppt` `.pptx` `.txt` `.md` `.csv` `.json` `.zip` `.mp3` `.mp4`

> 💡 手机上常见的 `.heic` / `.avif` 照片**不在白名单里**，上传会被拒绝，请先转成 JPEG。

> 💡 **图片会自动变小，这是正常的。** 超过 1MB 的 jpg / png / webp 图片在上传时会被系统压到 1MB 以下
> （列表里的「大小」就是压缩后的大小）。动图（gif）和矢量图（svg）不会被压。
> 只有确实需要保留原图时才让技术同事用 `?compress=0` 传（默认都压）。

## 使用注意事项

> ⚠️ **手工执行后提示「已触发执行」不等于跑成功。**
> 触发条件：点了「手动执行」看到绿色提示就以为好了。
> 后果：任务内部失败时，前端仍会显示「已触发执行」，只有执行日志里才有「失败」和原因。
> 正确做法：每次手工执行后，都点开「执行日志」确认最新一条是「成功」。

> ⚠️ **新建任务时「处理器」不能随便填。**
> 触发条件：自己编一个名字，例如 `syncData`（页面输入框的提示语给的就是这个例子）。
> 后果：保存被拒，提示「未知的任务处理器：syncData」。
> 正确做法：只能从上面的白名单里选（多数情况你根本不需要新建任务，用内置的 11 个就够）。

> ⚠️ **Cron 是六段式，别按五段式写。**
> 触发条件：看了页面提示里的 `0 0 * * *` 就照着填五段。
> 后果：表达式含义与预期不符（多一段/少一段会让任务在完全不同的时间跑），或直接被判无效。
> 正确做法：按「秒 分 时 日 月 周」六段写。例如要每天 18:00 跑，就填 `0 0 18 * * *`。

> ⚠️ **任务跑得比触发间隔慢时，会被自动跳过（不是排队）。**
> 触发条件：「允许并发」= 否（默认），且上一次执行还没结束。
> 后果：这一次触发被静默跳过，执行日志里**不会有**记录，容易误以为「任务没跑」。
> 正确做法：看日志时关注「上一次的耗时」是否接近触发间隔；数据量变大时应把它们改成更稀疏的频率。

> ⚠️ **不要为了「快点看到效果」把时间类任务改成每分钟一次。**
> 触发条件：把「预约到店提醒」改成每分钟跑。
> 后果：虽然有「同一张单当天只提醒一次」的保护，但会增加短信费用与系统压力。
> 正确做法：保持内置频率；需要立刻生效就用手工执行一次。

> ⚠️ **定时任务不碰钱，这是硬规则。**
> 触发条件：期望某个任务帮你「自动改余额 / 自动发提成」。
> 后果：找不到这样的任务（这是刻意设计：改钱必须有人操作、有日志）。
> 正确做法：钱的事走收银台、退款审批、提成结算页面。

> ⚠️ **删除文件是不可恢复的，而且业务图片也在这个列表里。**
> 触发条件：在「文件管理」里清掉一批「看起来没用」的图片。
> 后果：评价里的顾客图片、员工头像等都会变成打不开的空白。
> 正确做法：删除前先确认这张图没被业务引用；不确定就保留。

> ⚠️ **文件下载链接是公开的。**
> 触发条件：把下载链接发给外部的人。
> 后果：任何拿到链接的人都能下载这个文件（链接里是随机文件名，别人猜不到，但链接本身可转发）。
> 正确做法：涉密文件（身份证、合同扫描件）不要上传到这里。

> ⚠️ **5MB 是硬上限。**
> 触发条件：上传手机原图或视频。
> 后果：上传失败，提示文件过大。
> 正确做法：图片会自动压到 1MB 以下，但**源头不能超过 5MB**（超了会在收到前就被拒）；视频类素材建议放外部存储而不是这里。

## 常见问题

**Q：任务显示启用，但今天一条日志都没有？**
A：先看「Cron」是不是六段式、时间点是否符合你的预期；再看「允许并发」为否时，上一次是否还在跑（被跳过时不留日志）。如果一整天都没有任何记录，请让技术同事检查服务是否一直在运行。

**Q：手工执行了两次，会不会重复处理？**
A：内置任务都设计成可重复执行（幂等），重复跑不会重复算钱、不会重复发通知。「预约到店提醒」还额外做了「同一张单当天只发一次」的保护。

**Q：可以让任务立刻给所有明天的顾客发提醒吗？**
A：点「预约到店提醒」的手动执行即可，它会挑「次日且已确认」的预约发；已经发过的会跳过。

**Q：允许并发开着好还是关着好？**
A：**关着好（默认）**。开着可能导致同一批数据被两个实例同时处理，虽然任务本身做了幂等保护，但没有必要冒这个风险。

**Q：为什么「清空日志」之后任务历史全没了？**
A：清空是全清且不可恢复（包含所有任务的执行日志）。清空前建议先截图留档。

**Q：上传的图片为什么在业务页面能显示，在文件管理里却找不到？**
A：正常情况下都会出现在文件管理里（同一个仓库）。找不到时请先刷新列表，并按文件名搜一下；业务页面上的图片可能是通过其他方式引用的外链。

**Q：下载文件时浏览器直接打开了图片 / PDF 而不是下载？**
A：图片和 PDF 这类能被浏览器直接打开的文件会内嵌预览；要保存到本地，请在预览页里用浏览器的「另存为」，或右键链接选择「链接另存为」。

**Q：删除文件后，业务页面上的图会怎样？**
A：会显示成打不开的占位图或空白。请务必先确认没有业务在用。
