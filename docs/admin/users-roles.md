# 用户与角色

> 💡 **用户**是「谁能登录后台」；**角色**是「登录后能看哪些菜单、能点哪些按钮、能看哪些门店/部门的数据」。给员工开账号 = 建用户 + 挂一个角色。

## 这个模块解决什么问题

- 给新来的员工开后台账号，走人的时候停用账号。
- 用「角色」批量管理权限，而不是给每个人单独勾一遍。
- 控制**数据可见范围**：连锁店可以做到「A 店的人只看得到 A 店的数据」。
- 员工忘密码时帮他重置。

## 谁来用（适用角色）

| 功能                                 | 需要什么权限                               | 说明                                         |
| ------------------------------------ | ------------------------------------------ | -------------------------------------------- |
| 看用户列表                           | `system:user:list`                         | 对应菜单「系统管理 → 用户管理」              |
| 新增 / 编辑 / 删除用户、重置密码     | `system:user:create` / `update` / `delete` | **默认只有超级管理员能用**（原因见注意事项） |
| 看角色列表                           | `system:role:list`                         | 菜单「系统管理 → 角色管理」                  |
| 新增 / 编辑 / 删除角色、分配菜单权限 | `system:role:create` / `update` / `delete` | 同上                                         |

> 💡 名字叫「超级管理员」的角色（角色标识 `admin`，系统内置）拥有全部权限，且它的权限**不来自菜单勾选**，不能被改动。日常运营账号请另建普通角色。

## 操作路径

- 用户：后台管理端 → 左侧菜单「系统管理」→「用户管理」，或 `/system/users`
- 角色：后台管理端 → 左侧菜单「系统管理」→「角色管理」，或 `/system/roles`

## 分步操作

### A. 新建员工账号

1. 进「用户管理」，点右上角「新增用户」。
2. 填写弹窗字段：

| 字段          | 怎么填                                                                 |
| ------------- | ---------------------------------------------------------------------- |
| 用户名        | 登录用的名字，3~64 个字符，建议用拼音，例如 `xiaomei`                  |
| 显示名称      | 中文名，例如「小美」，会显示在操作日志里                               |
| 部门          | 选门店/部门（下拉里带层级，形如「总部 / 门店A」）                      |
| 密码          | **新增时必填，最少 12 位**。建议给一个临时密码，让员工首次登录后自己改 |
| 邮箱 / 手机号 | 选填                                                                   |
| 状态          | 保持开启（关闭 = 不允许登录）                                          |
| 角色          | 多选，勾上这个员工该有的角色（例如「店长」「美甲师」）                 |

3. 点「创建」。提示「创建成功」。
4. 检查列表里这一行：用户名、部门、角色、状态是否正确。
5. 把用户名和临时密码告诉员工，让他登录后到「个人中心」自己改密码。

### B. 给员工换角色 / 换部门

1. 在列表里点那一行的铅笔图标「编辑」。
2. 改「部门」「角色」「状态」等，点「保存」。提示「更新成功」。
3. 让员工重新登录一次，新权限才会生效（见注意事项）。
   - ⚠️ 编辑弹窗里**用户名改不了**（用户名是账号的身份证，不允许修改）。

### C. 重置密码（员工忘了密码）

1. 「用户管理」里点那一行的「编辑」。
2. 在「密码」框里填新密码，**最少 12 位**（提示语写着「新增必填；编辑选填，不填则不修改」——也就是说**留空就不会改密码**）。
3. 点「保存」。
4. 把新密码告诉员工；如果他当前还登录着，建议顺手去「在线用户」把他踢下线。

### D. 停用 / 删除账号

- **员工离职推荐「停用」**：编辑该用户 → 把「状态」关掉 → 保存。停用后无法登录，但历史操作记录、提成记录都还挂在他名下，报表可追溯。
- **删除**：点红色垃圾桶图标 → 二次确认「确定删除用户『XXX』吗？此操作不可恢复」。删除一般只在建错账号时用。
  - ⚠️ 停用后他再登录会提示「**用户名或密码错误**」，这是故意不区分原因的提示，不是密码错了。

### E. 新建一个角色

1. 进「角色管理」，点「新增角色」。
2. 填「角色名称」（中文，例如「店长」）和「角色标识」（英文/数字，例如 `shop_manager`，小写字母/数字/`:-_`）。
3. 填「排序」（数字越小越靠前）。
4. 选「数据范围」（见下方字段说明）。如果选「自定义数据权限」，会多出「授权部门」树，勾选这个角色能看到的部门。
5. 「备注」写清这个角色是给谁用的。
6. 点「创建」。

### F. 给角色分配菜单权限（决定他能看到哪些页面和按钮）

1. 在「角色管理」列表里点那一行的钥匙图标「分配菜单权限」。
2. 弹窗标题形如「分配菜单权限 - 店长」，里面是一棵菜单树（目录 / 菜单 / 按钮三层）。
3. **勾选**这个角色能看到的菜单。勾一个父菜单时，它下面的按钮会一起被勾上（这就是「按钮权限随其父菜单自动关联」的意思）。
4. 点「保存」，提示「权限已更新」。
5. 让该角色的员工重新登录一次验证效果。

> ⚠️ 保存是**覆盖式**的：这次没勾上的菜单会被**取消授权**。改权限时请从当前已勾选的清单上增删，不要一股脑全清空重勾。

### G. 删除角色

1. 在「角色管理」列表里点红色垃圾桶图标。
2. 二次确认后删除。

> ⚠️ 删除角色会把这个角色身上的**菜单授权和员工绑定一起解绑**。只在确认没人用这个角色时才删。

## 字段说明

### 用户表单

| 字段     | 必填                | 说明                                | 填错会怎样                                                             |
| -------- | ------------------- | ----------------------------------- | ---------------------------------------------------------------------- |
| 用户名   | 是                  | 登录名，3~64 字符                   | 与已有账号重名会被拒绝；**建好后不能改**                               |
| 显示名称 | 是                  | 中文名                              | 留空无法保存；名字太随意会让操作日志看不懂是谁                         |
| 部门     | 否                  | 所属门店/部门                       | 不选 → 数据范围类角色（本部门/自定义）算不出可见范围，可能什么都看不到 |
| 密码     | 新增必填 / 编辑选填 | 新增最少 12 位；编辑留空 = 不改密码 | 少于 12 位会提示「密码最少 12 位」                                     |
| 邮箱     | 否                  | 选填                                | —                                                                      |
| 手机号   | 否                  | 选填                                | —                                                                      |
| 状态     | 是                  | 启用 / 禁用                         | 关闭后无法登录，登录提示「用户名或密码错误」                           |
| 角色     | 否                  | 可多选                              | 一个都不选 → 登录后看不到任何菜单（只能看首页和个人中心）              |

### 角色表单

| 字段     | 必填                       | 说明                          | 填错会怎样                                                               |
| -------- | -------------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| 角色名称 | 是                         | 中文名，例如「店长」          | —                                                                        |
| 角色标识 | 是                         | 英文标识，小写字母/数字/`:-_` | 重复会提示「角色标识已存在」；标识写错不影响功能，但难以辨认             |
| 排序     | 否                         | 数字越小越靠前                | —                                                                        |
| 数据范围 | 是                         | 见下方「数据范围五种取值」    | 选「仅本人」→ 员工只能看自己创建的预约；选「全部」→ 能看到所有门店的数据 |
| 授权部门 | 仅「自定义数据权限」时需要 | 勾选可见部门                  | 一个都不勾 → 该角色看不到任何数据（系统按「一条都看不到」处理）          |
| 备注     | 否                         | 说明用途                      | —                                                                        |

### 数据范围五种取值

| 显示名称             | 含义                               | 举例              |
| -------------------- | ---------------------------------- | ----------------- |
| 全部数据权限         | 全部门店/部门的数据都能看          | 老板、总部运营    |
| 自定义数据权限       | 只能看「授权部门」里勾选的那些部门 | 区域经理管 2 家店 |
| 本部门数据权限       | 只看自己所属部门                   | 单店店长          |
| 本部门及以下数据权限 | 自己部门 + 所有下级部门            | 大区经理          |
| 仅本人数据权限       | 只看自己创建的数据                 | 兼职前台          |

**多角色怎么算**：一个人挂多个角色时取**并集**（谁宽按谁）。只要有一个角色是「全部数据权限」，这个人就能看全部。

### 数据范围目前实际生效的地方

| 页面                                    | 是否受数据范围影响                                                          |
| --------------------------------------- | --------------------------------------------------------------------------- |
| 用户管理                                | ✅ 受                                                                       |
| 部门管理                                | ✅ 受                                                                       |
| 登录日志                                | ✅ 受                                                                       |
| 操作日志                                | ✅ 受                                                                       |
| 预约管理                                | ✅ 受（且美甲师身份的人默认只能看自己的预约，除非另有「查看全部预约」权限） |
| 收银台 / 支付流水 / 会员 / 报表等业务页 | ❌ **不受数据范围限制** —— 这些页面按「可见门店」隔离，见下一段             |

> 💡 两条边界要说清：
> **① 数据范围是「后台基座」层面的可见性控制**（用户、部门、日志这几张表）。
> **② 业务数据按门店隔离，用的是另一套机制**：系统管理 →「用户管理」→ 该账号的「**设置可见门店**」。
> 预约、收款、退款、应收、报表、排班、首页都按「可见门店」过滤，保存后立即生效。
> 想实现「A 店的人只看 A 店数据」，请配**可见门店**，不要配数据范围 —— 细节见 [门店与连锁](./stores.md)。

## 使用注意事项

> ⚠️ **新建的普通角色点不到「新增用户」这类按钮，除非手工补权限点。**
> 触发条件：给店长勾了「用户管理」菜单，他看到列表却看不到「新增用户」按钮。
> 后果：菜单能进，但增删改都点不了，只能用来看。
> 正确做法：系统内置的「系统管理」类按钮权限点（例如 `system:user:create`）**没有预置在菜单树里**，所以角色授权弹窗里勾不到。要用它有两种办法：① 由超级管理员操作；② 请技术同事（或有「菜单管理」权限的人）在「菜单管理」里给「用户管理」**新增一条类型为「按钮」的子节点**，权限标识填 `system:user:create`，再回「角色管理」勾选它。

> ⚠️ **改了角色权限，员工那边不会立刻生效。**
> 触发条件：刚勾完菜单就催员工去看。
> 后果：他的登录凭证里还带着旧的权限清单，最长 15 分钟内一直看不到新菜单。
> 正确做法：让员工退出重新登录一次即可立即生效。

> ⚠️ **删角色会连带解绑员工。**
> 触发条件：删除一个还在用的角色。
> 后果：该角色下的员工失去对应菜单（如果这是他唯一的角色，登录后将看不到任何业务菜单），需要重新分配角色。
> 正确做法：不用的角色先改名加「（停用）」并取消全部菜单勾选，观察一周没人反馈再删。

> ⚠️ **「编辑用户」时密码留空不是「设成空密码」，而是「不修改」。**
> 触发条件：以为留空就是把密码清掉。
> 后果：员工仍然用旧密码登录，会以为你忘了帮他重置。
> 正确做法：重置密码必须**显式填入新密码**（最少 12 位）再保存。

> ⚠️ **停用账号不会立刻踢掉他正在用的会话。**
> 触发条件：员工离职当天只停用了账号。
> 后果：他这台电脑上如果还登录着，仍然可以操作到登录凭证过期为止。
> 正确做法：停用账号后，立刻去「系统监控 → 在线用户」把他强制下线。

> ⚠️ **一个人挂多个角色时权限会取并集，越挂越宽。**
> 触发条件：图省事给员工同时挂了「前台」和「店长」。
> 后果：他会拥有两个角色的所有权限（含退款审批、提成结算这类敏感操作）。
> 正确做法：按最小必要原则只挂一个角色；需要临时顶班，事后记得改回来。

> ⚠️ **不要让员工知道超级管理员账号的密码。**
> 触发条件：为了省事把 admin 账号借给员工用。
> 后果：所有操作日志都记成 admin，出问题无法追责；超级管理员拥有全部权限（含删用户、改参数、发提成）。
> 正确做法：一人一号，各挂各的角色。

## 常见问题

**Q：给员工开了账号，他说登录提示「用户名或密码错误」，但密码是我亲手设的。**
A：先确认「状态」是不是被关掉了——停用的账号登录时也提示「用户名或密码错误」（系统故意不区分原因）。打开状态再让他试。

**Q：员工登录后左边菜单是空的，只有首页。**
A：他挂的角色没有被分配任何菜单，或者他一个角色都没有。请在「角色管理」里给对应角色勾选菜单；如果这个账号的角色列表是空的，请在「用户管理」里给他挂角色。

**Q：为什么我改了角色权限，员工还是老样子？**
A：权限在他登录时被写进了登录凭证，需要他重新登录（或等最多 15 分钟）。

**Q：一个角色能同时管「能看哪些页面」和「能看哪些门店的数据」吗？**
A：能。菜单勾选管「页面和按钮」，数据范围管「数据行」。两者配合使用。

**Q：为什么「数据范围」选了「本部门数据权限」，员工还是什么都看不到？**
A：多半是这个用户自己没设「部门」。请到「用户管理」给他选一个部门。

**Q：美甲师想看自己的预约，要给他开什么？**
A：给美甲师账号挂一个带「预约管理」菜单的角色即可，但**不要**给他「查看全部预约」这个按钮权限——系统检测到账号绑定了美甲师档案时，会自动只让他看自己的预约。

**Q：能不能给某个角色单独开「退款审批」的权限？**
A：可以。「退款审批」页面下挂着一个「审批」按钮权限点，在角色授权弹窗里展开该页面就能勾到（业务页面下的按钮权限点是预置好的，与系统管理类页面不同）。

**Q：删掉的用户还能查到他以前的操作记录吗？**
A：能。「操作日志」存的是操作人 ID 和用户名快照，删除用户不会连带删日志。

**Q：员工换门店了，怎么改？**
A：「用户管理」里编辑该用户，改「部门」即可（前提是他的角色数据范围是「本部门」或「本部门及以下」）。同时建议顺带检查他看到的预约是否需要交接。
