# 系统监控（日志 / 在线用户 / 缓存）

> 💡 系统监控是后台的「行车记录仪」：谁在什么时候登录过、谁改了哪条数据、现在有谁在线、缓存正不正常。它不能改业务数据，只负责留痕和踢人。

## 这个模块解决什么问题

- **出了问题能追责**：某笔会员余额被改了，是谁改的、什么时候改的、改成了多少。
- **发现异常登录**：半夜有人在陌生 IP 上试密码（登录日志里的失败记录）。
- **现场处置**：员工手机丢了、离职了，立即把他踢下线。
- **确认系统状态**：缓存连不上时很多功能会悄悄降级，缓存监控一眼就能看出来。

## 谁来用（适用角色）

| 页面     | 页面权限点                                                       | 建议给谁                                    |
| -------- | ---------------------------------------------------------------- | ------------------------------------------- |
| 登录日志 | `monitor:loginlog:list`，删除/清空需要 `monitor:loginlog:delete` | 店长 / 技术同事                             |
| 操作日志 | `monitor:operlog:list`，删除/清空需要 `monitor:operlog:delete`   | 店长 / 老板（涉及追责，建议只给老板和店长） |
| 在线用户 | `monitor:online:list`，强制下线需要 `monitor:online:delete`      | 店长 / 技术同事                             |
| 缓存监控 | `monitor:cache:list`                                             | 技术同事（门店人员只需知道红色代表异常）    |

## 操作路径

后台管理端 → 左侧菜单「系统监控」：

- 登录日志 `/monitor/login-logs`
- 操作日志 `/monitor/operation-logs`
- 在线用户 `/monitor/online`
- 缓存监控 `/monitor/cache`

## 分步操作

### A. 查登录记录

1. 进「登录日志」。
2. 按「用户名」或「状态」（成功 / 失败）筛选，点「查询」。
3. 看列表：

| 列         | 说明                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| 用户名     | 尝试登录的账号                                                                |
| IP         | 来源网络地址                                                                  |
| User-Agent | 浏览器/设备标识（很长，鼠标悬停或拖宽列查看）                                 |
| 状态       | 成功（绿）/ 失败（红）                                                        |
| 消息       | 成功时显示 `success` 之类，失败时显示原因（**统一显示「用户名或密码错误」**） |
| 时间       | 登录尝试发生的时间                                                            |

4. 单条记录要点右侧垃圾桶删除；要清空全部，点右上角「清空日志」并在二次确认里点「清空」。

### B. 查「谁改了什么」（操作审计）

1. 进「操作日志」。
2. 按「状态」（成功/失败）和「操作人」筛选，点「查询」。
3. 看列表：

| 列       | 说明                                                                       |
| -------- | -------------------------------------------------------------------------- |
| 操作人   | 是谁做的（显示用户名；取不到时显示「用户#编号」）                          |
| 模块     | 大致是哪一块（由系统内部名称转换而来，例如 `Users`）                       |
| 操作     | 中文动作 + 动作名，例如「新增 · create」「修改 · update」「删除 · delete」 |
| 方法     | 请求方式（GET 查询 / POST 新增 / PATCH、PUT 修改 / DELETE 删除）           |
| 路径     | 具体的接口地址                                                             |
| 状态     | 成功（绿）/ 失败（红）                                                     |
| 耗时(ms) | 这次操作花了多少毫秒，数字特别大说明那一步很慢                             |
| IP       | 操作来源                                                                   |
| 时间     | 发生时间                                                                   |

4. 点左侧眼睛图标「详情」，可以看到：
   - 基本信息（操作人及其编号、模块、操作、方法、路径、状态、耗时、IP、时间）
   - **请求参数**：他提交了什么（改价、改余额的关键证据）
   - **返回参数**：系统返回了什么
   - **错误信息**：失败时才有，写清失败原因
5. 单条删除 / 清空全部的操作与登录日志相同。

### C. 把某人踢下线

1. 进「在线用户」。列表里是当前处于登录状态的账号：用户ID、用户名、登录IP、User-Agent、登录时间。
2. 找到要处理的那一行，点右侧的「下线」。
3. 二次确认「确定将用户『XXX』强制下线吗？」，点「下线」。
4. 提示「已强制下线」。

**什么时候用**：员工离职、手机/电脑丢失、怀疑账号被盗用、改完密码想立即断开其它设备。

### D. 看缓存状态

1. 进「缓存监控」。
2. 三个卡片：

| 卡片       | 正常表现       | 异常表现与影响                                             |
| ---------- | -------------- | ---------------------------------------------------------- |
| Redis 启用 | 显示「已启用」 | 显示「未启用」→ 在线用户列表永远是空的，缓存类功能全部降级 |
| 连接状态   | 显示「正常」   | 显示「异常」→ 同上，请让技术同事检查缓存服务               |
| 键数量     | 一个数字       | 显示 `-` → 说明没启用或连不上                              |

3. 这个页面**只读，没有清理缓存的按钮**。缓存过期由系统自动处理。

## 字段说明

| 字段 / 列   | 在哪                         | 说明                   | 备注                                             |
| ----------- | ---------------------------- | ---------------------- | ------------------------------------------------ |
| 用户名      | 登录日志、在线用户           | 账号名                 | 登录失败的记录也会出现在这里                     |
| IP          | 登录日志、操作日志、在线用户 | 来源地址               | 同一局域网内多台电脑可能是同一个地址             |
| User-Agent  | 登录日志、在线用户           | 浏览器/设备指纹        | 用来区分「是店里的电脑还是外面的手机」           |
| 状态        | 登录日志                     | 成功 / 失败            | 失败统一提示「用户名或密码错误」                 |
| 消息        | 登录日志                     | 失败原因摘要           | 不区分「账号不存在」和「密码错误」，这是有意设计 |
| 操作人      | 操作日志                     | 谁改的                 | 显示禁用的账号也会保留历史记录                   |
| 模块 / 操作 | 操作日志                     | 改的是哪一块、什么动作 | 中文动作用来快速扫读                             |
| 请求参数    | 操作日志详情                 | 提交内容               | 追查「改成了多少」的关键                         |
| 错误信息    | 操作日志详情                 | 失败原因               | 配合「状态=失败」筛选用                          |
| 重试 / 清空 | 登录日志、操作日志           | 删除单条 / 清空全部    | 清空不可恢复                                     |

## 使用注意事项

> ⚠️ **清空日志是不可恢复的，别随手点。**
> 触发条件：为了「让列表干净一点」点「清空日志」。
> 后果：所有历史登录/操作记录一次性删除，出了问题再也查不到是谁干的。
> 正确做法：只删明确的无效记录；建议每月底由老板确认后再清理一次，不要频繁清空。

> ⚠️ **强制下线不是「立刻踢出」，最长可能还有 15 分钟的空窗。**
> 触发条件：员工手机丢了，你点了「下线」就以为安全了。
> 后果：被踢的人当前已经拿到的登录凭证仍然有效，直到它自己到期（默认 15 分钟）；系统做的是让他**无法继续续期**。
> 正确做法：处置被盗/丢失账号时，**同时做两件事**：① 在「用户管理」里改密码或停用账号；② 在「在线用户」强制下线。改密码后也请照此办理。

> ⚠️ **Redis 没启用时，「在线用户」功能等于失效。**
> 触发条件：服务器没有配置缓存服务。
> 后果：在线用户列表永远为空；点不了「下线」（列表里没有行）；缓存监控显示「未启用」。业务本身仍可运行，属于降级而非故障。
> 正确做法：需要「在线用户 + 强制下线」能力，请让技术同事配置缓存服务；不配置时用「改密码 + 停用账号」替代。

> ⚠️ **同一个账号多人共用，日志就失去意义。**
> 触发条件：几个人共用一个用户名。
> 后果：操作日志里全是同一个「操作人」，追责时查不出具体是谁。
> 正确做法：一人一号。这条同时也是 [用户与角色](./users-roles.md) 里的硬要求。

> ⚠️ **日志「成功」不代表业务一定对。**
> 触发条件：看到操作日志里「修改成功」就当作数据没问题。
> 后果：操作成功 ≠ 填的值正确（例如把余额改成了 1 元也确实成功了）。
> 正确做法：追查金额类改动时，一定要点开详情看**请求参数**里改成了多少。

> ⚠️ **日志也会受「数据范围」影响。**
> 触发条件：给某个角色选了「本部门数据权限」。
> 后果：该角色的员工只能看到本部门的日志，看不到全店的操作记录（这是有意设计，避免越权窥探）。
> 正确做法：需要看全店日志的角色，请把数据范围设为「全部数据权限」。

> ⚠️ **登录日志里的失败记录不一定是被攻击。**
> 触发条件：员工记错密码连试几次。
> 后果：列表里出现一批红色「失败」，看起来像异常。
> 正确做法：先看 IP 和 User-Agent 是不是店里的设备；只有陌生 IP 的连续失败才需要警惕（那说明账号密码可能被试探，建议改密码并缩小账号权限）。

## 常见问题

**Q：怎么查「是谁把这位会员的余额改少了」？**
A：进「操作日志」，筛「状态=成功」，按时间范围找到对应时刻的记录，点详情看「请求参数」里的前后值。若记录太多，先用操作人筛选（怀疑对象），再逐条看。

**Q：为什么登录日志里失败原因只写「用户名或密码错误」？**
A：这是系统的安全设计——不告诉尝试者「账号是否存在」，避免被人拿来做账号枚举。

**Q：员工离职了，我要做哪几步？**
A：① 「用户管理」里把账号「状态」关掉（停用）；② 「在线用户」里把他强制下线；③ 如果他有角色，考虑把角色里的敏感权限（退款审批、提成结算）收回。详见 [用户与角色](./users-roles.md)。

**Q：在线用户里只看到 1 个人，但店里明明有 3 台电脑登录着？**
A：在线状态按账号记录，而且系统以缓存服务为存储。先看「缓存监控」是否显示启用/正常；如果未启用，这个列表就是空的或不全。

**Q：可以看某个按钮点了几次这类统计吗？**
A：不能。日志记录的是「接口调用」，不是「按钮点击」，两者大致对应但不完全等同。

**Q：操作日志能保存多久？**
A：系统不自动删除，会一直保留，直到有人手工删除或清空。请按门店合规要求定期归档。

**Q：为什么操作日志里的「模块」显示英文（例如 `Users`）？**
A：它是从系统内部名称自动转换来的，仅用于快速分类，不影响使用。

**Q：缓存监控里显示「异常」要处理吗？**
A：要。缓存异常会导致在线用户、部分统计能力降级（业务不会中断）。请把这三个卡片的截图发给技术同事排查。

**Q：清空日志后登录日志里的失败记录也一起没了吗？**
A：是的，清空是全清。清空前建议先导出或截图留档。
