# 菜单、部门、岗位、字典与参数

> 💡 这五个页面（菜单、部门、岗位、字典、参数）是后台的「地基」：它们不直接产生业务数据，但决定了左侧导航长什么样、员工能看哪些数据、系统的默认行为是什么。改错了会「哪儿都点不动」，所以操作前请先读完注意事项。

## 这个模块解决什么问题

- **菜单**：决定左侧导航显示哪些页面，以及每个按钮对应哪个权限点。
- **部门**：组织结构（总部 / 门店 / 小组），是「数据权限」的落点。
- **岗位**：员工的职务信息（店长 / 美甲师 / 前台），仅作标识与统计用。
- **字典**：下拉选项的统一来源（例如性别、渠道、状态这类选项）。
- **参数配置**：门店的经营参数（时区、定金比例、短信开关、积分规则…），改完不用重启。

## 谁来用（适用角色）

| 页面 | 页面权限点 | 建议给谁 |
| --- | --- | --- |
| 菜单管理 | `system:menu:list` | 只给技术同事或超级管理员 |
| 部门管理 | `system:dept:list` | 老板 / 店长 |
| 岗位管理 | `system:post:list` | 老板 / 店长 |
| 字典管理 | `system:dict:list` | 技术同事 / 运营 |
| 参数配置 | `system:config:list` | 老板 / 店长（涉及钱和短信） |

> ⚠️ 和 [用户与角色](./users-roles.md) 一样，这些系统管理页面的**新增/编辑/删除按钮权限点没有预置在菜单树里**，默认只有超级管理员点得动。需要给店长用，请按该页「使用注意事项」里的办法补按钮权限点。

## 操作路径

后台管理端 → 左侧菜单「系统管理」→ 对应子菜单：

- 菜单管理 `/system/menus`
- 部门管理 `/system/depts`
- 岗位管理 `/system/posts`
- 字典管理 `/system/dicts`
- 参数配置 `/system/configs`

## 分步操作

### A. 看懂菜单管理（先理解，再动手）

1. 进「菜单管理」，看到的是一棵**按层级缩进的列表**（不是树形折叠）：最深一层是「按钮」。
2. 三种类型：

| 类型 | 作用 | 需要填什么 |
| --- | --- | --- |
| 目录 | 只做分组，例如「系统管理」 | 路由路径、名称、标题 |
| 菜单 | 一个真正的页面，例如「用户管理」 | 路由路径 + **组件路径** |
| 按钮 | 一个权限点，例如「用户管理-新增」 | **权限标识**（例如 `system:user:create`） |

3. 左侧导航是怎么来的：**登录时系统把「你的角色被勾选的菜单」生成导航**，前端路由也跟着自动生成。所以「看不到菜单」= 角色没勾，而不是后端坏了。
4. 排序：每一行的「排序」列有上移/下移两个小箭头，点一下就和相邻的同级菜单交换顺序，提示「排序已更新」。
5. 图标：编辑弹窗里有一个图标选择区，再点一次同一个图标可以取消选择（显示「未设置（显示默认图标）」）。

### B. 给某个页面补一个按钮权限（最常见的运维动作）

1. 在「菜单管理」里找到目标页面（例如「用户管理」）。
2. 点那一行的钥匙图标「按钮权限」，弹窗标题形如「按钮权限 - 用户管理」。
3. 点弹窗右上角「新增按钮」。
4. 表单会自动带好「上级菜单」，你只需要：
   - 「类型」选「按钮」（默认已经是按钮）。
   - 「菜单标题」填一个能看懂的名字，例如「用户管理-新增」。
   - 「权限标识」填**和后端约定好的点**，例如 `system:user:create`（这是最关键的字段，填错按钮就永远不出现）。
   - 「状态」开启。
5. 点「保存」，回到「角色管理」给需要的角色勾上这个按钮。
6. 让员工重新登录验证。

### C. 建部门

1. 进「部门管理」，点「新增部门」建一个根部门；或在某一行点加号图标「添加子部门」建下级部门。
2. 填「部门名称」「排序」「联系电话」「邮箱」，状态保持开启。
3. 「上级部门」默认是「根部门」，需要挂到某个部门下就从下拉里选（下拉里带层级，形如「总部 / 门店A」）。
4. 点「保存」。

### D. 建岗位

1. 进「岗位管理」，点「新增岗位」。
2. 填「岗位名称」（中文，例如「店长」）和「岗位标识」（英文，例如 `shop_manager`）。
3. 填排序、状态、备注，保存。

> 💡 岗位只是「职务标签」，**不控制权限**。控制权限的是角色。

### E. 维护字典

1. 进「字典管理」，界面分左右两栏。
2. 左边是**字典类型**（例如「用户性别」）。点某一行把它选中（行首有勾选圈），右边的「字典数据」才会显示该类型下的选项。
3. 左边新增：点「字典类型」栏右上角「新增」，填「字典名称」和「类型标识」（小写字母/数字/`:-_`）。
4. 右边新增：先在左边选中一个类型，再点「字典数据」栏右上角「新增」（没选中时按钮是灰的，会提示「请先选择左侧字典类型」）。
5. 字典数据的字段：标签（界面上显示的文字，例如「男」）、键值（系统内部用的值，例如 `1`）、排序、状态、样式类名、列表样式。
6. 保存后**字典缓存会自动清掉**，刷新页面就生效。

### F. 改参数配置（门店经营参数）

1. 进「参数配置」。页面没有搜索框，请用浏览器的查找功能（Windows 按 `Ctrl + F`）搜「参数名称」，例如搜「短信」。
2. 找到要改的那一项，点铅笔图标「编辑」。
3. 改「参数值」，点「保存」，提示「更新成功」。
4. **不需要重启服务**：系统对参数有 10 秒的缓存，最多 10 秒后所有功能都会用新值。想立刻验证，等十几秒再试一次。
5. 「内置」为「是」的参数**不能删除**（点删除会被后端拒绝，提示「内置参数不能删除」），但可以改值。

## 字段说明

### 菜单表单

| 字段 | 必填 | 说明 | 填错会怎样 |
| --- | --- | --- | --- |
| 上级菜单 | 是 | 挂在哪一级下；类型选「按钮」时锁定不可改 | 挂错层级 → 菜单位置不对，或授权时找不到 |
| 类型 | 是 | 目录 / 菜单 / 按钮 | 类型选错 → 页面或按钮都不会按预期出现 |
| 路由名称 | 是 | 路由的唯一名称（英文），例如 `system_users` | 重复会让路由冲突，页面可能打不开 |
| 菜单标题 | 是 | 左侧导航上显示的中文名 | — |
| 路由路径 | 目录、菜单必填 | 例如 `/system/users` | 写错 → 点菜单打不开页面 |
| 组件路径 | 菜单必填 | 前端页面文件路径，例如 `system/users/index` | 写错 → 页面白屏或 404。**不要随手改** |
| 权限标识 | 按钮必填（菜单可选） | 例如 `system:user:create`，必须与后端代码一致 | 写错 → 按钮永远不显示，或权限给了也没用 |
| 排序 | 否 | 数字越小越靠前 | — |
| 状态 | 是 | 启用 / 禁用 | 禁用后该菜单从导航消失 |
| 图标 | 否 | 左侧导航的图标 | 不设会显示默认图标 |

### 部门 / 岗位表单

| 字段 | 必填 | 说明 | 填错会怎样 |
| --- | --- | --- | --- |
| 部门名称 / 岗位名称 | 是 | 中文名 | — |
| 上级部门 | 否 | 挂在哪个部门下 | 选错 → 数据范围算出来的可见范围不对 |
| 排序 | 否 | 数字越小越靠前 | — |
| 联系电话 / 邮箱 | 否 | 选填 | — |
| 岗位标识 | 是（建岗位时） | 英文标识，例如 `shop_manager` | 重复会被拒绝 |
| 状态 | 是 | 启用 / 禁用 | 禁用的部门/岗位在部分下拉里不再出现 |

### 参数配置全表（默认值 + 影响）

| 参数名称（界面显示） | 默认值 | 改了会怎样 |
| --- | --- | --- |
| 门店名称（通知模板 {shopName} 变量） | 美甲店 | 部分通知里的门店名会跟着变（其余通知目前不会自动带上门店名） |
| 店内时区 | Asia/Shanghai | **改错会让全店报表的「营业日」整体错位**，非必要不要改 |
| 可约时段粒度（分钟） | 15 | 影响可预约时间的网格；取值范围 5~120，越界会静默回落到 15 |
| 小程序端最少提前预约（分钟） | 60 | 顾客在小程序上最少要提前多久约；调大 = 临时单约不上 |
| 后台代录最少提前预约（分钟） | 0 | 前台帮顾客当场约的限制，默认允许立即约 |
| 最多提前预约天数 | 30 | 顾客能约到多久之后；调小会让远期预约约不上 |
| 爽约判定容忍期（分钟） | 15 | 到点后多久仍未到店会自动标记爽约 |
| 默认定金比例（‰） | 300（30%） | 新预约默认收多少定金，影响收银台默认金额 |
| 每元累计积分 | 1 | 消费 1 元积多少分，影响积分发放速度 |
| 多少积分抵 1 元 | 100 | 积分抵扣的汇率 |
| 单笔积分抵扣上限（‰） | 300（30%） | 一笔单子最多能用积分抵掉多少比例 |
| 充值赠送比例上限（‰） | 200（20%） | 充值方案的赠送比例不能超过这个数 |
| 余额扣减顺序 | bonus_first（先扣赠送） | 退款/扣减余额时先动赠送额还是本金 |
| 单次充值下限（分） | 10000（¥100） | 低于这个金额不能充值 |
| 退款/冲正是否必填原因 | true | 置为 false 后，退款可以不写原因（**不建议**） |
| 在线支付二维码有效期（分钟） | 5 | 扫码支付的二维码多久失效 |
| 每日对账触发小时 | 6 | 每天几点做支付渠道对账 |
| 短信总开关 | false（关闭） | 打开后短信才可能真正发出（还要配环境变量和模板白名单） |
| 允许走短信的模板白名单 | 空 | 逗号分隔的模板编码，例如 `recharge_success,booking_remind` |
| 通知失败重试上限 | 3 | 单条通知自动重试几次，0 = 不自动重试 |
| 新挂账主体默认额度（分） | 0 | 新建挂账主体的默认授信额度，0 = 不限额/需人工设 |
| 默认月结日 | 5 | 新建月结挂账主体的默认结算日（1~28） |
| 提成结算日 | 5 | 仅作为门店记账习惯的标记，**系统不会自动结算提成** |

## 使用注意事项

> ⚠️ **参数值填成非法数字或超范围，系统不会报错，而是默默用默认值。**
> 触发条件：把「默认定金比例」填成 `abc`，或把「可约时段粒度」填成 `200`（超出 5~120）。
> 后果：保存提示「更新成功」，但实际运行时用的是默认值——你以为改了，其实没生效，还很难发现。
> 正确做法：改数字类参数时只填数字，并留意上面表格里的取值范围；改完让同事实际走一遍验证效果。

> ⚠️ **不要改「店内时区」。**
> 触发条件：出于好奇或误操作把 `Asia/Shanghai` 改成别的值。
> 后果：报表的营业日切分、可约时段、通知时间会整体错位，历史报表口径也会跟着变，等于全店数据时间轴被平移。
> 正确做法：保持不变；如果门店确实在别的时区，请先与技术同事确认再改。

> ⚠️ **菜单管理里的「路由路径」「组件路径」不要随手改。**
> 触发条件：为了让菜单好看一点，改了路径或组件名。
> 后果：点菜单白屏 / 404，甚至整个导航错乱（前端路由是按菜单自动生成的）。
> 正确做法：只改「菜单标题」「图标」「排序」「状态」这些展示项；路径类字段由技术同事维护。

> ⚠️ **删除菜单会连带删掉它下面的按钮权限。**
> 触发条件：删除一个还有子节点的菜单。
> 后果：子按钮的权限点一起消失，相关按钮在全站都不再显示。有子菜单时删除按钮本身是灰的（悬停提示「存在子菜单时不可删除」），但删叶子节点要小心。
> 正确做法：不要的菜单改成「禁用」。

> ⚠️ **改菜单后必须让员工重新登录（或等最多 15 分钟）。**
> 触发条件：刚给菜单改名/改排序就催员工看。
> 后果：他那边还是旧的导航。
> 正确做法：让他退出重新登录。

> ⚠️ **部门调整会影响「数据范围」的可见性。**
> 触发条件：把某位店长的部门从「门店A」改到「总部」，而他的角色是「本部门数据权限」。
> 后果：他立刻看不到门店A的数据了（这是预期行为，但很容易被当成故障报上来）。
> 正确做法：调整组织架构前通知相关同事；调整后请他们重新登录确认。

> ⚠️ **字典是「下拉选项的源头」，改了会全站生效。**
> 触发条件：把某个字典项的「键值」从 `1` 改成 `male`。
> 后果：已有数据显示不出来或错位（历史数据里存的还是 `1`）。
> 正确做法：只改「标签」（显示文字）和「排序」；键值属于技术约定，不要改。

> ⚠️ **删除字典类型前先确认没人用。**
> 触发条件：删除一个还在使用的字典类型。
> 后果：二次确认里已经写明「其下所有字典数据将无法使用」，相关下拉会变空。
> 正确做法：先禁用，观察一周再删。

## 常见问题

**Q：为什么加了新菜单，员工还是看不到？**
A：菜单建好只是「存在」，还要到「角色管理 → 分配菜单权限」里给该角色**勾上**，然后让员工重新登录。

**Q：为什么点了「新增用户」没反应 / 按钮不存在？**
A：按钮权限点没给。系统管理类页面的按钮权限点没有预置在菜单里，需要先在「菜单管理 → 按钮权限」里补一条（参考上文 B 段），再去角色里勾选。或者改用超级管理员账号操作。

**Q：参数改了要重启服务吗？**
A：不用。系统对参数有 10 秒缓存，最多 10 秒后生效。改完等十几秒再试。

**Q：为什么我改的参数好像没生效？**
A：先检查是不是填了非法值或超范围的值（系统会静默回落到默认值）；再确认你改的是「参数值」而不是「参数名称」。

**Q：内置参数能删吗？**
A：不能。内置参数删除会被拒绝（提示「内置参数不能删除」），但值可以改。

**Q：参数配置页面为什么没有搜索框？**
A：当前版本没有。请用浏览器自带的查找（`Ctrl + F`）搜参数名称，例如搜「积分」。

**Q：岗位到底有什么用？**
A：只是职务标签，方便管理和统计，**不控制权限**。要控制能看什么，用「角色 + 数据范围」。

**Q：部门能建几层？**
A：可以多层嵌套（下拉里用「 / 」表示层级）。层级越深，「本部门及以下数据权限」覆盖的范围越大。

**Q：菜单里的排序上移下移没反应？**
A：它只会和**同级相邻**的菜单交换位置；第一行点「上移」、最后一行点「下移」都不会有变化。操作期间其它排序按钮会暂时禁用，等提示「排序已更新」再继续。

**Q：能改菜单的类型吗（比如把按钮改成菜单）？**
A：类型是可改字段，但改完要重新填对应的必填项（菜单要组件路径、按钮要权限标识），否则保存会被拦。建议不确定时新建而不是改类型。
