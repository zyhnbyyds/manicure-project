# 会员模块总览

## 这个模块解决什么问题

门店要记住的是「人」：她叫什么、手机号多少、喜欢什么颜色、卡里还剩多少钱、还有几次卡、攒了多少积分、够不够升级。

系统里管这些的模块就是会员模块。但它有一个和其他系统不一样的地方，必须先说清楚：

> 💡 **顾客档案就是会员档案。系统里没有第二套「会员表」。**
>
> 大白话：你在「顾客档案」里建的那个「张女士 138xxxx0002」，本身就是她的会员档案。她报手机号、消费过、卡里有钱，她就自动是会员了——**不需要额外的「入会」手续，也不会出现「顾客表里有一个张女士、会员表里还有一个张女士」这种事**。

这样做带来三个直接好处：

1. **前台不用录两遍**。新顾客来一次，录一条档案就够；之后充值、办卡、攒积分都在同一条档案上。
2. **不会对不上号**。「谁的余额」永远没有歧义——余额就挂在那条唯一的顾客档案上。
3. **小程序和门店看的是同一个人**。顾客在小程序里看到的余额、积分、次卡，和门店后台看到的完全一致，因为就是同一条档案。

## 谁来用（适用角色）

| 角色 | 主要在哪几页 | 说明 |
| --- | --- | --- |
| 前台 / 收银员 | 顾客档案、会员管理（只看）、收银台 | 日常建档、查余额 / 积分 / 次卡；**充值、退款、调级一般只给店长** |
| 店长 | 全部会员页面 | 充值、冲正退款、手工调级、发卡、积分兑换、发券、维护等级与卡种 |
| 老板 | 会员等级、充值方案、次卡卡种、优惠券模板 | 定规则、定价格；日常查询用会员管理 |
| 顾客（小程序自助） | 小程序「会员卡 / 充值中心 / 积分兑换 / 我的优惠券」 | 看余额积分次卡；**绑定手机号后可用；在线支付与在线充值尚未开通** |

## 分步操作

建议按这个顺序把会员模块配置好（一次配好，长期使用）：

1. **先看「会员等级」**：确认三档等级的折扣与升级门槛是不是符合门店实际（见 [会员等级与折扣](./levels.md)）。
2. **再定「充值方案」**：充多少送多少（见 [储值充值与次卡](./recharge-cards.md)）。
3. **再定「次卡卡种」**：卡的次数、有效期、适用项目、售价（同上）。
4. **再定「积分兑换品」**：多少积分能换什么（见 [积分与优惠券](./points-coupons.md)）。
5. **最后定「优惠券模板」**：满减券的面额与门槛（同上）。
6. **然后就可以开始用了**：顾客到店 → 建档 → 消费 / 充值 / 办卡 → 自动累计消费与积分 → 自动升级。

日常动线（前台最常用的三条）：

- **新顾客到店**：顾客档案 → 新增顾客（填姓名 + 手机号）→ 完成后正常开单收款。
- **顾客问「我卡里还有多少钱 / 几次」**：会员管理 → 按姓名 / 手机号 / 会员号搜 → 点「会员详情」看「储值余额（本金 + 赠送）」「积分」「次卡」。
- **顾客要充值**：会员管理 → 找到人 → 点「充值」→ 选充值方案或自定义金额 → 选收款方式 → 填备注 → 确认（详见 [储值充值与次卡](./recharge-cards.md)）。

## 字段说明

一条顾客档案上会同时出现「身份信息」和「资产信息」两类字段。这就是「顾客即会员」最直观的体现：

| 字段 | 类别 | 说明 | 怎么来的 |
| --- | --- | --- | --- |
| 姓名 / 性别 / 生日 / 备注 | 身份 | 建档时填的 | 人工填写 |
| **手机号** | 身份 + **锚点** | 全店唯一；小程序绑定、消费记录都认它 | 人工填写，或顾客在小程序授权手机号时自动带出 |
| 会员号 | 身份 | 形如 `M20260101001`（M + 入会日期 + 编号） | 系统生成；没入会时显示「未入会 / 散客」 |
| 等级 / 折扣 | 会员 | 例如金卡、9.5 折 | 按累计消费自动升级（可手工调，需原因） |
| 入会时间 | 会员 | 成为会员的时间 | 系统记录 |
| 储值余额 | 资产 | **本金 + 赠送**两块钱合起来才是可用余额 | 充值时增加，消费时扣减，退款时只退本金 |
| 积分 | 资产 | 当前可用积分 | 消费时累计、抵扣 / 兑换时扣减 |
| 累计消费 | 资产 | 用来决定等级 | 收款成功时增加，退款时按比例回减 |
| 到店次数 / 最近到店 | 统计 | 用来判断熟客 | 由「**已完成**」的预约驱动（可手动重算） |

> 💡 大白话：**「累计消费」不是「余额」**。累计消费是「这个人一共在店里花了多少钱」（只增不减，退款会回减），用来升级；储值余额是「卡里还剩多少钱」，用来付款。两个数完全不是一回事。

## 使用注意事项

> ⚠️ **手机号是唯一锚点，重号会被拒绝。** 一个手机号在系统里只能有一条顾客档案。如果录了一个已经存在的手机号，系统会直接告诉你「手机号 138xxxx0002 已被顾客「张女士」(#12) 使用」。这时请先搜索这个手机号，看看是不是同一个人——**不要为了建档给顾客换一个手机号**，否则小程序绑定时会绑到错的档案上。

> ⚠️ **散客可以没有手机号，会员必须有。** 只是路过做一次、不想留信息的顾客，建档时手机号可以空着（散客）。但一旦要**充值、办卡、累计积分**，就必须补上手机号——系统会提示「会员必须有手机号，请先补全手机号再充值」。

> ⚠️ **删掉顾客不等于手机号被释放。** 删除是「收藏起来」而不是「销毁」：被删档案的手机号仍然占位，其他顾客用不了这个号。想再用这个号，要先**恢复**那条档案（见 [顾客档案](./customers.md)）。

> ⚠️ **小程序里能看到什么，完全取决于绑定的手机号。** 顾客在小程序里授权手机号后，系统按手机号匹配档案；匹配到哪条档案，他就能看到那条档案上的余额、积分、次卡、优惠券。**所以「顾客说小程序里看不到我的次卡」，第一件事就是核对他授权的是哪个手机号。**

> ⚠️ **小程序内不能付钱、也不能充值。** 小程序里点「微信支付」会提示「这个功能马上就来啦～」，充值页面会提示「充值通道正在接入，可先到店充值」。**充值只能到店由前台操作。**（积分兑换、领优惠券、提交评价在小程序里是可用的。）

> ⚠️ **账务流水只追加、不能改也不能删。** 每一笔余额变动、积分变动都会留一条流水。发现数字不对时，正确做法是用「重算」按流水修复，**绝对不要手工去改数字**。

> ⚠️ **等级只升不降（除非你主动重算）。** 顾客消费越多等级越高；退货退款一般不会自动把他降级，只有系统重算或手工调整才会降。这一点在 [会员等级与折扣](./levels.md) 里有详细说明。

## 常见问题

**Q：顾客只是做了一次美甲，需要给他「办会员」吗？**
A：不需要单独办。只要建档时留了手机号，他就已经在会员体系里了（等级默认是最低那一档，也就是不打折那档）。后续充值、办卡、积分都会自动挂在他名下。

**Q：同一个人有两个手机号，怎么办？**
A：只建一条档案，把他常用的那个手机号填进去。**不要建两条**——两条档案会让余额、积分、消费记录分散在两边，而且小程序绑定时只能绑到其中一条。

**Q：顾客换了手机号怎么办？**
A：直接在顾客档案里改手机号。改完之后，他在小程序里需要重新授权一次新手机号才能看到自己的会员卡。

**Q：顾客说小程序里「没有我的会员卡」。**
A：三个可能：① 他还没授权手机号（页面上会显示「绑定手机号，解锁会员卡」）；② 他授权的手机号和门店档案里的不一样；③ 他授权到的是一条**已被删除**的档案——系统会提示「该手机号的历史档案已被门店删除（顾客 #X），请联系门店恢复后再绑定」，这时需要门店在顾客档案里点「恢复档案」。

**Q：为什么我搜不到某个顾客？**
A：「顾客档案」页默认只显示**在用档案**。如果这个人被删过，把「档案状态」筛选项改成「已删除档案」再搜。

**Q：充值送的钱和顾客自己充的钱，能混着花吗？**
A：能，可用余额 = 本金 + 赠送，付款时都能用。但**退款只退本金，赠送不退、也不能提现**。详见 [储值充值与次卡](./recharge-cards.md)。

**Q：会员的等级折扣和积分抵扣能一起用吗？**
A：能。系统先算等级折扣，再算积分抵扣。举例：原价 200 元、金卡 9.5 折 → 优惠 10 元 → 折后 190 元；再用积分抵扣时，抵扣上限是按**折后金额**算的（默认最多抵 30%，也就是 57 元）。详见 [积分与优惠券](./points-coupons.md)。
