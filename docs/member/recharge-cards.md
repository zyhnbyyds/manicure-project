# 储值充值与次卡

## 这个模块解决什么问题

门店最常见的两种「先收钱后服务」的生意：

- **储值**：顾客先充 1000 元到卡里，以后消费从卡里扣（通常还会送一点，例如充 1000 送 150）；
- **次卡**：顾客一次买 10 次服务，以后每次来做项目就核销一次。

两者都涉及「钱已经收了、服务还没做完」，所以一定要把下面这件事搞明白：

> 💡 **储值余额分成两块钱：本金 + 赠送。**
>
> - **本金**：顾客真金白银付的钱，**可以退**；
> - **赠送**：门店送的钱，**不可退、不可提现**；
> - 付款时两块钱都能用（可用余额 = 本金 + 赠送）。
>
> 大白话：充 1000 送 150，卡里有 1150 元；顾客要是反悔要退钱，**只能退那 1000 元**，送的 150 元不退。

## 谁来用（适用角色）

| 角色           | 能做什么                                                         | 权限点                                                                 |
| -------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 店长           | 充值、冲正退款、发卡、撤销核销、退卡、维护充值方案与卡种         | 会员管理-充值 / 退款、会员次卡-撤销核销 / 退卡、充值方案-_、次卡卡种-_ |
| 前台           | 一般只查余额与次数；**充值 / 退款 / 退卡建议只给店长**           | —                                                                      |
| 老板           | 定充值方案（充多少送多少）与卡种（次数、有效期、售价、适用项目） | 充值方案-_、次卡卡种-_                                                 |
| 顾客（小程序） | 看余额、看次卡剩余次数；**在线充值尚未开通，只能到店充值**       | —                                                                      |

> ⚠️ **钱的权限默认只给店长。** 「会员管理-充值」「会员管理-退款」「会员次卡-退卡」这些都是动账的动作，建议只授予店长。

## 操作路径

| 要做什么                                      | 路径                                                                                               |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 定充值方案（充多少送多少）                    | 后台 → 左侧菜单「美甲预约」→「充值方案」`/biz/recharge-plans`                                      |
| 定次卡卡种（次数 / 有效期 / 适用项目 / 售价） | 后台 → 左侧菜单「美甲预约」→「次卡卡种」`/biz/card-types`                                          |
| 给顾客充值 / 发卡 / 冲正退款                  | 后台 → 左侧菜单「美甲预约」→「会员管理」`/biz/members` → 找到顾客 → 「充值」/「发卡」/「冲正退款」 |
| 查已发出的卡、撤销核销、退卡                  | 后台 → 左侧菜单「美甲预约」→「会员次卡」`/biz/member-cards`                                        |
| 核销次卡（消费时）                            | 收银台 → 右栏渠道选「次卡核销」                                                                    |

## 分步操作

### 一、先配好充值方案

1. 打开「充值方案」页，点「**新增方案**」。
2. 填：

| 表单字段           | 怎么填                              | 系统提示原文                                                                   |
| ------------------ | ----------------------------------- | ------------------------------------------------------------------------------ |
| 方案名             | 必填，占位提示「如 充 1000 送 100」 | —                                                                              |
| 实付金额(元)       | 必填，必须大于 0                    | **「顾客实际支付的金额，计入可退本金」**                                       |
| 赠送金额(元)       | 选填                                | **「赠送比例上限 20%（配置项 biz.member.maxBonusPermille），超出后端会拒绝」** |
| 排序 / 状态 / 备注 | 状态默认启用                        | —                                                                              |

3. 点「保存」。列表里会显示「赠送比例」，**超过 20% 会标红**，并警告「赠送比例超过 20% 上限，后端可能拒绝该方案」。

**赠送比例怎么算**：赠送 ÷ 实付。

| 方案             | 实付 | 赠送 | 赠送比例 | 能不能保存                                                      |
| ---------------- | ---- | ---- | -------- | --------------------------------------------------------------- |
| 充 ¥500 送 ¥50   | 500  | 50   | 10%      | ✅                                                              |
| 充 ¥1000 送 ¥150 | 1000 | 150  | 15%      | ✅                                                              |
| 充 ¥2000 送 ¥400 | 2000 | 400  | 20%      | ✅（顶到上限）                                                  |
| 充 ¥1000 送 ¥300 | 1000 | 300  | 30%      | ❌ 会被后端拒绝：「赠送金额超过上限（不超过充值金额的 20.0%）」 |

系统预置了上面三个方案，可以直接改成门店自己的。

### 二、给顾客充值

1. 打开「会员管理」，按「姓名 / 手机号 / 会员号」搜到顾客，点「**充值**」。
2. 填：

| 表单字段             | 怎么填                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| 充值方案             | 选一个方案（选项会显示「充 ¥1000 送 ¥150（实付 ¥1000，赠 ¥150）」）；**想自定义金额就把这里留空** |
| 自定义实付(元)       | 不走方案时填写实付金额                                                                            |
| **收款方式**（必填） | 现金 / 微信（记账）/ 微信线下收款码 / 支付宝（记账）/ 支付宝线下收款码                            |
| **备注**（必填）     | 占位提示「充值备注（必填）」                                                                      |

3. 界面会实时显示「实付金额」与「赠送金额」两行，并提示：
   > 「赠送进入「赠送余额」，不可退、不可提现；赠送比例上限 20%（配置项 `biz.member.maxBonusPermille`），超出后端会拒绝。单次充值下限由配置项 `biz.member.minRechargeAmount` 控制（默认 100 元），且会员必须已有手机号。」
4. 点「充值」→ 二次确认窗：「实付 ¥1000，赠送 ¥150。**赠送金额不可退、不可提现**，且赠送比例上限为 20%。确定充值吗？」
5. 点「确认充值」→ 提示「充值成功」。

**充值成功后**：

- 顾客的「储值余额」增加（本金 +1000，赠送 +150）；
- 写一条「充值」流水；
- **累计消费增加 1000 元**（按实付算），并累计积分——所以大额充值往往会**当场触发升级**；
- 给顾客发一条充值成功通知（短信通道未配置时发站内消息，短信模板正文里明确写着「赠送金额不可退、余额不可提现」）。

充值会被拦住的几种情况（都是统一提示）：

| 情况                        | 系统提示                                                       |
| --------------------------- | -------------------------------------------------------------- |
| 顾客没有手机号              | 「会员必须有手机号，请先补全手机号再充值」                     |
| 既没选方案也没填金额        | 「请选择充值方案或填写充值金额」                               |
| 金额为 0 或负               | 「充值金额必须大于 0」                                         |
| 低于门店下限（默认 100 元） | 「单次充值不得低于 100.00 元」                                 |
| 赠送超过上限                | 「赠送金额超过配置上限」                                       |
| 方案被停用了                | 「充值方案已停用」                                             |
| 第一次充值（还不是会员）    | 系统**自动帮他入会**：生成会员号、记入会时间、置为最低启用等级 |

### 三、花钱的时候：余额怎么扣

顾客消费用余额付款时：

- 可用余额 = **本金 + 赠送**；
- 系统按门店配置的顺序扣减，**默认是「赠送优先」**（先花送的，把可退的本金留得多一些）；
- **余额不足会直接失败，不会「扣到 0 剩下让他补现金」**。收银台会提示「储值余额不足：当前可用 ¥X，余额不足不会部分扣减」，请拆成两行：余额行 + 现金（或其它方式）行。

> 💡 大白话：赠送优先是「为顾客着想」的默认设置——先花掉不能退的钱，卡里剩下的都是能退的本金。这个顺序由门店配置项决定，一般不用改。

### 四、配好次卡卡种

1. 打开「次卡卡种」页，点「**新增卡种**」。
2. 填：

| 表单字段           | 怎么填                       | 系统提示原文                                   |
| ------------------ | ---------------------------- | ---------------------------------------------- |
| 卡种名             | 必填，占位「如 10 次美甲卡」 | —                                              |
| 售价(元)           | 必填                         | **「发卡时可改价；积分兑换发出的卡售价为 0」** |
| 总次数             | 必填，至少 1 次              | 「不能为空」「至少 1 次」                      |
| 有效期(天)         | 多少天内有效                 | **「0 = 永久有效」**                           |
| 适用项目           | 至少选 1 个项目              | 「请选择适用项目（至少 1 个）」                |
| 排序 / 状态 / 备注 | 状态默认启用                 | —                                              |

3. 点「保存」。列表里能看到「售价(元)」「总次数」「有效期」（0 显示「永久」，否则显示「365 天」）「适用项目」「排序」「状态」。

系统预置了 5 个卡种：

| 卡种名         | 售价(元) | 总次数 | 有效期 | 适用项目                     |
| -------------- | -------- | ------ | ------ | ---------------------------- |
| 基础款 10 次卡 | 800.00   | 10     | 365 天 | 纯色美甲、法式美甲、跳色美甲 |
| 款式 5 次卡    | 700.00   | 5      | 180 天 | 猫眼美甲、渐变美甲、贴钻美甲 |
| 全项目 10 次卡 | 2000.00  | 10     | 365 天 | 全部项目（不含「卸甲」）     |
| 纯色美甲单次卡 | 88.00    | 1      | 90 天  | 纯色美甲（**积分兑换专用**） |
| 手部护理单次卡 | 68.00    | 1      | 90 天  | 手部护理（**积分兑换专用**） |

保存时会被拦住的几种情况：「卡种名称已存在」「总次数必须大于 0」「有效期天数不能为负」「卡价不能为负」「卡种必须至少配置一个适用项目」。

> ⚠️ **删除卡种不影响已发出的卡。** 确认窗写得很清楚：「确定删除次卡卡种「基础款 10 次卡」吗？**已发出的卡不受影响**。」所以下线一个卡种可以直接删（或改成「禁用」）；顾客手上已经买的卡照常使用。

### 五、给顾客发卡

1. 打开「会员管理」→ 找到顾客 → 点「**发卡**」。
2. 填：

| 表单字段   | 怎么填                                                          |
| ---------- | --------------------------------------------------------------- |
| 卡种       | 必填，选项显示「基础款 10 次卡（售价 ¥800.00 / 10 次）」        |
| 支付方式   | 现金 / 微信 / 支付宝 / 储值余额（**不允许再用另一张次卡买卡**） |
| 购卡价(元) | 不填就取卡种售价                                                |
| 备注       | 选填                                                            |

3. 提示原文：「卡种默认售价 ¥800.00；**发卡会累计消费与积分**，支付方式不允许再用另一张次卡。」
4. 点「发卡」→ 确认窗「将按 ¥800.00 收款并立即发放次卡（购卡会累计消费与积分）。确定发卡吗？」→ 确认后提示「发卡成功」。
5. 卡号由系统生成，形如 `C20260101001`，可以在「会员次卡」页或会员详情的「次卡」页签里查。

### 六、核销次卡（顾客来做项目时）

核销在**收银台**做（不在会员次卡页）：

1. 收银台选好单据，右栏「添加一行」，渠道选「**次卡核销**」；
2. 这一行的金额框是灰的（次卡核销不产生金额）；
3. 下拉里选顾客**生效中**的卡，格式像「基础款 10 次卡（C20260101001，剩余 7 次）」；
4. 点「去收款」→「确认收款」。

界面上明确写着三条规则：

> 「次卡核销不产生金额、不叠加等级折扣；仅可核销卡种适用项目内的项目。」

会被拦住的几种情况：

| 情况                   | 系统提示                                 |
| ---------------------- | ---------------------------------------- |
| 卡已退                 | 「次卡已退卡」                           |
| 卡过期了               | 「次卡已过期」                           |
| 次数用完了             | 「次卡次数已用完」                       |
| 卡种没配适用项目       | 「卡种未配置适用项目」                   |
| 项目不在卡的适用范围内 | 「次卡不适用于所选项目（项目 id：3）」   |
| 并发下状态变了         | 「次卡不可核销（状态已变或次数已用完）」 |

**用完最后 1 次后**，卡的状态自动变成「**已用完**」。

### 七、撤销核销（核错了）

1. 打开「会员次卡」页，按顾客 ID / 状态 / 卡种筛出这张卡；
2. 点「**撤销核销**」（**已过期、已退卡的卡不能撤销**）；
3. 弹窗里填「撤销原因」（必填，占位提示「请说明撤销原因（会写入核销记录）」）；
4. 保存 → 确认窗「确定撤销次卡「C20260101001」的**最近一次**核销吗？将回补次数并写入核销记录。」→ 确认后提示「已撤销核销」。

> ⚠️ **撤销的是「最近一次」核销。** 如果想撤销的不是最后一次（例如顾客第一次和第三次都记错了），请按正确顺序从最后一次往前撤，或者直接找店长确认怎么处理。

### 八、次卡到期

- 卡的到期时间 = 发卡时间 + 卡种的有效期天数；
- **有效期填 0 表示永久有效**，列表里「到期时间」显示「永久」；
- 系统每天凌晨 **00:05** 自动把已过期的卡从「生效中」改成「**已过期**」；
- 过期卡不能核销，也不能撤销核销和退卡（这两个按钮在已过期的行上不显示）。

### 九、退卡

1. 在「会员次卡」页找到卡，点「**退卡**」（卡状态必须是「生效中」或「已用完」）；
2. 弹窗里填：
   - **退款金额(元)**：系统会**预填一个按剩余次数折算的金额**（售价 × 剩余次数 ÷ 总次数），你可以改成人工核算的金额；
   - **退卡原因**（必填）；
3. 提交 → 确认窗（警示样式）：「确定对次卡「C20260101001」退卡吗？退款金额 ￥300.00，**退卡将冲减累计消费，此操作不可恢复**。」→ 确认后提示「已退卡」。

> ⚠️ **退卡是直接生效的，没有二次审批。** 退卡会立刻把卡置为「已退卡」、写一条退款流水、并**冲减顾客的累计消费与积分**。系统**不会**生成一张退款审批单。所以「会员次卡-退卡」这个权限请**只给店长**，并在操作前和顾客确认清楚退款金额。

### 十、冲正退款（把充值的钱退回去）

1. 打开「会员管理」→ 找到顾客 → 点「**冲正退款**」；
2. 弹窗顶部会显示「当前储值余额：本金 ¥X / 赠送 ¥Y（赠送不可退、余额不可提现，只能退实付本金）」；
3. 填：

| 表单字段     | 选项 / 说明                                                                    |
| ------------ | ------------------------------------------------------------------------------ |
| 退款金额(元) | 必填，必须大于 0                                                               |
| **退款去向** | 「**现金冲正**（写流水，不改动储值余额）」或「**储值冲正**（从储值余额扣回）」 |
| 退款原因     | 必填，占位「冲正原因（必填）」                                                 |

4. 两种去向的区别：

| 去向     | 会发生什么                                                         | 界面上的说明                                                                  |
| -------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| 现金冲正 | 只写一条反向流水，**卡里余额不变**（因为钱是当面用现金退给顾客的） | 「将记录一笔现金冲正 ¥X（写反向流水，**不改变储值余额**）」                   |
| 储值冲正 | 从卡里扣回这笔钱（按赠送优先顺序扣），并写反向流水                 | 「将从储值余额扣回 ¥X（按赠送优先顺序扣减，余额不足会直接失败）并写反向流水」 |

5. 校验规则：**现金冲正不得超过实付本金余额**（「现金冲正不得超过实付本金余额 ¥X（赠送余额不可退、不可提现）」）；储值冲正不得超过当前储值余额（本金 + 赠送）。

> ⚠️ **冲正退款同样没有退款审批单。** 弹窗里如实写着：「该接口不产生退款审批单」。它是「店长直接在会员管理里操作」的动作，会即时生效、写反向流水（原流水保持不动，方便追溯）。**请把「会员管理-退款」权限只给店长。**

## 字段说明

| ------------------------------------------ | ----------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------- |

| 自定义实付(元)                             | 二选一                  | 不走方案时填                                                           | 填 0 或负数 → 「充值金额必须大于 0」                                         |
| 收款方式（充值）                           | 是                      | 现金 / 微信（记账）/ 微信线下收款码 / 支付宝（记账）/ 支付宝线下收款码 | 选错会让收款方式统计偏差；**注意「（记账）」和「线下收款码」是两个不同选项** |
| 充值备注                                   | **是**                  | 为什么充、谁经手                                                       | 不填 → 「请填写充值备注」                                                    |

| 退款金额（退卡）                           | 是                      | 默认按剩余次数折算，可改                                               | 填非数字 / 负数 → 「请输入正确的退款金额」/「退款金额必须是非负整数（分）」  |
| 退款去向（冲正）                           | 是                      | 现金冲正 / 储值冲正                                                    | 选错会导致余额和现金账不一致                                                 |
| 退款原因 / 退卡原因 / 撤销原因             | **是**                  | 必填并留痕                                                             | 不填会被拦下                                                                 |

## 使用注意事项

> ⚠️ **赠送的钱不可退、不可提现，这是系统硬规则。** 退款 / 冲正时都只能针对**实付本金**，界面会拦：「现金冲正不得超过实付本金余额 ¥X（赠送余额不可退、不可提现）」。跟顾客解释时可以直接说：充值的赠品部分不折现。

> ⚠️ **赠送比例上限是 20%。** 想设「充 1000 送 300」会被后端拒绝（「赠送金额超过上限（不超过充值金额的 20.0%）」）。如果门店真的要做超过 20% 的活动，需要技术对接人先调整门店配置项的上限，**不要用两个方案拼凑或者手工加余额**。

> ⚠️ **充值有下限（默认 100 元）。** 「单次充值不得低于 100.00 元」。顾客想充 50 元会被拦。不过收银台可以直接现金收 50 元，不一定非要充值。

> ⚠️ **会员没有手机号不能充值。** 系统会提示「会员必须有手机号，请先补全手机号再充值」。**先去顾客档案把手机号补上**，不要为了充值新建一条档案。

> ⚠️ **首次充值会自动入会，并当场累计消费。** 充 1000 元会直接给顾客加 1000 元的累计消费，很可能**当场把他送到下一个等级**。这是设计如此；如果你不希望充值计入升级，需要门店重新考虑等级门槛。

> ⚠️ **余额不足不会部分扣减。** 收银台提示原文是「余额不足不会部分扣减」。想让顾客「余额花完再补现金」，请**手动拆成两行**：余额行填余额能覆盖的金额，剩下用现金。

> ⚠️ **次卡核销不叠加等级折扣、不产生金额。** 别指望「用次卡还能再打折」：次卡核销那一行的金额是 0，等级优惠也不会体现在这行上。

> ⚠️ **次卡只能核销卡种适用项目内的项目，而且是按预约的第一个项目判定。** 顾客买了「基础款 10 次卡」，来做「猫眼美甲」是核销不了的（会提示「次卡不适用于所选项目」）。这时要么让他按原价付款，要么给他换一个卡种。

> ⚠️ **过期卡不能核销、不能撤销核销、也不能退卡。** 系统每天 00:05 自动置过期。如果顾客的卡刚过期就来投诉，前台没有自助处理的办法——**只能由店长决定是否用其它方式补偿**（例如发一张优惠券或手动发一张新卡）。

> ⚠️ **退卡与冲正退款都跳过退款审批单。** 这两处是「店长直接操作、即时生效」的，操作本身会冲减顾客的累计消费与积分。请把相关权限收在店长手上，并养成「先跟顾客确认金额、再操作」的习惯。

> ⚠️ **小程序不能在线充值。** 小程序充值页面点了「立即充值」只会提示「充值通道正在接入，可先到店充值」。**顾客只能到店由前台充值。**

> ⚠️ **余额和积分都有对账等式。** 系统会校验「所有流水加起来 = 当前余额 / 当前积分」。如果发现数字对不上（例如历史数据问题），正确做法是在「会员管理」点「**重算**」（按流水重算余额、积分、累计消费与等级），**绝对不要手工改数字**。

## 常见问题

**Q：充 1000 送 150，顾客消费了 200，卡里还剩多少？**
A：1150 − 200 = 950 元。系统按「赠送优先」扣，所以先把 150 元赠送花掉，再从本金里扣 50 元 → 剩下本金 950 元、赠送 0 元。

**Q：顾客充了 1000 送 150，现在要退钱，退多少？**
A：**最多退 1000 元**（实付本金）。赠送的 150 元不可退、不可提现。如果他已经消费过一部分，可退金额要按剩余本金核算。

**Q：为什么顾客的次卡核销不了？**
A：按顺序查四件事：① 卡是不是「生效中」（过期 / 已用完 / 已退卡都不行）；② 预约里的第一个项目在不在这个卡种的适用项目里；③ 做这个项目的美甲师是不是会做（美甲师可做项目也要匹配）；④ 卡是不是刚被另一个人核销掉了。

**Q：次卡核销和等级折扣会叠加吗？**
A：不会。次卡核销不产生金额、不叠加等级折扣。

**Q：顾客的卡过期了，能给他退吗？**
A：系统里已过期的卡不能点「退卡」（按钮不显示）。需要处理请联系店长，用其它方式（发券、发新卡）补偿。

**Q：充值算不算「消费」？顾客会不会因为充值就升级？**
A：算。充值会按实付金额累计消费与积分，所以充 1000 元很可能直接触发升级。

**Q：顾客充值后用小票来问「你们说的送 150 呢」？**
A：会员详情里能看到余额的构成：「¥950.00（本金 ¥950.00 / 赠送 ¥0.00）」，一眼就能解释清哪部分是本金、哪部分是赠送。充值成功通知的正文里也写明了「赠送金额不可退、余额不可提现」。

**Q：我误操作给顾客退卡了，能撤销吗？**
A：不能。界面明确写着「此操作不可恢复」。请立刻告诉店长，由店长决定后续处理方式（例如重新发一张等价的新卡）。这也是为什么退卡只给店长权限。

**Q：撤销核销有什么限制？**
A：只能撤销「最近一次」核销，且已退卡的核销记录不能撤销（「已退卡的核销记录不能撤销」）。撤销必须填原因，会写进核销记录里。
