## 这个模块解决什么问题

预约模块是整套系统的**主心骨**：门店一天里"谁、几点、给谁、做什么、收了多少钱"，全部记在这里。

它由 4 个页面组成，各管一段：

| 页面           | 路径                    | 一句话职责                                         |
| -------------- | ----------------------- | -------------------------------------------------- |
| **预约管理**   | `/biz/bookings`         | 所有单据的列表、开单、到店、完成、改期、取消、结算 |
| **排班管理**   | `/biz/schedules`        | 决定"谁什么时候上班"，也就是可约时段的前提         |
| **周期预约**   | `/biz/recurrences`      | 熟客固定档期自动生成预约                           |
| **工作台授权** | `/biz/app-staff-grants` | 审批美甲师手机上的工作台                           |

## 谁来用（适用角色）

| 谁         | 用哪部分                                                            | 权限要点                                           |
| ---------- | ------------------------------------------------------------------- | -------------------------------------------------- |
| **前台**   | 预约管理（开单 / 到店 / 完成 / 改期 / 取消 / 收款）、排班管理（看） | 需要"新建、改期、到店、完成、取消"等按钮权限       |
| **店长**   | 全部，含爽约判定、改价、退款、周期预约、工作台授权                  | 建议给全量业务权限                                 |
| **美甲师** | 手机上的美甲师工作台（看自己的单、点到店/完成）                     | 后台账号需绑定美甲师档案，且**不要**给"看全部预约" |
| **顾客**   | 小程序自助预约与取消                                                | 与后台权限无关                                     |

## 操作路径

后台管理端 → 左侧菜单「美甲预约」→「预约管理 / 排班管理 / 周期预约 / 工作台授权」。

- 预约管理：`/biz/bookings`
- 排班管理：`/biz/schedules`
- 周期预约：`/biz/recurrences`
- 工作台授权：`/biz/app-staff-grants`

## 分步操作：一天的营业动线

### 开门前

1. 打开「预约管理」，页面默认筛的就是**今天**。逐行看今天的单：几点、哪位美甲师、什么项目、收了多少、还差多少；
2. 有临时请假或调班，到「排班管理」加日期例外；
3. 提醒今天上班的美甲师打开小程序工作台，核对"今日班次"。

### 营业中

4. **顾客自己约的单**是"待确认"状态。核实后点「确认」，或直接等顾客到店；
5. **顾客上门/来电要约**时，点「新建预约」：搜索顾客 → 选 1~3 个项目 → 选美甲师和日期 → 查询可约时段 → 选时间 → 收款（全款或定金）→ 提交。前台代录的单子直接是"已确认"；
6. **顾客到店**：美甲师在工作台点「已到店」，或前台在预约管理点「到店」图标；
7. **服务做完**：点「完成服务」。系统立刻累计到店次数、计提提成、给顾客发完成通知与评价邀请；
8. **收尾款**：点「结算 / 收尾款」，可以一次用多种方式收款（例如储值余额 + 现金）；
9. **要改时间**：点「改期 / 改美甲师」，重新查时段后确认；
10. **顾客不来了**：点「取消」（需填原因）；**顾客没来**：点「爽约」（需填原因）；
11. **要退钱**：点「发起退款」，填原因、确认退款去向。服务开始前提交即全额退回；服务开始后由店长填写金额后执行。

### 关门后

12. 把当天已到店未完成的单全部点「完成服务」（否则系统会在每 10 分钟一次的自动检查里替你完成，但提成与到店次数会按预约结束时间计入）；
13. 用「资金状态」筛"未收款 / 部分收款"，把该收的尾款收掉；
14. 检查现金与线下收款是否都记了账；
15. （店长）处理退款申请，检查当天是否有周期预约的冲突提醒。

## 单据的两种状态

每一张单有**两个独立的状态**，看单时要同时看。

### 服务状态（这个顾客的服务进行到哪一步）

| 状态        | 界面显示 | 含义                           | 占不占用时段 |
| ----------- | -------- | ------------------------------ | ------------ |
| `pending`   | 待确认   | 顾客在小程序提交，门店还没确认 | **占用**     |
| `confirmed` | 已确认   | 时间已经定下来了               | **占用**     |
| `arrived`   | 已到店   | 顾客已经到了，正在做           | **占用**     |
| `completed` | 已完成   | 服务做完，提成已计提           | 不占用       |
| `cancelled` | 已取消   | 门店或顾客取消（有原因）       | 不占用       |
| `no_show`   | 爽约     | 顾客没来（有原因）             | 不占用       |

允许的动作顺序（点错会被拒绝）：

```
待确认 ──确认──▶ 已确认 ──到店──▶ 已到店 ──完成──▶ 已完成
   │                │
   └──取消──▶ 已取消  ├──取消──▶ 已取消
                     └──爽约──▶ 爽约
```

> 💡 **为什么"待确认"也占时段**：顾客已经在小程序上选走了这个时间，如果不等确认就不占，门店会被同一个人重复约走两个时段。所以三种"还没结束"的状态都会占用时段。

### 资金状态（这一单的钱收得怎么样）

| 状态       | 界面显示 | 含义                                             |
| ---------- | -------- | ------------------------------------------------ |
| `unpaid`   | 未收款   | 一分钱都还没收（小程序自助预约的单子默认是这样） |
| `partial`  | 部分收款 | 收过定金，尾款还没收                             |
| `paid`     | 已结清   | 应收全收齐了                                     |
| `refunded` | 已退款   | 退过款                                           |
| `credit`   | 挂账     | 钱没收到，记成了应收（谁欠的记在"应收台账"里）   |

界面上的「已收 / 尾款」列会同时显示两个数：已经收了多少、还差多少。差额是红色的。

## 可约时段是怎么来的

「查询可约时段」不是查一张现成的空位表，而是现场算出来的：

```
当天班次（排班） − 已有预约（含缓冲） = 能约的时间点
```

- 时间点按**可约时段粒度**（默认 15 分钟）排列，例如 10:00、10:15、10:30；
- 一个时段要能**完整**装下这单的总时长（多个项目的时长相加），装不下就不出现；
- 与前后的已有预约之间，还要留出**缓冲时间**（取这单和对方当中较大的那个）；
- 顾客自己约有**最少提前量**（默认 60 分钟），前台当场开单没有这个限制。

查不到时段时，页面会直接告诉你原因：

| 提示                     | 意思                                 | 怎么办                       |
| ------------------------ | ------------------------------------ | ---------------------------- |
| 该美甲师当天请假         | 那天加了"整天休息"的日期例外         | 换日期或换美甲师             |
| 该美甲师当天没有排班     | 周模板里那天本来就是休息             | 换日期，或先去排班管理配班次 |
| 该美甲师不能做所选项目   | 可做项目白名单里没有这个项目         | 换美甲师，或调整项目         |
| 当天已约满               | 没有能装下所选总时长的空档了         | 换日期、换美甲师，或减少项目 |
| 超出了允许提前预约的窗口 | 超过"最多提前预约天数"（默认 30 天） | 换更近的日期                 |

> 💡 **缓冲时间是什么、为什么要有**：两单之间需要收工具、消毒的时间。它不占顾客看到的时间，但会让两单之间自动空出间隔。多个项目一起做时，**时长相加、缓冲取最大值**。

## 系统自己会做的事（定时任务）

有些动作不需要人点，系统按固定节奏自己执行：

| 时间节奏        | 系统做什么                                                                     |
| --------------- | ------------------------------------------------------------------------------ |
| 每 10 分钟      | 把"已到店"且已经过了结束时间的单，自动改成"已完成"                             |
| 每 10 分钟      | 把"已确认"且超过容忍期（默认开始时间后 15 分钟）还没点到店的单，自动改成"爽约" |
| 每分钟          | 关闭已经过期的在线收款单（默认 5 分钟有效期）                                  |
| 每 2 分钟       | 主动向支付渠道查询还没付的在线收款单（防止"顾客付了但没通知到"）               |
| 每天 18:00      | 给第二天有预约的顾客发到店提醒                                                 |
| 每天凌晨 3:15   | 按周期预约规则滚动生成未来的预约                                               |
| 每天 6:30       | 拉取支付渠道账单做对账                                                         |
| 每 5 分钟       | 重试发送失败的通知                                                             |
| 每月 1 日 01:10 | 把逾期的应收标记出来                                                           |

这些任务可以在「系统管理 → 定时任务」里看到与手动触发，详见 [系统管理](../admin/index.md)。

## 使用注意事项

> ⚠️ **顾客到了必须点「到店」。** 触发条件：单子是"已确认"，到了开始时间后容忍期（默认 15 分钟）仍无人点「到店」。后果：系统自动记"爽约"，顾客档案上的履约记录变差，而且事后只能靠新建单据纠正。正确做法：顾客一进门就由美甲师（工作台）或前台（后台）点「到店」。

> ⚠️ **"完成"会立刻计提成，别提前点。** 触发条件：服务还没做完就点「完成服务」。后果：提成当场计入，之后如果顾客取消，冲销提成受限制（已结算的提成不能冲销）。正确做法：等服务真正结束再点。顺便说一句：**美甲师在小程序上提前点会被拒绝**（系统提示"服务尚未开始"），但后台没有这道时间护栏，全靠自觉。

> ⚠️ **取消、爽约必须填原因，而且原因顾客能看到。** 触发条件：点「取消」或「爽约」时不写原因。后果：系统直接拒绝提交；写了不合适的措辞，会显示在给顾客的取消通知里。正确做法：写客观原因，例如"顾客临时有事"、"顾客未按时到店"。

> ⚠️ **取消不等于退款。** 触发条件：这一单已经收过钱（比如定金），点了「取消」。后果：单子变成"已取消"，但钱还在账上，系统只给一句提醒，**不会自动退**。正确做法：到「发起退款」提交退款（服务开始前提交即执行全额退；服务中由店长填金额后执行）。

> ⚠️ **"软删"只用于清理误录，不用于日常作废。** 触发条件：对有实收的单子点删除。后果：系统拒绝，必须先走完退款。正确做法：正常作废用「取消」或「爽约」，删除只用来清掉录错的空单。

> ⚠️ **同一顾客同一时段重复录单会被拦。** 触发条件：给同一位顾客在重叠时间开两张单。后果：系统弹出"该顾客此时段已有预约"的清单并拒绝。正确做法：确认是不是手滑重复录；如果确实是两个人同时给同一位顾客做项目，可以点"确认强制创建"。

> ⚠️ **改了项目或价格不会改历史单。** 触发条件：调整服务项目的时长、缓冲或价格。后果：历史单子里保存的是**当时的**项目名、时长和价格，不会跟着变。正确做法：涨价前先把当天未完成的单处理掉，避免同一时段不同价。

## 常见问题

**Q：预约管理有没有日历 / 时间轴视图？**
A：目前只有列表 + 筛选 + 状态流转，没有日历时间轴。看一天安排请在"按单日"模式下按时间排序查看。

**Q：为什么列表里看不到某位美甲师今天的单？**
A：筛选项里的"美甲师"没有选中他，或者你的账号被限制成了"只能看自己的单"。详见 [角色与权限](../guide/roles.md)。

**Q：顾客在小程序约的单为什么是"待确认"、也没收钱？**
A：小程序端按设计不收款，到店结算。门店可以点「确认」把它变成"已确认"，也可以直接等顾客到店。

**Q：已经过了时间的单子怎么还挂在"已确认"上？**
A：系统每 10 分钟检查一次，超过容忍期会自动改"爽约"。如果刚过几分钟还没变，等下一次检查即可。

**Q：一天最多能约几个项目？**
A：一张单最多 1~3 个项目。

**Q：能不能给同一位顾客在同一个时间约两位美甲师？**
A：可以，需要分别开两张单，并且第二张会遇到"该顾客此时段已有预约"的提示，确认后强制创建。
