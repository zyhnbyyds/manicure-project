## 这个模块解决什么问题

这套系统解决的是一件很具体的事：**把"顾客想约某个美甲师的某个时间"这件事，从口头/微信里的一句话说清楚，并且从建档一路管到收钱、评价和提成。**

在没有系统之前，常见的麻烦是：

- 一天里谁几点有空、谁在忙，靠脑子记，容易撞单；
- 定金收了没、尾款还差多少，靠翻微信记录；
- 熟客每周固定时间来，每次都要重新录一遍；
- 月底算谁做了多少、该发多少提成，靠翻本子。

系统把这些都落到三端里：**顾客自己约、美甲师自己打卡、门店统一收钱算账。**

## 谁来用（三个客户端分别给谁）

| 客户端               | 给谁用     | 怎么打开                       | 能不能互相替代                         |
| -------------------- | ---------- | ------------------------------ | -------------------------------------- |
| **后台管理端**       | 店长、前台 | 电脑浏览器登录后台账号         | 不能。建档、排班、收款、报表只有这里有 |
| **微信小程序顾客端** | 顾客       | 微信打开小程序                 | 不能。顾客只能看自己的单和账           |
| **美甲师工作台**     | 美甲师     | 微信小程序内切换到"工作台模式" | 不能。只能看**本人**的单，看不到别人的 |

> 💡 **一句话分工**：后台是"店里的账本 + 排班表"，小程序是"顾客的自助服务窗口"，工作台是"美甲师自己的排班卡 + 打卡机"。

三个客户端共用同一份数据：顾客在小程序约的时段，后台立刻能看到；美甲师在工作台点的"已到店"，后台的预约状态同时变成"已到店"。

## 一条预约的完整旅程

下面是一条预约从无到有的全部环节。每一步都标了"谁做、在哪里做"，照着这条线看后面的模块页会很容易。

### 第 0 步：开门前的准备（一次性）

1. **建服务项目**：后台「美甲预约 → 服务项目」。每个项目要填**时长**（决定占用多久）、**缓冲**（两单之间的最小间隔）、**价格**。示例：纯色美甲 60 分钟、缓冲 15 分钟、88 元。
2. **建美甲师档案**：后台「美甲预约 → 美甲师」。填昵称、电话、简介；可以在详情里配置**可做项目**。**不配置 = 可做全部项目**，这是新建美甲师的默认状态。
3. **排班**：后台「美甲预约 → 排班管理」给每位美甲师配**周模板**（例如周二到周日 10:00–19:00），有请假或加班再单独加**日期例外**。
4. **建顾客档案**：后台「美甲预约 → 顾客档案」。**手机号是唯一的**，同号不能建两个顾客。
5. **分配账号与权限**：后台「系统管理 → 用户管理 / 角色管理」，给店长和前台各一个账号。

### 第 1 步：顾客预约（顾客自己约，或前台代录）

**顾客自己约**（微信小程序）：

1. 挑服务项目 → 挑美甲师 → 挑日期 → 点查询，系统列出当天真正能约的时间；
2. 选一个时间点提交。这时候单子的状态是**待确认**，并且**没有收任何钱**；
3. 门店在后台看到后点「确认」；也可以直接约到店再收钱。

**前台代录**（后台「预约管理 → 新建预约」）：

1. 搜索并选择顾客（**开单前必须先有顾客档案**）；
2. 选 1~3 个服务项目，系统实时累加时长与价格；
3. 选美甲师和日期，点「查询可约时段」，从列出的时间里选一个；
4. 选收款方式：**收全款**或**收定金**（定金留空时按默认定金比例 30% 计算）；
5. 提交。前台代录的单子**直接就是"已确认"**。

> 💡 **定金与尾款**：定金是"先收一部分把时间占住"，剩下的叫尾款，到店做完再收。定金比例默认 30%，可以在参数配置里改。示例：应付 88 元，默认定金 26.4 元，尾款 61.6 元。

### 第 2 步：顾客到店打卡

**美甲师**在小程序工作台里点「已到店」，或者**前台**在后台「预约管理」里点「到店」图标。单子从"已确认"变成"已到店"。

> ⚠️ **这一步绝对不能忘**。系统会定时把"已确认但超过容忍期还没到店"的单子**自动记为爽约**（默认容忍期 15 分钟，从预约开始时间算起）。顾客明明来了、你却忘了点，单子就会被记成爽约，影响顾客档案里的记录。

### 第 3 步：服务完成

做完项目后，美甲师在工作台点「完成服务」，或前台在后台点「完成服务」。单子变成"已完成"，同时系统马上做三件事：

- 给顾客档案**加一次到店次数**、更新最近到店时间；
- **计提这一单的提成**（金额按提成规则算，进入"待发"）；
- 给顾客发一条完成通知，附带评价邀请。

### 第 4 步：结算收尾款

到「预约管理」某一行点「结算 / 收尾款」，或者在「收银台」处理。系统会显示：应付多少、已收多少、还差多少。可以**一次用多种收款方式**（例如一半储值余额 + 一半现金），也可以整单挂账。

### 第 5 步：评价与算账

- 顾客在小程序里对已完成的单子评价一次（一单一评），门店在「评价管理」里可以回复、隐藏；
- 美甲师在小程序工作台的"我的评价"里看到**已公开**的评价和平均评分；
- 月底在「报表中心」「提成结算」里看收入与提成，把待发的提成结算掉。

## 字段说明

这里只解释四个全局口径，各模块的字段见对应页面。

| 概念         | 必填   | 说明                                                                                   | 弄错会怎样                                                     |
| ------------ | ------ | -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 店内本地时间 | —      | 系统内部按统一时刻保存，展示时一律换算成**门店所在时区**的墙上时间（默认中国标准时间） | 门店时区配错，所有时段会整体偏移，约到"看得到但不对"的时间     |
| 营业日       | —      | 每天的生意从**门店本地时间的凌晨 0 点**算起，到次日 0 点为止                           | 凌晨之后的单子会被算进新的一天，对日结报表时注意口径           |
| 缓冲时间     | 建议填 | 项目前后预留的收拾/消毒时间，**不占用顾客看到的时间**，但会参与"能不能排得下"的判断    | 缓冲填 0，两个顾客之间会紧贴，实际做不完；填太大，可约时段变少 |
| 时长         | 必填   | 项目实际占用美甲师的时间；一单多个项目时**相加**                                       | 时长填短了会连环迟到；填长了可约时段变少                       |

## 使用注意事项

> ⚠️ **一单多个项目时，时长相加、缓冲取最大值。** 例如"纯色美甲 60 分钟 + 卸甲 30 分钟"按 90 分钟排，缓冲取两者中较大的那个（15 分钟）。不要以为缓冲也会相加。

> ⚠️ **可约时段是"算出来"的，不是一张固定表。** 它等于：当天班次 − 已有预约占用 − 缓冲。所以同样的日期，换个美甲师、换个项目组合，能约的时间都不一样。查不到时段时，系统会给出原因（请假 / 没排班 / 该美甲师不能做所选项目 / 已约满 / 超出可提前预约的天数），请照着原因处理，不要反复重试。

> ⚠️ **取消预约不会自动退钱。** 取消后如果这单已经收过钱（比如收过定金），系统会提示你去「退款审批」发起退款。退款需要店长审批通过才真正退，且必须填原因。

> ⚠️ **排班和主数据改动会被"既有预约"拦住。** 给某天加请假、缩短班次、停用项目或美甲师时，只要会让已有的未完成预约"落在班次之外"，系统就会弹出受影响的单号清单并拒绝保存。**这是有意设计的保护**，不是故障。

## 常见问题

**Q：顾客在小程序约了单，为什么后台一分钱都没收到？**
A：小程序提交的单子按设计**不收款**，状态是"待确认"、资金状态是"未收款"，到店做完再由门店收。这是正常流程。

**Q：顾客明明到店了，为什么显示"爽约"？**
A：因为没有人点「到店」。系统在预约开始时间超过容忍期（默认 15 分钟）后会把"已确认"的单子自动记为爽约。请让美甲师一到店就点「已到店」。

**Q：为什么我在后台看不到别的美甲师的单？**
A：如果你负责的美甲师档案绑定了你这个后台账号，系统会把你的可见范围**收窄到你自己名下**；需要看全店时，让店长给对应角色加"看全部预约"的权限。详见 [角色与权限](./roles.md)。

**Q：顾客自己在小程序能改时间吗？**
A：顾客可以自己取消（需填原因），改时间请让顾客取消后重新约，或由门店在后台「改期」。
