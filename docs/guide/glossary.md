# 术语表

> 💡 这一页是「店里的人和系统说同一种话」的字典。遇到看不懂的词，先来这里查；查不到再问客服或技术同事。

## 怎么用这一页

- 按主题分组，组内按「你会先遇到哪个词」排序。
- 「界面上显示」列写的是后台里真实看到的中文，方便你对照屏幕。
- 一句话说不清的，在「提醒」列补了一句最容易踩的点。
- 金额相关的一律以「元」为单位举例。

## 一、预约与到店状态（状态机）

一张预约单在系统里的「人生阶段」。它只能按顺序往前走，不会跳级。

| 名词   | 界面上显示 | 一句话解释                                             | 提醒                                           |
| ------ | ---------- | ------------------------------------------------------ | ---------------------------------------------- |
| 待确认 | 待确认     | 单子建好了，还没最终敲定（例如等顾客回复、等门店确认） | 这个状态的单子**不计**任何业绩                 |
| 已确认 | 已确认     | 时间、美甲师都定了，顾客会来                           | 新预约默认就是「已确认」                       |
| 已到店 | 已到店     | 顾客已经进店，开始做                                   | 服务时间过后系统会自动把它变成「已完成」       |
| 已完成 | 已完成     | 服务做完了                                             | **只有这个状态才计单量、才计提成**             |
| 已取消 | 已取消     | 单子作废了（顾客取消或门店取消）                       | 取消必须能说清原因；已收的钱要另外走退款       |
| 爽约   | 爽约       | 到点了顾客没来，过了容忍期系统自动标记                 | 爽约会记到顾客档案里；已收定金是否退要另行处理 |

**状态之间的常见走法**

```
待确认 → 已确认 → 已到店 → 已完成
                 ↘ 已取消
                 ↘ 爽约
```

## 二、钱的状态（收款 / 支付 / 退款）

| 名词                                          | 界面上显示             | 一句话解释                                   | 提醒                                               |
| --------------------------------------------- | ---------------------- | -------------------------------------------- | -------------------------------------------------- |
| 未收款                                        | 未收款                 | 这单一分钱都还没收到                         | 报表上不计营收                                     |
| 部分收款                                      | 部分收款               | 收了一部分（例如只收了定金），还差尾款       | 收银台会把它列进「待收尾款」队列                   |
| 已结清                                        | 已结清                 | 该收的钱都收齐了                             | 这是收银台的目标状态                               |
| 已退款                                        | 已退款                 | 已经退过钱（可能全退也可能部分退）           | 退款会冲减退款当天的营收                           |
| 挂账                                          | 挂账                   | 这单先欠着，不付钱（记在挂账主体名下）       | **下单时不计营收**，销账那天才计入                 |
| 定金                                          | 定金                   | 预约时先付的一部分钱                         | 默认按订单金额的 30% 收（参数可调）                |
| 尾款                                          | 尾款                   | 到店后补付的剩余部分                         | 尾款没结清的单，完成时系统会提醒催收               |
| 待支付                                        | 待支付                 | 在线收款单已生成，顾客还没扫码付             | 二维码默认 5 分钟失效，超时自动关闭                |
| 成功                                          | 成功                   | 这笔钱确实收到了                             | 只有「成功」的支付单才算实收                       |
| 已关闭                                        | 已关闭                 | 超时未支付，系统把单据关掉了                 | 关单只是作废，不代表没收过钱                       |
| 已全额退款                                    | 已全额退款             | 这笔支付单的钱全退回去了                     | 它当初收的钱仍然算在「毛收入」里                   |
| 部分退款                                      | 部分退款               | 只退了一部分                                 | 同上，退款额单列                                   |
| 待审批                                        | 待审批                 | 升级前的老状态：退款申请已提交，等店长点头   | 新流程**建单即执行**，只在历史数据里会遇到         |
| 已通过                                        | 已通过                 | 店长同意了，退款正在执行                     | —                                                  |
| 已驳回                                        | 已驳回                 | 店长不同意退                                 | 会记录驳回原因                                     |
| 已退款成功                                    | 已退款成功             | 钱真的退回去了                               | 这一刻才冲减营收                                   |
| 退款失败                                      | 退款失败               | 退款动作执行失败                             | 需要人工排查（例如原路退回失败）                   |
| 原路退回                                      | 原路退回               | 钱按原支付渠道退回去                         | 线上收款默认走这个                                 |
| 现金退                                        | 现金退                 | 现场给顾客现金                               | 适合线下收的现金                                   |
| 退入余额                                      | 退入余额               | 不退现金，退到会员余额里                     | 顾客以后还能在店里用                               |
| 判责扣减                                      | 判责扣减               | 老口径：按取消时间等规则，退的钱里扣掉一部分 | 现已不按规则扣减（服务开始前全额退、服务中店长定） |
| 责任（店家/顾客/不可抗力）                    | 店家 / 顾客 / 不可抗力 | 这笔损失算谁头上                             | 用于统计与复盘                                     |
| 对账差异                                      | 对账差异               | 系统记的钱和支付渠道账单对不上               | 必须填写处理备注，**不允许静默忽略**               |
| 金额不一致 / 系统缺单 / 渠道缺单 / 状态不一致 | 同左                   | 四种对不上的情形                             | 「渠道缺单」通常还没到账，稍后再看                 |

## 三、顾客的资产（余额 / 次卡 / 积分 / 券）

| 名词     | 界面上显示         | 一句话解释                             | 提醒                                   |
| -------- | ------------------ | -------------------------------------- | -------------------------------------- |
| 本金     | 本金               | 顾客真金白银充进来的钱                 | 本金可退（按门店退款规则）             |
| 赠送余额 | 赠送               | 充值活动额外送的钱                     | **赠送不可退、不可提现**               |
| 余额     | 余额 / 结存        | 本金 + 赠送，顾客现在还能花多少        | 扣减顺序默认「先扣赠送」               |
| 充值     | 充值               | 顾客把钱存进会员账户                   | 充值算**预收款**，不算营收             |
| 冲正     | 冲正 / 退款        | 把充错的金额改回去（需填原因）         | 属于敏感操作，默认只给店长             |
| 次卡     | 次卡               | 一次买断、分多次用的卡（例如 10 次卡） | 买卡那天收钱，用的时候不再收钱         |
| 次卡核销 | 核销               | 用次卡做了一次服务，扣掉一次次数       | 核销时支付单金额记 **0**，但计次数     |
| 撤销核销 | 撤销               | 核销弄错了，撤销这一次                 | 会生成负数的核销记录                   |
| 生效中   | 生效中             | 次卡还能用                             | —                                      |
| 已用完   | 已用完             | 次数用完了                             | 还能看到历史核销记录                   |
| 已过期   | 已过期             | 超过有效期了，不能再核销               | 系统每天 00:05 自动标记                |
| 已退卡   | 已退卡             | 卡退了钱                               | 需要权限，默认只给店长                 |
| 积分     | 积分               | 消费攒的分，可以抵钱或换东西           | 默认「消费 1 元得 1 分」               |
| 积分发放 | 发放               | 消费后系统给顾客加分                   | —                                      |
| 积分抵扣 | 抵扣               | 结账时用积分抵掉一部分钱               | 单笔有抵扣上限（默认 30%）             |
| 积分兑换 | 兑换               | 用积分换一张体验卡之类的实物权益       | 兑换品在「积分兑换品」里维护           |
| 优惠券   | 优惠券             | 一张有面额、有门槛、有有效期的抵扣券   | 券模板可启停                           |
| 会员等级 | 银卡 / 金卡 / 钻卡 | 按累计消费自动升级的档位               | 等级只影响折扣，与余额无关             |
| 折扣率   | 95 折 / 9 折       | 会员等级带来的价格优惠                 | 系统内部用千分比记录，页面上显示成折扣 |
| 累计消费 | 累计消费           | 顾客历史上一共花了多少                 | 只用于算等级，**不要**拿它当营收       |

## 五、报表与提成

| 名词           | 界面上显示            | 一句话解释                                      | 提醒                                     |
| -------------- | --------------------- | ----------------------------------------------- | ---------------------------------------- |
| 净营收         | 净营收                | **成功收到的钱 − 成功退掉的钱**                 | 报表里唯一和银行到账对得上的数           |
| 毛收入（实收） | 毛收入(实收) / 实收   | 只算收到的钱，不减退款                          | 与净营收的差额就是退款                   |
| 客单价         | 客单价                | 净营收 ÷ 完成单量                               | 跨日单会让单日客单价略失真               |
| 完成单量       | 完成单量              | 状态为「已完成」的预约数                        | 按服务开始时间归到营业日                 |
| 营业日         | —                     | 系统用来切分「今天/昨天」的那一天               | 目前就是店内自然日 00:00–24:00           |
| 新客           | 新客数                | 第一次来店的顾客                                | 按「首次完成」判定                       |
| 回头客         | 回头客数              | 以前来过、这次又来了的顾客                      | 同一个人多次只算 1 人                    |
| 次卡核销占比   | 次卡核销占比          | 这个项目里有多少次是用卡的                      | 卡的部分金额为 0，所以占比高不等于不赚钱 |
| 销账实收       | 销账实收              | 收到的钱里有多少来自挂账销账                    | 它是毛收入的一部分，别和渠道列相加       |
| 分摊           | 净营收分摊            | 把一张单的钱按项目原价比例分到各项目/美甲师头上 | 向下取整，差额留在单头                   |
| 计提           | 计提 / 计提中         | 系统先「记账」该给美甲师多少提成                | 一提单里每个项目一条记录                 |
| 计提基数       | 计提基数              | 用来乘提成比例的那个金额                        | 默认是实收（不是原价）                   |
| 提成比例       | 比例(‰)               | 千分比，`100` = 10%                             | 填错会差 10 倍                           |
| 固定额         | 固定额                | 每个项目固定提成多少元                          | 可以和比例同时生效                       |
| 结算           | 结算 / 已结算         | 把这段时间的提成锁定、生成批次号准备发钱        | 结算后不可修改                           |
| 结算批次       | 结算批次              | 形如 `S202609001` 的发钱凭证号                  | 方便和工资表对应                         |
| 冲销           | 已冲销                | 把这笔提成作废（不删除，留痕）                  | 只有「计提中」的能冲销                   |
| 命中规则       | 命中规则 / 未配置规则 | 这笔提成是用哪条规则算的                        | 显示「未配置规则」= 没提成               |

## 六、通知

| 名词     | 界面上显示             | 一句话解释                                                 | 提醒                                     |
| -------- | ---------------------- | ---------------------------------------------------------- | ---------------------------------------- |
| 通知模板 | 通知模板               | 通知的文字模板，用 `{变量}` 挖空                           | 用了没声明的变量保存会被拒               |
| 变量     | 变量清单               | 模板里要填进去的数据，例如顾客姓名                         | 名字必须与系统提供的完全一致             |
| 站内消息 | 站内                   | 只在系统里留一条，不进顾客手机                             | 后台目前没有未读小铃铛，去「通知记录」看 |
| 短信渠道 | 短信                   | 真正发到顾客手机上的那种                                   | 要花钱，且要报备模板                     |
| 待发送   | 待发送                 | 记录已生成，还没投递                                       | 正常会很快变成成功/失败                  |
| 成功     | 成功                   | 已交给短信网关或已写入站内                                 | 短信成功不等于顾客一定收到（可能被拦截） |
| 失败     | 失败                   | 投递失败                                                   | 自动重试最多 3 次，可人工重发            |
| 已跳过   | 已跳过（未配置）       | **根本没尝试发**（总开关没开 / 模板不在白名单 / 没手机号） | 不会自动重试                             |
| 渲染     | 渲染后内容             | 把 `{变量}` 替换成真实内容后的最终文字                     | 缺变量会变成空白                         |
| 白名单   | 允许走短信的模板白名单 | 只允许名单里的模板发短信                                   | 逗号分隔填模板编码                       |

## 七、后台基座与权限

| 名词              | 界面上显示 | 一句话解释                                 | 提醒                                   |
| ----------------- | ---------- | ------------------------------------------ | -------------------------------------- |
| 用户              | 用户       | 一个能登录后台的账号                       | 一人一号                               |
| 角色              | 角色       | 一包权限（能看哪些菜单、能点哪些按钮）     | 给员工挂角色而不是逐个配权限           |
| 菜单              | 菜单       | 左侧导航里的一项；分目录 / 菜单 / 按钮三种 | 目录只是分组，按钮是一条权限点         |
| 权限标识 / 权限点 | 权限标识   | 形如 `biz:report:export` 的内部代号        | 前端按钮、后端接口都靠它校验           |
| 按钮权限          | 类型=按钮  | 控制某个按钮显不显示的那条权限             | 没预置的按钮要手工补                   |
| 数据范围          | 数据范围   | 这个角色能看**哪些部门的数据**             | 五种取值，多角色取并集                 |
| 部门              | 部门       | 组织结构，数据范围的落点                   | 用户不设部门时，本部门类范围算不出结果 |
| 岗位              | 岗位       | 职务标签，**不控制权限**                   | 别把它当角色用                         |
| 字典              | 字典       | 全站下拉选项的统一来源                     | 只改标签，别改键值                     |
| 参数配置          | 参数配置   | 门店经营参数（时区、定金比例、短信开关…）  | 改了最多 10 秒生效，不用重启           |
| 内置参数          | 内置=是    | 系统自带的参数                             | 不能删，但能改值                       |
| 在线用户          | 在线用户   | 当前处于登录状态的账号                     | 依赖缓存服务，没配就是空的             |
| 强制下线          | 下线       | 让某人失去续期能力                         | 他手上的登录凭证最长还能用 15 分钟     |
| 操作日志          | 操作日志   | 谁在什么时候调用了哪个接口、成功还是失败   | 追查金额改动的第一现场                 |
| 登录日志          | 登录日志   | 谁尝试登录过、成功还是失败                 | 失败统一提示「用户名或密码错误」       |
| 定时任务          | 定时任务   | 系统按点自动干的活                         | 只改状态与等级，**不碰钱**             |
| 处理器            | 处理器     | 任务要执行的那段内置动作名                 | 只能从白名单里选                       |
| 幂等              | —          | 同一个动作重复执行多次，结果和做一次一样   | 所以手工补跑任务是安全的               |
| 审计              | —          | 把所有关键动作留痕，事后可追               | AI 的操作也会留痕                      |
| 数据脱敏          | —          | 展示前把敏感信息遮掉                       | AI 工具返回的数据会先脱敏              |

| 名词       | 一句话解释                                                  |
| ---------- | ----------------------------------------------------------- |
| 缓冲时间   | 两个预约之间留出的收拾/换场时间，不排给顾客                 |
| 可约时段   | 系统算出来的、可以下单的时间点（班次 − 已有预约 − 缓冲）    |
| 周模板     | 美甲师每周固定的上下班时间，用来生成可约时段                |
| 日期例外   | 某一天和平时不一样（请假、加班），优先于周模板              |
| 周期预约   | 按「每周几 + 时间」自动重复生成的预约                       |
| 冲突策略   | 周期预约生成时撞上已有单怎么办：跳过 / 通知店员             |
| 扫码轮询   | 收银台每隔几秒问一次「顾客付了没」                          |
| 主动查单   | 回调丢了时，系统主动去问渠道「这笔到底成没成」              |
| 关单       | 把超时未支付的在线收款单作废                                |
| 首单/复购  | 顾客第一次消费 / 第二次及以后消费，报表里体现为新客与回头客 |
| 评价可见性 | 评价可以在前台公开展示，也可以隐藏（处理恶意评价）          |
| 一单一评   | 一张预约只能评价一次                                        |
| 代录       | 顾客当面口述，店员替他把评价录进系统                        |
