title: 角色与权限：谁能看到什么、能点什么

## 这个模块解决什么问题

系统里每个人的**可见范围**和**可点按钮**都由"角色"决定。这一页告诉你：

- 四种使用者（店长 / 前台 / 美甲师 / 顾客）各自应该能做哪些事；
- 后台的"权限"到底控制了什么（菜单看得见 vs 按钮点得动 vs 只能看自己的）；
- 配权限时最容易配错、配漏、配过头的地方。

## 谁来用（适用角色）

| 谁 | 该不该碰权限 |
| --- | --- |
| **店长** | 应该。本页主要就是给店长的操作依据 |
| **系统管理员 / 技术人员** | 只在初始化时帮忙建账号，日常授权由店长做 |
| **前台 / 美甲师** | 不该碰。发现自己少看到了什么，找店长加 |
| **顾客** | 与后台权限无关，顾客只有小程序的顾客模式、看不到门店账目 |

## 操作路径

后台管理端 → 左侧菜单「系统管理」→「用户管理」（建账号）、「角色管理」（建角色、勾权限）、「菜单管理」（看系统里有哪些页面和按钮权限），或直接访问 `/system/users`、`/system/roles`。

美甲师工作台的"开通"不在用户管理里，而在「美甲预约 → 工作台授权」，或直接访问 `/biz/app-staff-grants`。

## 分步操作

### 第一步：先建"角色"，不要把权限直接挂到人身上

系统初始化时只有两个角色：**超级管理员**和**普通用户**。除超级管理员外，其余角色都要自己建。

建议至少建 3 个：**店长、前台、美甲师**。

1. 进入「角色管理 → 新增角色」，填角色名称（如"前台"）和标识、排序；
2. 勾选这个角色能访问的**菜单**（页面）与**按钮权限**；
3. 保存后回到「用户管理」，新建用户并把角色分配给他。

> 💡 **菜单权限与按钮权限的区别**：勾了"预约管理"这个菜单，这个人就能打开预约页面；但页面里的"改价""结算""取消"这些**按钮**是单独的权限点。只勾菜单不勾按钮，他会看到页面但点不动关键操作。

### 第二步：按下面这份推荐清单分配

#### 店长（建议全部业务权限）

- 门店经营：服务项目、美甲师（含"可做项目"）、排班管理、顾客档案
- 预约：预约管理**全部按钮**（含"看全部预约"、"改价"、"取消"、"爽约"、删除）
- 钱：收银台（收款、关单）、退款审批（**审批**）、支付流水、支付对账、挂账主体、应收台账（销账）
- 会员：会员等级、充值方案、次卡卡种、会员管理（充值 / 冲正退款 / 发券 / 发卡核销）、会员次卡
- 运营：评价管理（回复 / 隐藏）、周期预约、通知模板与通知记录
- 看数：报表中心（含导出）、提成规则、提成结算
- 授权：工作台授权（审批美甲师的开通申请）
- 建议同时给：参数配置、用户管理、角色管理（否则改价格、加店员都要找技术）

> 💡 **为什么"充值"和"退款审批"建议只给店长**：这两件事都是直接动钱的口子。给前台"收款"可以，给前台"充值 / 冲正 / 审批退款"风险很大。

#### 前台（干活的人，不给动钱的口子）

- 预约：预约管理里的**列表、新建、改期、确认、到店、完成、取消、爽约**
- 顾客：顾客档案的新增、修改
- 看：排班管理（**只勾"查看"，不要勾"修改"**）、美甲师（只勾查看）
- 钱：收银台的**收款 / 关单**、发起退款申请（申请与审批是两件事，前台只能申请）
- 会员：会员管理的查看与修改（发券、核销次卡），**不给充值、不给冲正退款**
- 评价：评价管理的录入与回复

**不要给前台勾的**：改价、看全部预约（如果前台本身没有被绑定成美甲师，勾不勾都一样，见下方注意事项）、退款审批、提成结算、参数配置、用户/角色管理。

#### 美甲师（只有查看自己和打卡）

- 预约管理：**列表、到店、完成**这三项
- 不勾：新建、改期、取消、爽约、删除、改价、结算、看全部预约
- 不要给：排班管理的"修改"（他改自己的班次也顺手会改到别人的）、任何钱相关的页面

然后到「美甲预约 → 美甲师」，把这位美甲师的档案与他的后台账号**绑定**起来（一个后台账号只能绑一位美甲师）。

> ⚠️ **美甲师角色必须靠"绑定档案"来收窄范围。** 只勾了"列表/到店/完成"还不够：只有在档案里绑定了后台账号之后，系统才会把这位美甲师限制成"只能看自己名下的单"。**同时千万不要勾"看全部预约"**，一旦勾上，收窄就失效，他能看到全店所有人的单子和金额。

#### 顾客（不需要后台账号）

顾客只使用微信小程序的顾客模式：看项目、自己预约与取消、看余额积分次卡、看消息（站内通知）。后台的权限体系与顾客无关，也不要在「用户管理」里给顾客建账号。

### 第三步：给美甲师开通小程序工作台

1. 美甲师自己在小程序「我的」里发起"申请开通工作台"（系统会用他的手机号去匹配在职的美甲师档案）；
2. 店长打开「美甲预约 → 工作台授权」，筛选"待确认"，核对微信身份与匹配到的档案名是否一致；
3. 点勾「通过」，或点叉「驳回」并**必填驳回原因**（申请人会看到这句话）。

开通不等于永久有效：**停用或删除美甲师档案会立刻收回工作台权限**，他下一次打开工作台就会被切回顾客模式并看到提示。详见 [美甲师工作台](../booking/staff-workbench.md)。

## 字段说明

角色与用户页面的字段以系统管理章节为准，这里只解释与"权限"有关的三个概念。

| 概念 | 必填 | 说明 | 弄错会怎样 |
| --- | --- | --- | --- |
| 菜单授权 | 是 | 决定这个人能不能**打开**某个页面（左侧菜单里出不出现） | 不勾=整个页面消失，对方会以为"系统没这个功能" |
| 按钮权限点 | 视页面 | 决定页面里的关键按钮**点不点得动** | 只勾菜单不勾按钮=看得到、点不动，容易被当成故障 |
| 数据范围 | 是 | 决定这个人能看到**谁的数据**（全部 / 仅本人 / 本部门等） | 配成"全部"却给了美甲师，他会看到别人所有单与金额 |
| 美甲师档案绑定 | 否 | 在「美甲师」详情里把档案绑到某个后台账号 | 绑错人=被绑的人只能看到另一个人的单 |

## 使用注意事项

> ⚠️ **改完权限必须让对方重新登录。** 触发条件：你刚给某个角色加了或减了权限，对方还在原来的登录状态里。后果：他看到的还是旧权限（页面刷不出来、按钮还是灰的）。正确做法：让对方退出后重新登录一次。

> ⚠️ **给美甲师勾了"看全部预约"= 收窄失效。** 触发条件：某位美甲师的档案绑定了后台账号，但角色里勾了"看全部预约"这个权限点。后果：他能在「预约管理」里看到并操作全店所有单子（包括别人的金额）。正确做法：美甲师角色一律不勾这一项。

> ⚠️ **"保存"和"保存并删除"这类按钮也可能带权限。** 触发条件：只勾了菜单的"查看"。后果：页面打得开但所有操作都被拒绝，操作日志里都是失败记录。正确做法：按上面的清单逐页勾按钮权限。

> ⚠️ **一个后台账号只能绑定一位美甲师，一位美甲师也只能绑一个账号。** 触发条件：想把两个账号都绑给同一个人，或把一个人的账号绑给两个人。后果：系统直接拒绝。正确做法：共用一台电脑登录时，各自用自己的账号；不要让两个人共用一个账号。

> ⚠️ **"驳回"必须写原因，而且写的话申请人能看到。** 触发条件：驳回了美甲师的开通申请。后果：原因会显示在申请人的小程序上。正确做法：写清楚、别写内部人才懂的简称（例如"手机号与档案不符，请联系店长改成 138xxxx"）。

> ⚠️ **停用美甲师档案 = 立即收回工作台。** 触发条件：在「美甲师」里把某人的状态关掉或删除档案。后果：他手机上下一次请求就被拒绝，工作台自动切回顾客模式。这是有意的，用来处理离职或临时停岗。

## 常见问题

**Q：新店员登录后左侧菜单是空的？**
A：他的角色没有勾任何菜单。找到他的角色，勾上该看的页面（记得连按钮权限一起勾），保存后请他重新登录。

**Q：为什么前台看不到"退款审批"页？**
A：退款审批默认只给店长。前台拿到的通常是"发起退款申请"，入口在预约管理或收银台的退款按钮上，不在左侧菜单。

**Q：为什么某位美甲师登录后台后，只能看到自己名下的单？**
A：这是设计好的保护：他的档案绑定了这个账号，且没有"看全部预约"权限。这正是美甲师该有的样子。

**Q：能给一个账号分配多个角色吗？**
A：可以。多个角色的权限取**并集**（能看能做的合并在一起）。给美甲师同时挂"前台"和"美甲师"两个角色时要注意：并集里如果包含"看全部预约"，收窄仍然会失效。

**Q：顾客要一个后台账号看自己的消费记录行不行？**
A：不建议。顾客的所有自助功能都在小程序里（预约、余额、积分、次卡、消息），后台账号既贵又容易点错东西。
