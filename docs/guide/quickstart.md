## 这个模块解决什么问题

让一家新店**从零配到能正常做生意**。这 7 件事有固定先后顺序：后面的事依赖前面配好的东西，跳着配会卡住。

配完之后，这份页面的最后两节（账号与权限、每天的开店/闭店清单）就是日常要照着走的东西。

## 谁来用（适用角色）

| 谁                        | 负责哪几件                                                             |
| ------------------------- | ---------------------------------------------------------------------- |
| **店长**                  | 全部 7 件，尤其是权限分配、价格、定金比例                              |
| **前台**                  | 日常第 2、3、4 件事的维护（项目、美甲师、排班）以及每天的开店/闭店清单 |
| **系统管理员 / 技术支持** | 只负责第一件里的账号初始化与支付通道开通，不参与日常经营               |
| **美甲师**                | 配合提供手机号（用于匹配档案）与可做项目清单                           |

## 操作路径

配置主要分散在三个地方：

- 经营参数与账号权限：后台「系统管理 → 参数配置 / 用户管理 / 角色管理 / 菜单管理」
- 门店资料：后台「美甲预约 → 服务项目 / 美甲师 / 顾客档案 / 排班管理」
- 钱的通道：后台「美甲预约 → 收银台 / 支付流水」+「系统管理 → 参数配置」

## 分步操作

### 第 1 件：参数配置（先做，10 分钟）

打开「系统管理 → 参数配置」，按门店实际情况改这几项，**保存后最多 10 秒生效**。

- **门店名称**：默认是"美甲店"。所有通知里出现的 `{shopName}` 就是它，请改成真实店名。
- **店内时区**：默认中国标准时间。**国内门店不要改**。
- **可约时段粒度**：默认 15 分钟。意思是顾客能选的时间点只会是 10:00、10:15、10:30 这种整刻。
- **小程序端最少提前预约**：默认 60 分钟，防止顾客"现在立刻约 5 分钟后"。
- **后台代录最少提前预约**：默认 0 分钟。顾客已经坐在店里、前台当场开单时不会被拦。
- **最多提前预约天数**：默认 30 天，即今天最多约到 30 天后。
- **爽约判定容忍期**：默认 15 分钟。**这一项直接影响"忘点到达会不会被记爽约"**，见下方注意事项。
- **默认定金比例**：默认 30%（合同里的写法是 300‰）。示例：应付 88 元 → 默认定金 26.4 元。
- **单次充值下限、充值赠送比例上限、积分抵扣上限**：与会员相关的钱，先按默认，等会员章节看完再调。

### 第 2 件：服务项目（半小时）

打开「美甲预约 → 服务项目 → 新增项目」，把店里真正会做的项目逐个建好。每个项目 4 个关键数字：

- **时长**：这个项目实际占用美甲师多少分钟。示例：纯色美甲 60 分钟。
- **缓冲**：两单之间留出的收拾/消毒时间，示例 15 分钟。**不占顾客看到的时间，但会让两个顾客之间留出间隔。**
- **价格**：单位是元，填 88 就是 88 元。
- **图片**：可以传多张，第一张作为封面；顾客在小程序里看的就是这些图。

> 💡 **缓冲时间是什么、为什么要有**：上一个顾客做完到下一个顾客坐下之间，需要收工具、消毒、擦台面。这段时间不产生收入，但如果设成 0，下一个顾客会紧贴着上一个的时间开始，实际做不完、会连环迟到。系统用它来判断"两单之间排不排得下"。

系统的示例项目（纯色美甲 88 元 / 60 分钟、法式美甲 128 元 / 75 分钟、手部护理 68 元 / 45 分钟等）可以直接改价格继续用，也可以删掉重建。

**已经做过生意的项目不要随便删**：被未完成的预约引用时，系统会拒绝删除并列出单号。

### 第 3 件：美甲师档案与可做项目（半小时）

打开「美甲预约 → 美甲师 → 新增美甲师」：

1. 填**昵称**（顾客在小程序上看到的就是这个）、电话、简介、头像；
2. 「状态」打开表示在职；
3. **电话一定要填对**：美甲师在小程序里申请工作台时，系统是**用手机号去匹配档案**的，填错了就匹配不上；
4. 保存后在列表里点「详情 / 可做项目」配置这个人**会做哪些项目**。

> 💡 **"可做项目"的规则**：**一个都不勾 = 可做全部项目**（新建美甲师的默认状态，适合店长本人）；只要勾了任意一个，就变成"白名单"，**没勾的项目既查不到可约时段、也开不了单**。

### 第 4 件：排班（一小时）

打开「美甲预约 → 排班管理」，先在顶部选一位美甲师，然后在「周模板」标签里编辑每天的班次：

1. 点某一天的编辑按钮，填开始与结束时间（示例 10:00 ~ 19:00）；
2. 一天可以有**多段**（上午 / 下午分开），点「添加时段」再填一段；
3. 某天全天不上班就不用填，列表里会显示"休息"；
4. 点「保存周模板」保存，会给这位美甲师**整体替换**。

有临时请假或加班，切到「日期例外」标签单独加：类型选「请假（整天休息）」或「自定义时段（加班 / 调整）」，填日期和原因。

> ⚠️ **排班保存会被已有预约拦住。** 如果改动会让未来 30 天里已经约好的单子"落在新班次之外"，系统会弹出受影响的单号清单并拒绝保存。正确做法是**先去改期或取消那些单子**，再回来保存。详见 [排班管理](../booking/scheduling.md)。

### 第 5 件：顾客建档规则（10 分钟，主要是讲清规矩）

顾客档案在「美甲预约 → 顾客档案」。前台要记住两条：

- **手机号是顾客的唯一识别**：同一个手机号只能有一个顾客档案，重复新建会被拒绝；
- **开单前必须先有顾客档案**：后台上门开单的弹窗里只能**搜索并选择**已有顾客，不能在弹窗里顺手新建（这是为了避免收银时录错人）。

顾客在小程序里绑定手机号后，系统会自动建/合上他的档案，所以大多数老顾客不需要手建。

如果遇到"这个手机号已经被一个已删除的顾客占用"的提示，说明以前删过这个人，需要先在顾客档案里把他恢复出来，改手机号或直接复用。

### 第 6 件：会员、卡与价格体系（按需，半天）

按需配置，配置顺序建议是：会员等级 → 充值方案 → 次卡卡种。

- 「会员等级」：默认已建好**银卡（不打折）、金卡（95 折，累计消费满 500 元升级）、钻卡（88 折，累计消费满 2000 元升级）**；
- 「充值方案」：默认已建好充 500 送 50、充 1000 送 150、充 2000 送 400（赠送比例不能超过参数里的上限 20%）；
- 「次卡卡种」：默认已建好基础款 10 次卡、款式 5 次卡、全项目 10 次卡等。

等级折扣、储值、次卡、积分、券的完整规则见 [会员与顾客](../member/index.md) 章节（等级与价格口径见 [会员等级](../member/levels.md)）。

### 第 7 件：收钱方式与通知（半天）

1. **收款方式**：日常现金、店主个人收款码收款，用"现金 / 微信（线下）/ 支付宝（线下）"三种方式记账即可，**不需要任何开通**；
2. **顾客扫店里的码付款（在线收款）**：需要先开通微信支付 / 支付宝通道，由技术人员配置。没开通时选择"微信 Native 扫码 / 支付宝当面付"会直接报错，不会产生半截单据；
3. **通知**：系统默认只发**站内消息**（顾客在小程序的"消息"里看，美甲师在工作台的站内消息里看）。要发**手机短信**，需要门店自行开通短信服务，并在参数配置里打开"短信总开关"、把要发的模板加入白名单。

通知模板的措辞在「美甲预约 → 通知模板」里改，发送记录在「通知记录」里查。

### 每天的开店动作清单

- [ ] 打开「预约管理」（默认筛的就是今天），看今天全程的单量、时段、哪位美甲师；
- [ ] 扫一眼有没有"未收款 / 部分收款"的旧单需要催尾款；
- [ ] 确认今天的请假、临时调班已经加进「排班管理 → 日期例外」；
- [ ] 让每位美甲师打开小程序工作台，确认"今日班次"和"今日待服务"都对；
- [ ] 把昨天遗留的退款申请处理掉（店长）。

### 每天的闭店动作清单

- [ ] 把当天已到店、已经做完的单子都点「完成服务」（完成后才会计提成和记到店次数）；
- [ ] 处理"已确认但顾客没来"的单子：点「爽约」并填原因，或等系统自动判（默认开始时间后 15 分钟）；
- [ ] 用「资金状态」筛选"未收款 / 部分收款"，把该收的尾款收掉；
- [ ] 核对当天的现金与线下收款有没有漏记（收了钱一定要在系统里记一笔，否则报表和提成都对不上）；
- [ ] 检查「预约管理 → 备注」里有特殊要求的单子是否都已处理；
- [ ] （店长）审批当天的退款申请，并把待发的提成看一眼。

## 字段说明

以上提到的经营参数都集中在「系统管理 → 参数配置」，默认值如下。

| 配置项（页面上的中文名） | 默认值       | 说明                           | 改错的后果                                             |
| ------------------------ | ------------ | ------------------------------ | ------------------------------------------------------ |
| 门店名称                 | 美甲店       | 通知里的 `{shopName}`          | 顾客收到"欢迎光临美甲店"，显得不专业                   |
| 店内时区                 | 中国标准时间 | 所有时间的换算基准             | 改动后时段显示整体偏移，**国内门店不要动**             |
| 可约时段粒度             | 15 分钟      | 顾客能选的最小时间间隔         | 设得太小（如 5）时段列表很长；太大会约不上心仪时间     |
| 小程序端最少提前预约     | 60 分钟      | 顾客自己约的提前量             | 设 0 会让顾客约到"马上开始"的时段                      |
| 后台代录最少提前预约     | 0 分钟       | 前台当场开单的提前量           | 设成 60 会让坐店的顾客无法立刻开单                     |
| 最多提前预约天数         | 30 天        | 能约到多久之后                 | 设太大会让排班还没配好的远期日期被约走                 |
| 爽约判定容忍期           | 15 分钟      | 开始时间后多久未点到店就算爽约 | 设太小会误伤迟到的顾客；设太大爽约判不出来             |
| 默认定金比例             | 30%          | 定金留空时按应付金额的比例算   | 设 100% 等于必须收全款                                 |
| 多少积分抵 1 元          | 100 分       | 积分抵钱汇率                   | 与顾客预期不符会引起纠纷                               |
| 单笔积分抵扣上限         | 30%          | 一单最多能抵应付的比例         | 设太高会让高积分顾客几乎不花钱                         |
| 充值赠送比例上限         | 20%          | 单笔充值最多送多少             | 建充值方案超过上限时会被拒绝                           |
| 在线支付二维码有效期     | 5 分钟       | 扫码支付的等待时长             | 太长会让"人走了单还挂着"                               |
| 短信总开关               | 关闭         | 短信是否发出                   | 打开但没开通短信服务时，短信会记为"失败"，站内消息照常 |

## 使用注意事项

> ⚠️ **忘记点「到店」= 顾客被记爽约。** 触发条件：单子状态是"已确认"，且已经过了预约开始时间 + 容忍期（默认 15 分钟），期间没有任何人点「到店」。后果：单子被自动改成"爽约"，顾客档案上的履约记录变差。正确做法：顾客一进门就点「到店」（美甲师在小程序、前台在后台都可以点）。

> ⚠️ **改「可约时段粒度」不会重排已有预约。** 触发条件：把 15 分钟改成 30 分钟。后果：已经约在 10:15 这种"非整刻"上的历史单子依然存在，但以后开新单时不能再选 10:15。正确做法：尽量在开店前定好粒度。

> ⚠️ **改项目时长 / 缓冲 / 价格不影响历史单。** 历史单子里已保存了当时的项目名、时长和价格。后果：改价后，昨天的单子金额不会跟着变（这是对的）。正确做法：涨价前先把当天未完成的单子处理完，避免同一时段的顾客发现价格不一致。

> ⚠️ **删项目、停用项目、停用美甲师都会被拦住。** 触发条件：该项目/美甲师身上还有"待确认 / 已确认 / 已到店"的单子。后果：系统拒绝并列出单号。正确做法：先把这些单子改期、完成或取消，再删/停用。

> ⚠️ **不要多人共用 `admin` 账号。** 系统初始化时只有这一个超级管理员账号，密码由部署时设定。所有操作日志、退款审批、提成结算都会记到操作人名下，共用账号等于没人负责。正确做法：登录后立刻改密码，并给每位店员单独开账号、按角色授权。

> ⚠️ **一位美甲师只能绑定一个后台账号。** 一个后台账号也只能绑定一位美甲师，重复绑定会被拒绝。正确做法：先确认这位美甲师确实要用后台，再在档案里绑定。

## 常见问题

**Q：为什么顾客在小程序里选完项目后，有些美甲师根本不出现在列表里？**
A：那位美甲师的可做项目白名单里没有这个项目。要么改项目，要么给他加上这个项目。

**Q：为什么"查询可约时段"是空的？**
A：系统会告诉原因：该美甲师当天请假 / 当天没有排班 / 该美甲师不能做所选项目 / 当天已约满 / 所选日期超出了允许提前预约的窗口。照着原因处理即可，不需要反复重试。

**Q：刚改了参数配置，为什么页面上的行为没变？**
A：配置有约 10 秒的生效延迟。等一下再刷新试。

**Q：今天临时来了一位顾客，前台能当场开单吗？**
A：能。后台代录的提前期默认是 0 分钟，只要当天有班次、时段没被占，就能选一个马上开始的时间。

**Q：顾客在小程序提交后，后台显示"待确认"，需要做什么？**
A：确认时间和项目没问题后点「确认」，或者干脆到店时收钱。不点确认不影响顾客到店，但"待确认"的单子同样占用时段。
