# 通知（模板与站内消息）

> 💡 通知分两种：**短信**（发到顾客手机上）和**站内消息**（只在本系统里留一条记录给店员看）。它们用同一套模板、同一张记录表，区别只在「渠道」字段。

## 这个模块解决什么问题

- 让顾客知道：预约成功、明天要来、服务完成、充值到账。
- 让店员知道：周期预约生成撞单了、生成失败了、应收逾期了。
- 出事能举证：每一条通知都存了**渲染后的最终内容**，模板后来改了也能查到当时到底发了什么。

## 谁来用（适用角色）

| 功能               | 需要什么权限                          | 建议给谁        |
| ------------------ | ------------------------------------- | --------------- |
| 看/改通知模板      | `biz:notice:template`（页面权限同名） | 店长 / 运营     |
| 看通知记录、看详情 | `biz:notice:log`                      | 店长 / 前台主管 |
| 重发单条通知       | `biz:notice:send`                     | 前台主管 / 店长 |

> ⚠️ 如果你的账号没有模板权限，进「通知记录」时模板筛选框会从下拉列表变成手工输入框——这是正常的降级，不影响查看记录。

## 操作路径

- 模板：后台管理端 → 左侧菜单「美甲预约」→「通知模板」，或 `/biz/notice-templates`
- 记录：后台管理端 → 左侧菜单「美甲预约」→「通知记录」，或 `/biz/notice-logs`

## 分步操作

### A. 改一条模板文案

1. 进「通知模板」，用「编码 / 名称」搜索框找到目标模板（也可以按渠道、状态筛）。
2. 点那一行右侧的铅笔图标「编辑」。
3. 弹窗顶部有一排**「插入变量」**快捷按钮，点一下就把变量追加到内容末尾，并自动写进「变量清单」。
4. 在「内容」里写文案，需要填数据的地方用 `{变量名}` 占位。
   - 例：`{customerName}您好，您在{shopName}的预约已确认：{bookingDate} {bookingTime}。`
5. 弹窗下方会实时显示：
   - **内容预览**：已声明的变量用 `【变量名】` 标出来，一眼看出位置对不对。
   - 如果有变量**没在变量清单里声明**，会出红框提示「以下变量未在变量清单中声明，无法保存」，并给出「声明 {xxx}」按钮，点一下就补上。
6. 「渠道」选好：短信 / 站内 / 短信 + 站内。
   - 「标题」是站内消息的标题，短信不看标题，所以发短信的模板标题可以留空。
7. 「状态」保持开启，点「保存」。
8. 保存成功提示「更新成功」。**已经在发出去的历史记录不会被追改**，日志里存的还是当时的文案。

### B. 新建一条模板（很少用，通常用于补系统要用的编码）

1. 点「新增模板」。
2. 填「模板编码」：只能小写字母、数字、下划线，且**全系统唯一**（重复会提示「模板编码 xxx 已存在」）。
3. 填名称、渠道、标题、内容、变量清单，保存。

### C. 查一条通知到底发没发出去

1. 进「通知记录」。
2. 按渠道（短信 / 站内）、状态、模板、发送日期区间筛选，点「查询」。
3. 表格里重点看三列：
   - **状态**：待发送 / 成功 / 失败 / 已跳过（未配置）
   - **渲染后内容**：顾客实际会收到的文字（这是最有用的列）
   - **重试次数**：显示 `3（已达上限）` 说明系统已经放弃自动重试
4. 点左侧眼睛图标「详情」，可以看到手机号、供应商、供应商消息号、错误信息、阅读时间、关联预约等完整信息。

### D. 重发一条通知

1. 在记录行右侧点「重发」（绿色圆形箭头）或在详情弹窗里点「重发」。
2. 二次确认会显示模板编码、接收人、渠道。
3. 点「重发」。成功后提示「已重新发送」，该条记录的「重试次数」会 +1。
4. 人工重发**不受自动重试上限限制**，可以重试第 4 次、第 5 次。

## 字段说明

### 模板表单

| 字段     | 必填 | 说明                                                   | 填错会怎样                                                                       |
| -------- | ---- | ------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 模板编码 | 是   | 唯一标识，小写字母/数字/下划线，例如 `booking_created` | 重复 → 提示已存在；改了编码 → 触发通知的地方会找不到模板，降级成「原始变量通知」 |
| 模板名称 | 是   | 给人看的中文名，例如「预约成功通知」                   | 只影响可读性                                                                     |
| 渠道     | 是   | 短信 / 站内 / 短信 + 站内                              | 选「短信」但短信开关没开 → 记录显示「已跳过」                                    |
| 标题     | 否   | 站内消息的标题；短信不用                               | 短信模板留空即可                                                                 |
| 内容     | 是   | 正文，用 `{变量}` 占位                                 | 用了没声明的变量 → 保存被拒                                                      |
| 变量清单 | 否   | 声明内容里用到的变量名（不含花括号），回车添加         | 漏声明 → 保存被拒（前端实时红框 + 后端也会拒）                                   |
| 状态     | 是   | 启用 / 禁用                                            | 禁用 = 模板失效，通知会降级成「原始变量通知」                                    |
| 备注     | 否   | 给自己的说明                                           | —                                                                                |

| `{bookingNo}`     | 预约单号   |
| `{bookingTime}`   | 预约时间   |

| `{points}`        | 积分       |
| `{cardName}`      | 次卡名称   |
| `{expireDate}`    | 到期日     |
| `{dueDate}`       | 应收到期日 |
| `{receivableNo}`  | 应收单号   |

| 事件                                  | 用哪个模板            | 默认渠道              | 备注                                                  |
| ------------------------------------- | --------------------- | --------------------- | ----------------------------------------------------- |
| 创建预约（含后台代录、周期单生成）    | `booking_created`     | 按模板（短信 + 站内） | 短信是否真发还受「短信总开关 + 模板白名单」限制       |

| 次日到店提醒                          | `booking_remind`      | 按模板                | 每天 **18:00** 由定时任务发出；同一张单当天只提醒一次 |

> 💡 站内消息本身保存在通知记录里，**后台目前没有「未读消息小铃铛」界面**，店员的站内消息也是到「通知记录」里查（接收人显示为「后台用户 #编号」）。

## 使用注意事项

> ⚠️ **短信默认是关着的，不改配置永远发不出短信。**
> 触发条件：装完系统没配短信，顾客当然收不到短信。
> 后果：所有短信记录的「状态」都是**已跳过**，错误信息写着「短信总开关 biz.notice.smsEnabled 未开启」。站内消息不受影响，照常生成。
> 正确做法：先在「参数配置」里把「短信总开关」改成 `true`，再把要发短信的模板编码填进「允许走短信的模板白名单」（逗号分隔，例如 `recharge_success,booking_remind`），最后在服务器环境变量里配好短信通道（`SMS_PROVIDER`、`SMS_ACCESS_KEY_ID`、`SMS_ACCESS_KEY_SECRET`、`SMS_SIGN_NAME`）并重启服务。

> ⚠️ **短信有「三闸门」，任何一关没过都会记成「已跳过」而不是「失败」。**
> 顺序是：① 短信总开关是否打开 → ② 这个模板编码在不在白名单里 → ③ 收件人有没有手机号。
> 触发条件：白名单里漏了某个模板编码（例如只写了 `booking_remind`，却没写 `recharge_success`）。
> 后果：这条通知的短信渠道永远发不出去，且**不会被自动重试**（自动重试只重试「失败」，不重试「已跳过」）。
> 正确做法：每上线一个要发短信的模板，都回「参数配置」里把编码加进白名单，然后手工重发一条验证。

> ⚠️ **「已跳过」不等于「失败」，不要对着跳过记录等系统自动重试。**
> 触发条件：把状态当同义词。
> 后果：自动重试任务每 5 分钟跑一次，但它只挑「失败」的记录，且每条的自动重试上限是 3 次（参数「通知失败重试上限」）。跳过的记录永远不会被自动处理。
> 正确做法：筛出「已跳过」，按错误信息的原因去修配置/补手机号，再人工点「重发」。

> ⚠️ **充值/购卡/销账要用的模板编码是 `recharge_success`，但系统初始化的是 `member_recharged`。**
> 触发条件：顾客充值后想看「充值成功」的短信。
> 后果：系统按 `recharge_success` 找模板，找不到就**降级**成一条站内「原始变量通知」，内容长得像 `【recharge_success】amount=500.00；paymentNo=PAY20260911001`，顾客收不到短信。
> 正确做法：在「通知模板」里新建一条编码为 `recharge_success` 的模板（渠道选「短信 + 站内」），内容用 `{customerName}`、`{amount}` 这类变量（系统在充值成功时只提供 `amount` 和 `paymentNo`，其余变量会渲染成空）。

> ⚠️ **模板里用了系统没提供的变量，会静默变成空白，不报错。**
> 触发条件：例如「预约成功通知」的模板里写了 `{shopName}`（门店名称）和 `{staffName}`（美甲师），但创建预约时系统只提供了顾客姓名、预约日期、预约时间、金额。
> 后果：顾客收到的短信是这样的：「张三您好，您在的预约已确认：2026-09-12 10:00，美甲师。请准时到店……」（门店名和人名位置是空的）。
> 正确做法：编辑模板后，一定到「通知记录」里看新产生的那条记录的**渲染后内容**，确认每个变量都有值；缺的变量要么从模板里去掉，要么先在系统里补上（可以找技术同事或参考本手册「通知」章节的变量对照）。

> ⚠️ **门店名称要单独配。**
> 触发条件：`{shopName}` 渲染为空。
> 后果：所有含门店名的短信都缺门店名。
> 正确做法：到「参数配置」里把「门店名称（通知模板 {shopName} 变量）」这一项的值改成本店名称（默认值是「美甲店」）。注意：次日提醒这条通知会自动带上门店名，其余通知目前不会自动带上，需要模板里去掉该变量。

> ⚠️ **改模板不会改变已经发出去的通知。**
> 触发条件：发现文案写错了，改模板后想「追究」之前的记录。
> 后果：历史记录里存的仍是当时的渲染内容（这正是留存日志的目的）。
> 正确做法：新文案只影响之后发出的通知；对已发错的，靠人工再发一条说明。

> ⚠️ **删模板会把这条通知「连根拔掉」。**
> 触发条件：删掉某个还在被系统使用的模板编码。
> 后果：之后该事件的通知全部降级成站内「原始变量通知」，顾客看不到短信。历史发送日志会保留。
> 正确做法：不需要的通知请改成「禁用」而不是删除；确实要删，先确认没有代码在用这个编码。

> ⚠️ **通知发失败绝不会影响业务。**
> 触发条件：短信网关挂了。
> 后果：预约照样创建、钱照样收，只是通知记录里多一条「失败」。这是刻意设计，不是故障。
> 正确做法：每天早上顺手筛一次「失败」，处理完就点重发。

## 常见问题

**Q：顾客说「没收到短信」，我怎么一步步查？**
A：按这个顺序做，基本能定位：

1. 「通知记录」按**发送日期**和**模板**筛出那一条（筛选框里模板下拉如果不可用，就手输编码）。
2. 看**状态**：
   - 记录里根本没有 → 说明这件事**当前版本不发通知**（例如取消、爽约、次卡到期、应收逾期），或事件还没发生。
   - **已跳过** → 看错误信息，三种原因：短信总开关未开 / 该模板不在白名单 / 顾客没手机号。
   - **失败** → 看错误信息：写「短信通道未配置」就是服务器没配短信账号；写「短信网关 HTTP 5xx」或带供应商错误码，就是运营商侧问题。
   - **待发送** → 记录已落库但还没投递，刷新一下再看；长期停在待发送请联系技术同事。
   - **成功** → 网关已接收，把「供应商消息号」给运营商核实是否被拦截/退订。
3. 看**渲染后内容**，确认文案里没有空掉的变量（顾客可能收到了但你没认出来）。
4. 到「顾客档案」核对手机号是否正确。
5. 修好原因后点「重发」。

**Q：短信和站内消息有什么区别？**
A：短信发给顾客手机（要钱、要报备模板）；站内消息只写进系统，店员在「通知记录」里看。同一条模板可以两者都发。

**Q：顾客手机号为空会怎样？**
A：短信渠道记「已跳过」，原因是「收件人缺少手机号」；站内消息照常生成。

**Q：为什么充值之后顾客没收到短信？**
A：多半是模板编码不匹配（系统找 `recharge_success`，库里只有 `member_recharged`），或者是短信总开关/白名单没配。请对照上面的注意事项处理。

**Q：次卡快到期了会自动提醒顾客吗？**
A：当前版本不会自动发。这条通知目前只能人工提醒，或者由前台在「会员次卡」页面筛出快到期的手工联系。

**Q：自动重试会重试几次？多久一次？**
A：每 5 分钟跑一次，只挑「失败」的记录，单条最多自动重试 3 次（上限由参数「通知失败重试上限」控制，可在「参数配置」里调，范围 0~10；设为 0 表示关闭自动重试）。

**Q：人工重发有次数限制吗？**
A：没有。人工重发不受上限约束，只是会把「重试次数」继续往上加，方便追溯。

**Q：站内消息的「未读」怎么看？**
A：目前后台没有未读小铃铛，看「阅读时间」为空即为未读；系统接口层支持按未读统计，但界面上暂未展示。

**Q：模板里的变量要用花括号吗？**
A：内容里要用花括号，例如 `{customerName}`；「变量清单」里**不要**花括号，写 `customerName` 即可（点「插入变量」会自动处理）。

**Q：改完模板要重启系统吗？**
A：不需要。下一笔通知就会用新文案。
